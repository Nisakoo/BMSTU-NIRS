# Логирование backend

[← Глобальный каталог](./README.md)

Настройку читает `load_config` из process environment, а `bootstrap` применяет
её к logger namespace `smeshariki_ai`. Модуль
[`observability.py`](../backend/src/smeshariki_ai/observability.py) форматирует
события и переносит контекст между асинхронными задачами. Логи идут в stdout
backend-контейнера. Штатный Uvicorn access log отключён: HTTP-события формирует
backend, чтобы не записывать полный URL с query string.

| Переменная | Допустимые значения | По умолчанию |
| --- | --- | --- |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING`, `ERROR` | `INFO` |
| `LOG_FORMAT` | `human`, `json` | `human` |

Неверное значение останавливает запуск при проверке конфигурации. В Compose
значения задаются через локальный `docker/.env`; без него действуют defaults.

## Схема события

Каждая запись содержит `timestamp` в UTC (ISO 8601 с `Z`), `level`, `logger`,
`event` и поля `request_id`, `dialog_id`, `call_id`, `tool_call_id`. В JSON
неприменимые идентификаторы имеют значение `null`; в `human` они могут
опускаться. События начала и завершения операции связаны идентификатором.

Терминальные события HTTP, фонового запуска диалога, LLM и инструментов
содержат `started_at`, `duration_ms` и `outcome`. `timestamp` такой записи
обозначает момент завершения, `duration_ms` измеряется монотонными часами.
Для HTTP дополнительно доступны метод, шаблон маршрута и статус, для LLM —
имя модели, число сообщений и доступных инструментов.

`POST /api/v1/dialogs/{dialog_id}/messages` возвращает `X-Request-ID`.
Его значение сохраняется в логах фоновой задачи после ответа `202`. Отдельное
SSE-подключение имеет собственный `request_id`; связь событий конкретного
диалога выполняется по `dialog_id`. Один LLM-вызов получает `call_id`, а
вызов инструмента — `tool_call_id` из ответа модели. Идентификаторы служат
для поиска событий, а не для аутентификации.

## Метрики модели

`llm.request.completed` содержит длительность вызова, а при текстовом ответе
также `time_to_first_token_ms`. Поля `input_tokens`, `output_tokens` и
`total_tokens` записываются только если потоковый провайдер вернул корректный
usage. При отсутствии или некорректности метаданных указывается
`usage_available=false`; нулевые значения не подставляются. Длительность
включает ожидание потока и внутренние повторы SDK, если они есть. Отдельная
стоимость вызова не вычисляется.

Журнал содержит стабильные имена событий, типы ошибок и безопасные статусы.
Тексты запросов, ответов и исключений, аргументы инструментов и секреты
туда не передаются. Подробнее о требованиях и проверках — в
[SDD-спецификации](../specs/changes/backend-observability-logging/spec.md).
