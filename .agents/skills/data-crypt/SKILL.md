# Шифрование данных RAG

Закрытые данные RAG (сценарии, пакеты знаний) лежат в `data/`, которую Git
игнорирует. В публичный репозиторий попадает только зашифрованный архив
`encrypted/data.enc`. Расшифровать его может только тот, кто знает общую
кодовую фразу команды.

## Команды

Запускаются из корня репозитория:

| Команда | Что делает |
| --- | --- |
| `make data-encrypt` | Дважды спрашивает фразу (не короче 12 символов) и записывает `encrypted/data.enc`. Если данные не изменились, файл не перезаписывается |
| `make data-decrypt` | Спрашивает фразу и восстанавливает `data/`. Отказывается, если `data/` отличается от архива, и перечисляет отличия |
| `make data-decrypt FORCE=1` | Заменяет `data/` содержимым архива, локальные отличия теряются |

Скрипт: [`scripts/data_crypt.py`](scripts/data_crypt.py) (scrypt + AES-256-GCM,
запуск через `uv run --locked --script`). Коды возврата: `0` — успех или «без
изменений», `1` — ошибка, `2` — неверные аргументы (`make` при ошибке
возвращает свой код `2`).

## Кодовая фраза — только у пользователя

- Никогда не проси кодовую фразу в чате, не вводи её, не подставляй в
  команды, файлы, environment или `--passphrase-stdin` и не пытайся
  подобрать.
- Не запускай `make data-encrypt` и `make data-decrypt` сам: команда ждёт
  ввода в терминале. Дай пользователю команду отдельным блоком и попроси
  запустить её в своём терминале; продолжай после его ответа.
- Если пользователь всё же прислал фразу в чат, не используй её и предложи
  сменить фразу: она могла попасть в журналы.

## Когда что делать

- **`data/` нет или она пуста, а `encrypted/data.enc` есть** (свежий клон,
  pull с новым архивом) — попроси пользователя выполнить `make data-decrypt`.
- **Изменились файлы в `data/`** и их нужно сохранить для команды — попроси
  выполнить `make data-encrypt`, затем предложи закоммитить только
  `encrypted/data.enc`.
- **`make data-decrypt` отказался из-за отличий** — покажи пользователю
  список и спроси, что важнее: сохранить локальные правки
  (`make data-encrypt`) или взять версию из репозитория
  (`make data-decrypt FORCE=1`). Не выбирай сам.
- **«Неверная кодовая фраза или файл повреждён»** — попроси проверить фразу;
  если она верна, сравни `encrypted/data.enc` с версией в Git
  (`git diff --stat`, `git log -- encrypted/data.enc`).
- **Предупреждение «прежний архив не открывается этой фразой»** при
  шифровании означает, что архив перезаписан новой фразой. Если смена фразы
  не планировалась, предложи вернуть файл (`git restore encrypted/data.enc`) и
  зашифровать заново правильной фразой.

## Ограничения

- Коммить только `encrypted/data.enc`; `data/` никогда не добавляй в Git
  (`git add -f` запрещён).
- Шифруется весь каталог одним файлом: размер архива и история его изменений
  видны всем. Смена фразы не закрывает доступ к старым версиям в истории Git.
- `.DS_Store` и `.git` внутри `data/` не шифруются и при `FORCE=1`
  сохраняются на верхнем уровне; символьные ссылки не поддерживаются.

Спецификация: `specs/changes/data-encryption/`.
