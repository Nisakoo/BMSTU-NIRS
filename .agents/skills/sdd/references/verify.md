# Verify

1. Сопоставь каждое требование и критерий приёмки из `spec.md` с тестом поведения продукта или результатом ревью. Не создавай автоматические тесты только для проверки структуры каталогов, README и служебных файлов.
2. Если изменение затрагивает Python-код продукта, запусти `make test` на итоговом состоянии репозитория.
3. Выполни предусмотренные спецификацией сборку и runtime-проверки.
4. Убедись, что тесты не отключены, а изменения не вышли за согласованный scope.
5. Запиши результат в `specs/changes/<change-id>/verification.md`: проверенные требования, команды, результаты и известные ограничения.

Задача выполнена только если все критерии подтверждены. Для изменений Python-кода продукта дополнительно требуется успешный `make test`. При ошибке вернись к `implement`, устрани причину и повтори `verify`.
