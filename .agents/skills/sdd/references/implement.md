# Implement

Начинай только после одобрения `spec.md` и `plan.md`.

1. Выполняй задачи плана по одной.
2. Для изменения поведения используй RED -> GREEN -> REFACTOR: сначала падающий тест, затем минимальная реализация, затем упрощение при зелёных тестах.
3. После каждой задачи с изменением Python-кода продукта запускай указанный в плане тест. Для документации и структуры проводи предусмотренное планом ревью без искусственных автоматических тестов.
4. Не добавляй возможности и рефакторинг вне согласованного плана.
5. При ошибке останови реализацию, воспроизведи проблему, исправь первопричину и добавь регрессионный тест.
6. После всех задач, изменяющих Python-код продукта, запусти `make test`.

Если реализация требует изменить согласованные требования, вернись на этап `specify`. Не называй задачу выполненной: после реализации остаётся этап `verify`.
