# Plan

Начинай только после одобрения `spec.md`.

1. Изучи спецификацию и существующие паттерны проекта.
2. Определи зависимости и порядок реализации.
3. Разбей работу на небольшие вертикальные задачи. Каждая задача должна давать проверяемый результат и обычно затрагивать не более пяти файлов.
4. Для каждой задачи укажи связанные требования, критерии приёмки, зависимости, предполагаемые файлы и способ проверки. Для задачи, изменяющей Python-код продукта, укажи точную команду теста. Документацию и структуру проверяй ревью, не создавая для них искусственные автоматические тесты.
5. Сохрани план в `specs/changes/<change-id>/plan.md`.
6. Не пиши производственный код на этом этапе.
7. Покажи план пользователю и дождись явного одобрения.

Выноси рискованные предположения в первые задачи.
