# Проверка: оценка семантического поиска (отрицательный результат)

## Результат

Гипотеза «embeddings и гибридный поиск закроют лексический разрыв и поднимут
`Recall@5`» проверена на golden set и **не подтвердилась**. Лучший вариант
(гибрид с `intfloat/multilingual-e5-small`) даёт `+0.017` документового
`Recall@5` — это один документ из шестидесяти, в пределах шума. По правилу
`docs/rag.md` («ML-модели в процессе backend без подтверждения бенчмарком не
используются») pgvector не внедряется.

Продуктовый код и корпус не изменены: эксперимент выполнялся временным
скриптом в эфемерном окружении `uv run --with transformers`.

## Метод

- корпус: `data/lore-golden/lore` — 84 документа, 188 чанков (после чистки и
  стоп-слов), вопросы не менялись;
- метрики: документовый `Recall@5` и `MRR@5` по 20 обычным вопросам; для
  сравнения приведён и чанковый `Recall@5` (официальная метрика бенчмарка);
- эмбеддинги: mean-pooling + L2-нормировка, косинусное сходство;
- слияние: взвешенная сумма нормализованных баллов (0.3/0.5/0.7) и reciprocal
  rank fusion (k=60);
- модели: `cointegrated/rubert-tiny2` (312d, 29M), `intfloat/multilingual-e5-small`
  (384d, 118M, префиксы `query:`/`passage:`), `ai-forever/sbert_large_nlu_ru`
  (1024d, 427M).

## Метрики

Базовый BM25 после стоп-слов: `0.550 / 0.722` (документовый).

## Разбор по сложным вопросам (`e5-small`, dense)

| вопрос | BM25@5 | dense@5 | первый релевантный в dense |
| --- | --- | --- | --- |
| garden | 0 | 0 | 16 |
| fear | 1 | 0 | 13 |
| technique | 0 | 0 | 9 |
| games | 1 | 2 | 1 |
| weather | 0 | 1 | 1 |

Семантика вытаскивает два вопроса, ломает один и бессильна там, где документ
тематически далёк. Крупная русская модель оказалась хуже компактной
многоязычной.

## Почему эффект мал

- корпус — 84 грязных ASR-транскрипта; тематическая близость в них слабо
  выражена, а «релевантность» размечена по упоминаниям, а не по смысловой
  центральности;
- вопросы короткие и общие, документы длинные и шумные; один вектор на чанк
  теряет детали;
- малые модели на русском не дают прироста на таком домене.

## Вывод

Решение: **pgvector и embeddings не внедрять**. Инфраструктурная цена
(смена образа Postgres, зависимость `transformers`, модель 400 МБ, миграция,
гибридное слияние) не оправдана приростом в пределах шума. Вместо этого
внедрено расширение запроса через LLM (`lore-query-expansion`), которое даёт
`0.583 / 0.738` без новой инфраструктуры.

## Ограничения

- Замер одноразовый на held-out наборе; вопросы не менялись.
- Гипотеза не проверялась на переписанных (более «смысловых») запросах — это
  отдельный эксперимент, если корпус и разметка станут чище.
- Модели скачивались в `~/.cache/huggingface` (≈2.2 ГБ, во временном
  окружении); в репозиторий ничего не попало.
