# Сохранение контекста browser fetch в frontend API-клиенте

## Цель

Устранить отказ создания диалога до отправки HTTP-запроса. `AgentApi`
сохраняет `window.fetch`, но вызывает его как `this.fetchImpl(...)`, передавая
встроенному методу объект `AgentApi` вместо `Window`. В браузерах, требующих
корректный receiver, это может завершиться `Illegal invocation`; текущие
Node-тесты с обычной функцией этот случай не воспроизводят.

## Требования

- REQ-001: `AgentApi` вызывает `fetch` с корректным глобальным контекстом
  для создания диалога и отправки сообщения.
- REQ-002: Инъекция fake `fetch` для тестов сохраняется; URL, методы, JSON
  тело, обработка статусов и SSE-контракт не меняются.
- REQ-003: Регрессионные Node-тесты с receiver-sensitive fake подтверждают
  правильный `this` при обоих HTTP-запросах.
- REQ-004: Backend, Vite proxy, Docker и browser origin не меняются.

## Сценарии

### Создание диалога

- Given браузерный `fetch` требует `Window` как `this`
- When `AgentApi.createDialog()` отправляет POST
- Then вызов доходит до `fetch` с корректным receiver и возвращает `dialog_id`

### Отправка сообщения

- Given диалог создан и browser `fetch` требует корректный receiver
- When `AgentApi.submitMessage()` отправляет запрос
- Then запрос доходит до `fetch` с корректным receiver и принимает `202`

## Технологии и структура

Изменяется только `frontend/src/agent-api.js`, его Node-тесты и необходимая
документация причины. Новых зависимостей нет.

## Команды

- Тесты: `make test`
- Сборка: `npm --prefix frontend run build`
- Proxy smoke: `npm --prefix frontend run test:proxy`

## Тестирование

| Требования | Проверка |
| --- | --- |
| REQ-001–REQ-003 | Node-тесты с fake `fetch`, бросающим ошибку при неверном `this`; существующие тесты API-контракта |
| REQ-004 | Ревью diff и proxy smoke без браузера |

## Границы

- Всегда: сохранять same-origin `/api/v1/...` и явную инъекцию зависимостей.
- Сначала спросить: менять API, proxy, CORS или способ запуска.
- Никогда: запускать браузер для проверки согласно указанию пользователя.

## Критерии приёмки

- [ ] Receiver-sensitive тесты создания и отправки проходят.
- [ ] Существующие frontend/backend тесты, Vite build и proxy smoke проходят.
- [ ] Backend и Vite конфигурация не изменены.
