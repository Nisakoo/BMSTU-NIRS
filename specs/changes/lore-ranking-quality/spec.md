# Качество ранжирования: документные метрики, заголовки, настройки контекста

## Цель

Закрыть три дефекта, найденных замерами: метрики считаются по чанкам и
расходятся с продакшн-логикой «один пассаж на документ»; заголовки эпизодов не
индексируются, поэтому поиск по названию не работает; параметры контекста
(`min_score`, `retrieval_k`, `max_chars`, `max_passages`) зашиты в коде и не
настраиваются без правки.

## Требования

- REQ-001: `BenchmarkReport` получает документные метрики
  `document_recall_at_k` и `document_mrr`: хиты дедуплицируются по документу
  **до** среза `k`, поэтому «пять документов» — это пять разных эпизодов.
  Чанковые `recall_at_k`/`mrr` остаются для совместимости.
- REQ-002: CLI печатает `Doc Recall@k` и `Doc MRR@k`; JSON содержит новые поля.
- REQ-003: `LoadLore` добавляет термы заголовка в первый чанк документа, чтобы
  запрос по названию эпизода находил документ. Текст чанка не меняется;
  `term_count` учитывает добавленные термы.
- REQ-004: `RagConfig` получает `lore_retrieval_k` (10), `lore_max_passages`
  (3), `lore_max_chars` (1600), `lore_min_score` (2.0) с переменными
  `RAG_LORE_*`; bootstrap строит `LoreContextBuilder` из конфигурации.
- REQ-005: значения по умолчанию воспроизводят текущее поведение, поэтому
  прежние метрики не обязаны меняться — изменение измеряется и фиксируется.
- REQ-006: документация (`docs/lore.md`, `docs/rag.md`, `AGENTS.md`,
  `docker/.env.example`) отражает новые метрики и настройки.
- REQ-007: длинный пассаж обрезается по границе предложения (или слова), а не
  посередине; освободившийся бюджет достаётся следующему пассажу; обрывок
  короче 80 символов не показывается. Метрика `Context Recall` не ухудшается.

## Сценарии

- Given golden set, When выполняется бенчмарк, Then отчёт содержит и чанковые,
  и документные метрики.
- Given запрос «Телеграф», When документ с таким заголовком есть в корпусе,
  Then он попадает в выдачу даже если слово не встречается в тексте.
- Given `RAG_LORE_MAX_CHARS=800`, When приложение собрано, Then контекст
  ограничен 800 символами.

## Тестирование

- `test_benchmark.py`: документные метрики при дублях чанков одного документа;
  документная метрика не может быть меньше чанковой на тех же данных.
- `test_services.py`: заголовок попадает в термы первого чанка, остальные чанки
  не меняются.
- `test_lore_cli.py`: новые строки вывода и JSON-поля.
- `test_backend_config.py`: значения по умолчанию и разбор `RAG_LORE_*`.

## Границы

- Всегда: вопросы golden set не меняются; дефолты сохраняют поведение.
- Сначала спросить: изменение дефолтов, веса заголовка больше одного
  вхождения, embeddings/rerank.
- Никогда: не подгонять формулировки вопросов под выдачу.

## Критерии приёмки

- [ ] `make test` и `make lint` проходят.
- [ ] Бенчмарк печатает документные метрики; значения зафиксированы в
      `verification.md` до/после индексации заголовков.
- [ ] Настройки `RAG_LORE_*` проверены тестом.
- [ ] Обрезка по границе предложения проверена тестом; `Context Recall` не
      ниже прежнего значения.
