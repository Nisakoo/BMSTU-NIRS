# Копирование сообщений в чате

## Цель

Пользователь хочет повторить или поправить свой запрос и сохранить
понравившуюся историю. Под каждым сообщением в чате появляется кнопка
«Копировать», которая кладёт текст сообщения в буфер обмена. Изменение
затрагивает только frontend.

## Требования

- REQ-001: У каждого сообщения пользователя и у каждого завершённого ответа
  ассистента (из сохранённой истории или после `message_end`) есть кнопка
  «Копировать» с `aria-label="Скопировать сообщение"`. Пока ответ генерируется
  и у ответа с `message_error` кнопки нет.
- REQ-002: Нажатие копирует в буфер обмена ровно текст сообщения (без подписей,
  мордашек и служебных элементов) через `navigator.clipboard.writeText`.
- REQ-003: Если `navigator.clipboard` недоступен (не secure context, например
  HTTP по IP) или вызов отклонён, используется запасной путь: временный
  скрытый `textarea` и `document.execCommand("copy")`; после копирования
  `textarea` удаляется.
- REQ-004: При успехе кнопка на 1,5 секунды показывает «Скопировано» и
  возвращается в исходное состояние. Если оба способа не сработали, строка
  состояния показывает «Не удалось скопировать».
- REQ-005: Копирование работает независимо от состояния формы: и во время
  генерации ответа, и при заблокированной форме, и в открытой сохранённой
  истории. Оно не отправляет сетевых запросов.
- REQ-006: Текст сообщения по-прежнему выводится только через `textContent`.

## Сценарии

### Копирование своего запроса

- Given в чате есть сообщение пользователя «Расскажи про Нюшу»
- When пользователь нажимает «Копировать» под ним
- Then в буфере обмена «Расскажи про Нюшу», кнопка показывает «Скопировано»

### Копирование истории

- Given ответ ассистента завершён `message_end`
- When пользователь нажимает «Копировать» под ответом
- Then в буфер попадает полный текст ответа

### Нет Clipboard API

- Given страница открыта по HTTP не на `localhost`, `navigator.clipboard` нет
- When пользователь нажимает «Копировать»
- Then текст копируется через `execCommand("copy")`

### Ошибка

- Given оба способа копирования не сработали
- When пользователь нажимает «Копировать»
- Then строка состояния показывает «Не удалось скопировать», чат работает

## Технологии и структура

- Vanilla JavaScript: `frontend/src/script.js` (кнопка в `addMessage` и после
  `message_end`, функция копирования с запасным путём), `frontend/src/styles.css`.
- Документация: `frontend/README.md`, раздел «Реализованный frontend» в
  `AGENTS.md`, `docs/README.md` при необходимости.

## Команды

- Запуск: `make run` или `make frontend`
- Тесты: `make test`

## Тестирование

- Node-тесты UI в `frontend/tests/ui.test.js`: кнопка есть у сообщений
  пользователя и завершённых ответов и отсутствует у генерируемого и
  ошибочного ответа; в `clipboard.writeText` уходит точный текст; запасной
  путь при отсутствии и отказе Clipboard API; «Скопировано» и возврат подписи;
  «Не удалось скопировать» при двойном отказе; нет сетевых запросов.
- Ручная проверка в `make run`: копирование на `localhost` и по IP.

## Границы

- Всегда: копировать только текст сообщения; не использовать `innerHTML`.
- Сначала спросить: копирование всей истории целиком, редактирование и
  повторную отправку запроса одной кнопкой.
- Никогда: не менять backend и HTTP-контракт; не сохранять текст в
  `localStorage`.

## Критерии приёмки

- [ ] Под сообщениями пользователя и завершёнными ответами есть кнопка
  «Копировать», копирующая точный текст.
- [ ] Без Clipboard API копирование работает через запасной путь.
- [ ] Ошибка копирования показывается в строке состояния.
- [ ] `make test` проходит успешно; Python-код не меняется.
