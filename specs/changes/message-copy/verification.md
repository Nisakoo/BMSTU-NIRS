## Порядок TDD и отклонения

- Сначала добавлены 7 UI-тестов и поддержка в fake DOM (`navigator.clipboard`
  в вариантах `ok`/`denied`/`none`, `document.body`, `execCommand`,
  `select`). Все 7 падали, остальные 143 проходили.
- Помощник `bubbles()` в тестах искал пузырь как последний элемент строки;
  кнопка копирования после ответа это нарушила бы, поэтому он теперь ищет
  элемент с классом `sai-bubble`.
- Первая версия кнопки была текстовой («Копировать»). При ручной проверке на
  ширине 390px она сжимала ответ ассистента в узкую колонку. Кнопка стала
  иконкой 32px: текст остаётся в кнопке для скринридера, после копирования
  иконка меняется на галочку, а на компьютере рядом видна подпись
  «Скопировано». Тесты поведения не менялись.

## Ручная проверка

Проверка через CDP в headless Chrome настоящими событиями мыши на
`127.0.0.1:8081`, пользователь `sdd_copy` (создан для проверки), одно
сообщение к настоящей модели.

- Кнопка у сообщения пользователя появилась сразу после `202`; у
  генерируемого ответа кнопки нет; после `message_end` кнопок две.
- Клик по кнопке пользователя: буфер обмена (`navigator.clipboard.readText`)
  равен тексту запроса, подпись «Скопировано», через 1,5 с — снова
  «Копировать».
- Клик по кнопке ответа: буфер равен полному тексту ответа (177 символов).
- `navigator.clipboard` отключён на странице (как при HTTP по IP): копирование
  прошло через `textarea`, буфер равен тексту запроса, `textarea` в `body` не
  осталось.
- Компьютер 1280px: кнопки 38px, `opacity` 0,45, при наведении на строку — 1;
  после копирования кнопка 120px с подписью. Сохранённая история открыта из
  списка — кнопки у обоих сообщений.
- Телефон 390px: `opacity` 0,8, после копирования только галочка (ширина не
  меняется), `scrollWidth` 390.

Проверить именно HTTP по IP машины не удалось: Caddy слушает только
`127.0.0.1`. Запасной путь проверен отключением Clipboard API на странице.

Скриншоты лежат в `~/Desktop/макеты-смешарики/копирование/`.
