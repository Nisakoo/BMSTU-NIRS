# Единый контейнерный запуск с Caddy и Nginx

## Цель

Запускать готовое приложение одной командой из корня репозитория. Caddy становится единой внешней точкой входа, frontend собирается из актуальных исходников и отдаётся отдельным Nginx-контейнером, а backend остаётся
внутренним сервисом того же Docker Compose проекта.

## Требования

- REQ-001: `make run` собирает и запускает backend, frontend на Nginx и Caddy через один `docker/compose.yaml`; отдельный запуск Vite для основного сценария не требуется.
- REQ-002: Для контейнерного запуска frontend собирается командой Vite build из
  `frontend/src/` с зафиксированными npm-зависимостями. Nginx раздаёт
  полученные статические файлы; он и Caddy работают в разных контейнерах.
- REQ-003: Публичный адрес по умолчанию — `http://localhost:8080/`. Только Caddy публикует порт на хосте; путь `/` и статические файлы передаются frontend-контейнеру, `/api` и `/api/*` — backend без удаления префикса.
  Внешний порт можно переопределить через `docker/.env`.
- REQ-004: Через публичный адрес сохраняются действующие HTTP- и SSE-контракты: создание диалога возвращает `201`, отправка сообщения — `202`, подключение к
  потоку получает `ready`, а дальнейшие события доходят без накопления до закрытия соединения. Браузерный код продолжает использовать относительные
  `/api/v1/...`; CORS для этого сценария не нужен.
- REQ-005: При временной недоступности backend на старте stack становится доступен после его готовности без ручного перезапуска сервисов. Отказ backend не маскируется статическим frontend-ответом на `/api/*`.
- REQ-006: Настройки LLM и локальные секреты по-прежнему поступают в backend через Compose environment из `docker/.env`; файл не коммитится. Все новые файлы контейнерного запуска располагаются в `docker/`.
- REQ-007: Документация и правила проекта отражают новый основной запуск, адрес, маршрутизацию и границы сервисов. `make frontend` с Vite остаётся
  необязательным режимом разработки; Python API и бизнес-логика не меняются.

## Границы

- Всегда: сохранять существующие пути `/api/v1`, поток SSE и отсутствие секретов в репозитории; не вмешиваться в чужие незакоммиченные изменения.
- Сначала спросить: нужен ли внешний домен, автоматический HTTPS или другой публичный порт вместо выбранного локального значения по умолчанию.
- Никогда: не запускать браузер, не добавлять CORS, отдельный LiteLLM Proxy, RAG-сервис или постоянное хранилище истории в рамках этого изменения.
