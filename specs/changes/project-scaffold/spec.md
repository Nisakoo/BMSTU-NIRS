# Базовая структура проекта «Смешарики AI»

## Цель

Создать минимальный физический каркас проекта `smeshariki-ai` на тему
«Смешарики» для последующей независимой разработки frontend и модульного
backend. Изменение должно только обозначить границы будущих частей проекта и не
добавлять запускаемое приложение, зависимости или преждевременные технические
решения.

## Допущения

- Публичное имя проекта и будущего Python-дистрибутива — `smeshariki-ai`.
- Импортируемый Python-пакет backend называется `smeshariki_ai`, поскольку
  дефис нельзя использовать в обычном имени импортируемого Python-модуля.
- Пустые каталоги, которые Git сам по себе не отслеживает, сохраняются с помощью
  файла `.gitkeep`.
- Файлы `__init__.py` остаются пустыми и только обозначают границы Python-пакетов.
- Существующее содержимое `docker/` не изменяется.
- Из `Makefile` удаляются проверки структуры репозитория: `make test`
  предназначен только для тестов Python-кода продукта.

## Требования

- REQ-001: В корне репозитория должен появиться `README.md` с названием
  `smeshariki-ai`, кратким описанием проекта на тему «Смешарики», описанием его
  верхнеуровневых каталогов и ссылкой на команды из `Makefile`.
- REQ-002: Каталог `backend/` должен содержать `README.md`, исходный пакет
  `src/smeshariki_ai/` и каталоги модульных и интеграционных тестов.
- REQ-003: Внутри `backend/src/smeshariki_ai/` должны быть обозначены модули
  `api`, `agent` и `rag`; агент и RAG не должны становиться отдельными
  верхнеуровневыми приложениями или сервисами.
- REQ-004: Каталог `frontend/` должен содержать `README.md`, пустой каталог
  исходников `src/` и пустой каталог тестов `tests/`.
- REQ-005: Создаваемый каркас должен иметь следующее точное дерево:

  ```text
  .
  ├── README.md
  ├── backend/
  │   ├── README.md
  │   ├── src/
  │   │   └── smeshariki_ai/
  │   │       ├── __init__.py
  │   │       ├── api/
  │   │       │   └── __init__.py
  │   │       ├── agent/
  │   │       │   └── __init__.py
  │   │       └── rag/
  │   │           └── __init__.py
  │   └── tests/
  │       ├── integration/
  │       │   └── .gitkeep
  │       └── unit/
  │           └── .gitkeep
  └── frontend/
      ├── README.md
      ├── src/
      │   └── .gitkeep
      └── tests/
          └── .gitkeep
  ```

- REQ-006: `backend/README.md` должен кратко фиксировать, что API, runtime
  агента, серверная бизнес-логика и RAG развиваются в одном backend-приложении.
- REQ-007: `frontend/README.md` должен фиксировать, что frontend запускается
  отдельно от Docker-окружения backend, а его стек будет выбран отдельной
  спецификацией.
- REQ-008: В рамках изменения запрещено добавлять исполняемый код, маршруты API,
  конфигурацию зависимостей, lock-файлы, Dockerfile, Compose-файлы или конфигурацию
  конкретного frontend-фреймворка.
- REQ-009: `make test` не должен проверять структуру каталогов или наличие
  служебных файлов. Пока Python-тесты продукта не настроены, команда должна
  завершаться с ошибкой и явно сообщать причину.

## Сценарии

### Просмотр структуры нового клона

- Given репозиторий получен из системы контроля версий
- When разработчик просматривает его верхнеуровневую структуру
- Then видны отдельные каталоги `frontend/`, `backend/`, `docker/` и `specs/`
- And внутри backend агент и RAG расположены как внутренние модули

### Попытка запустить ещё не реализованное приложение

- Given создан только базовый каркас
- When разработчик изучает созданные файлы
- Then в них отсутствуют исполняемое приложение и фиктивная конфигурация запуска
- And README явно указывают, что реализация и выбор недостающих технологий
  выполняются отдельными SDD-изменениями

### Сохранение пустых каталогов

- Given каталоги исходников или тестов пока не содержат реализации
- When каркас добавлен в Git и получен в новом клоне
- Then каталоги присутствуют благодаря `__init__.py` или `.gitkeep`

## Технологии и структура

Backend следует `src`-layout и резервирует единый импортируемый Python-пакет
`smeshariki_ai`. Имя `smeshariki-ai` используется для проекта и будущего
дистрибутива. Подкаталоги `api`, `agent` и `rag` обозначают архитектурные границы
без реализации. Frontend получает только нейтральные каталоги `src` и `tests`,
чтобы не выбирать фреймворк или пакетный менеджер на этом этапе.

Каталог `docker/` уже существует и в рамках изменения не дополняется: файлы
контейнерного запуска появятся вместе со спецификацией запускаемого backend и
его инфраструктуры.

## Команды

- Запуск: `make run` — поведение не изменяется; запускаемый проект этим
  изменением не создаётся.
- Тесты: `make test` — тесты Python-кода продукта ещё не настроены, поэтому
  команда должна явно завершаться с ошибкой.

## Тестирование

Изменение не добавляет поведение продукта, поэтому автоматические тесты для него
не создаются. Состав файлов и содержание README проверяются при ревью изменения,
а не тестами. `make test` не используется для проверки структуры репозитория и
не должен успешно завершаться до появления настоящих Python-тестов продукта.

## Границы

- Всегда: сохранять агента и RAG внутри backend; хранить контейнерные файлы
  только в `docker/`; оставлять секреты вне Git.
- Сначала спросить: изменить имена `smeshariki-ai` или `smeshariki_ai`; добавить
  новый верхнеуровневый каталог; выбрать frontend-стек; добавить запускаемый код
  или конфигурацию.
- Никогда: добавлять frontend в Docker Compose; выделять агента или RAG в
  отдельный верхнеуровневый сервис; коммитить секреты.

## Критерии приёмки

- [ ] Все пути из REQ-005 существуют и отслеживаются Git.
- [ ] README описывают назначение каталогов и не обещают ещё не реализованную
  функциональность.
- [ ] В изменении нет запускаемого кода и конфигурации конкретного стека.
- [ ] Существующие файлы в `docker/` не изменены.
- [ ] `make test` не содержит проверок каталогов, README или служебных файлов и
  явно сообщает, что Python-тесты продукта ещё не настроены.

## Открытые вопросы

- Нет. Каталоги `frontend/src` и `frontend/tests` входят в согласованный
  базовый каркас.
