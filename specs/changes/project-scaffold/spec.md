# Базовая структура проекта «Смешарики AI»

## Цель

Создать минимальный физический каркас проекта `smeshariki-ai` на тему «Смешарики» для последующей независимой разработки frontend и модульного
backend. Изменение должно только обозначить границы будущих частей проекта и не добавлять запускаемое приложение, зависимости или преждевременные технические решения.

## Допущения

- Публичное имя проекта и будущего Python-дистрибутива — `smeshariki-ai`.
- Импортируемый Python-пакет backend называется `smeshariki_ai`, поскольку дефис нельзя использовать в обычном имени импортируемого Python-модуля.
- Пустые каталоги, которые Git сам по себе не отслеживает, сохраняются с помощью файла `.gitkeep`.
- Файлы `__init__.py` остаются пустыми и только обозначают границы Python-пакетов.
- Существующее содержимое `docker/` не изменяется.
- Из `Makefile` удаляются проверки структуры репозитория: `make test` предназначен только для тестов Python-кода продукта.

## Требования

- REQ-001: В корне репозитория должен появиться `README.md` с названием
  `smeshariki-ai`, кратким описанием проекта на тему «Смешарики», описанием его
  верхнеуровневых каталогов и ссылкой на команды из `Makefile`.
- REQ-002: Каталог `backend/` должен содержать `README.md`, исходный пакет
  `src/smeshariki_ai/` и каталоги модульных и интеграционных тестов.
- REQ-003: Внутри `backend/src/smeshariki_ai/` должны быть обозначены модули
  `api`, `agent` и `rag`; агент и RAG не должны становиться отдельными
  верхнеуровневыми приложениями или сервисами.
- REQ-004: Каталог `frontend/` должен содержать `README.md`, пустой каталог исходников `src/` и пустой каталог тестов `tests/`.
- REQ-005: Создаваемый каркас должен иметь следующее точное дерево:

  ```text
  . ├── README.md ├── backend/ │   ├── README.md │   ├── src/ │   │   └── smeshariki_ai/ │   │       ├── __init__.py │   │       ├── api/ │   │       │   └── __init__.py │   │       ├── agent/
  │   │       │   └── __init__.py │   │       └── rag/ │   │           └── __init__.py │   └── tests/ │       ├── integration/ │       │   └── .gitkeep │       └── unit/ │           └── .gitkeep └── frontend/
      ├── README.md ├── src/ │   └── .gitkeep └── tests/ └── .gitkeep
  ```

- REQ-006: `backend/README.md` должен кратко фиксировать, что API, runtime агента, серверная бизнес-логика и RAG развиваются в одном backend-приложении.
- REQ-007: `frontend/README.md` должен фиксировать, что frontend запускается отдельно от Docker-окружения backend, а его стек будет выбран отдельной спецификацией.
- REQ-008: В рамках изменения запрещено добавлять исполняемый код, маршруты API, конфигурацию зависимостей, lock-файлы, Dockerfile, Compose-файлы или конфигурацию конкретного frontend-фреймворка.
- REQ-009: `make test` не должен проверять структуру каталогов или наличие служебных файлов. Пока Python-тесты продукта не настроены, команда должна завершаться с ошибкой и явно сообщать причину.

## Границы

- Всегда: сохранять агента и RAG внутри backend; хранить контейнерные файлы только в `docker/`; оставлять секреты вне Git.
- Сначала спросить: изменить имена `smeshariki-ai` или `smeshariki_ai`; добавить новый верхнеуровневый каталог; выбрать frontend-стек; добавить запускаемый код или конфигурацию.
- Никогда: добавлять frontend в Docker Compose; выделять агента или RAG в отдельный верхнеуровневый сервис; коммитить секреты.
