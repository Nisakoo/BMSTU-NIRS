# План: базовая структура проекта «Смешарики AI»

## Основание

План реализует согласованную спецификацию
`specs/changes/project-scaffold/spec.md`. В проекте создаётся только физический
каркас: README, пустые Python-пакеты и маркеры пустых каталогов. Исполняемый код
и конфигурация технологических стеков не входят в работу.

## Зависимости и порядок

1. Сначала из `make test` удаляются проверки структуры репозитория, а правило о
   продуктовых тестах фиксируется в `AGENTS.md`.
2. Затем документируются название проекта и границы каталогов. Это закрепляет
   различие между именем проекта `smeshariki-ai` и импортируемым пакетом
   `smeshariki_ai` до создания структуры backend.
3. Затем создаются границы Python-пакета backend.
4. После этого создаются нейтральные каталоги тестов и frontend с маркерами для
   Git.
5. В конце изменение проверяется ревью без искусственных тестов структуры.

Внешние зависимости отсутствуют. Установка Python- или frontend-пакетов не
требуется.

## Задача 1. Убрать структурные проверки из `make test`

**Связанные требования:** REQ-009.

**Критерии приёмки:** `make test` не проверяет каталоги, README или служебные
файлы и не завершается успешно, пока Python-тесты продукта не настроены.

**Зависимости:** нет.

**Файлы:**

- `Makefile`;
- `AGENTS.md`.

**Действия:**

1. Удалить из цели `test` проверки существования `AGENTS.md`, `docker/` и
   `docker/.env.example`.
2. До появления тестового Python-проекта оставить явное сообщение об отсутствии
   продуктовых тестов и ненулевой код завершения.
3. Зафиксировать в `AGENTS.md`, что автоматические тесты проверяют поведение
   Python-кода продукта, а не устройство репозитория.

**Проверка ревью:**

```sh
sed -n '20,36p' AGENTS.md
sed -n '1,80p' Makefile
```

Автоматические тесты для этой задачи не добавляются.

## Задача 2. Создать документацию каркаса

**Связанные требования:** REQ-001, REQ-002, REQ-006, REQ-007.

**Критерии приёмки:** README существуют, описывают назначение частей проекта и
не обещают запускаемую реализацию.

**Зависимости:** задача 1.

**Файлы:**

- `README.md`;
- `backend/README.md`;
- `frontend/README.md`.

**Действия:**

1. В корневом README указать название `smeshariki-ai`, тему «Смешарики», роли
   `frontend/`, `backend/`, `docker/` и `specs/`, а также команды `make run` и
   `make test` без заявления о готовности приложения.
2. В README backend зафиксировать модульный монолит и внутреннее расположение
   API, агента, бизнес-логики и RAG.
3. В README frontend зафиксировать отдельный от Docker запуск и отложенный выбор
   стека через будущую SDD-спецификацию.

**Проверка ревью:**

```sh
sed -n '1,200p' README.md
sed -n '1,200p' backend/README.md
sed -n '1,200p' frontend/README.md
```

Автоматические тесты для этой задачи не добавляются.

## Задача 3. Создать границы пакета backend

**Связанные требования:** REQ-002, REQ-003, REQ-005, REQ-008.

**Критерии приёмки:** пакет расположен в `backend/src/smeshariki_ai`, содержит
только пустые `__init__.py`, а `api`, `agent` и `rag` остаются внутренними
модулями backend.

**Зависимости:** задача 2.

**Файлы:**

- `backend/src/smeshariki_ai/__init__.py`;
- `backend/src/smeshariki_ai/api/__init__.py`;
- `backend/src/smeshariki_ai/agent/__init__.py`;
- `backend/src/smeshariki_ai/rag/__init__.py`.

**Действия:**

1. Создать дерево импортируемого пакета `smeshariki_ai`.
2. Добавить пустые `__init__.py` в корень пакета и три внутренних модуля.
3. Не добавлять точки входа, маршруты, классы, функции или конфигурацию
   зависимостей.

**Проверка ревью:**

```sh
git status --short
```

Автоматические тесты для этой задачи не добавляются.

## Задача 4. Создать пустые каталоги frontend и тестов

**Связанные требования:** REQ-002, REQ-004, REQ-005, REQ-008.

**Критерии приёмки:** все нейтральные каталоги из согласованного дерева
отслеживаются Git, при этом не выбран frontend-фреймворк и не создан тестовый
стек.

**Зависимости:** задача 2.

**Файлы:**

- `backend/tests/integration/.gitkeep`;
- `backend/tests/unit/.gitkeep`;
- `frontend/src/.gitkeep`;
- `frontend/tests/.gitkeep`.

**Действия:**

1. Создать каталоги модульных и интеграционных тестов backend.
2. Создать каталоги исходников и тестов frontend.
3. Добавить в каждый пустой каталог только пустой `.gitkeep`.

**Проверка ревью:**

```sh
git status --short
```

Автоматические тесты для этой задачи не добавляются.

## Итоговая проверка реализации

**Связанные требования:** REQ-001–REQ-009 и все критерии приёмки.

1. Сопоставить итоговые пути с деревом из REQ-005.
2. Убедиться, что не добавлены `pyproject.toml`, lock-файлы, `package.json`,
   Dockerfile, Compose-файлы или исполняемые модули.
3. Убедиться, что `Makefile` изменён только в части REQ-009, а существующие
   файлы `docker/` не изменены.
4. Не добавлять и не запускать автоматические тесты структуры репозитория.

**Команды:**

```sh
git status --short
```

После ревью реализации перейти к отдельному этапу `verify` и записать
результаты в `verification.md`. `make test` начнёт использоваться после появления
Python-кода продукта и настоящих тестов его поведения.
