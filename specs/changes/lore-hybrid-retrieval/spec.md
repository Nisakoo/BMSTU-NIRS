# Гибридный поиск: заголовки, бюджет контекста и pgvector

## Цель

Поднять метрики поиска, как разрешил преподаватель: докручивать BM25 можно любым способом, а бенчмарк мерит весь движок, а не только чистый BM25. План построен на замерах: гибрид BM25 + плотный поиск даёт на независимом
контрольном наборе `doc Recall@5 0.833 → 0.900`, заголовки закрывают два документа, которые находятся только по названию эпизода, а бюджет контекста даёт `+0.1` контекстного recall.

## Этапы

### Этап 1. Бюджет контекста (дёшево)

- REQ-101: `RagConfig.lore_max_chars` по умолчанию `3200` вместо `1600`; bootstrap передаёт значение в `LoreContextBuilder`; прежние тесты, задающие бюджет явно, не меняются.
- REQ-102: измерено на dev и один раз на контрольном наборе.

### Этап 2. Заголовки эпизодов (BM25-поле)

- REQ-201: термы заголовка добавляются в индекс документа с весом (`×2` повторения), но **не увеличивают длину чанка**: `LoreChunk` получает необязательное поле `length`, а `term_count` берёт его, если оно задано.
  Так заголовок даёт буст без штрафа по длине, который испортил прошлый замер.
- REQ-202: в PostgreSQL длина чанка уже хранится (`rag_lore_chunks.term_count`), схема не меняется; миграции не нужны.
- REQ-203: замер на dev; если не хуже, проверка на контрольном наборе.

### Этап 3. Гибрид с pgvector

- REQ-301: порт `EmbeddingProvider` (`embed(texts)`, `dimension`, `model_id`) и реализации `LocalEmbeddingProvider` (transformers + e5-small, mean pooling),
  `FakeEmbeddingProvider` (детерминированный, для тестов).
- REQ-302: миграция `0017`: `CREATE EXTENSION vector`, таблица
  `rag_lore_embeddings(chunk_id, model, embedding vector(384))`, HNSW-индекс;
  таблица описана в `rag/lore/tables.py`, контрактный тест схемы обновлён.
- REQ-303: `lore-load` считает эмбеддинги чанков и пишет их; без модели — безопасная ошибка загрузки (`unavailable`), поиск продолжает работать на BM25.
- REQ-304: `SearchLore` поддерживает гибридное слияние: `BM25 top-20` +
  `dense top-50`, нормализация баллов по документам, вес
  `RAG_HYBRID_BM25_WEIGHT` (по умолчанию `0.7`); при выключенном гибриде
  поведение прежнее.
- REQ-305: образ PostgreSQL в `docker/compose.yaml` и тестовом compose —
  `pgvector/pgvector:pg17`.
- REQ-306: бенчмарк `lore-benchmark --hybrid` измеряет весь движок; отчёт показывает те же метрики.
- REQ-307: конфигурация `RAG_HYBRID_ENABLED` (по умолчанию `false`) и
  `RAG_HYBRID_BM25_WEIGHT`; модели скачиваются скриптом, как Silero.

## Границы

- Всегда: проверка каждого этапа на dev и один контрольный прогон; при отсутствии прироста этап откатывается.
- Сначала спросить: изменение образа Postgres, зависимость `transformers`, скачивание модели.
- Никогда: не подгонять контрольный набор, не менять вопросы после прогона.
