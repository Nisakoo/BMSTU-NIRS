# Расширение запроса через LLM перед BM25

## Цель

Поднять качество лексического поиска на тематических вопросах, где BM25
промахивается из-за разрыва словаря. Замер на golden set: BM25 даёт `Recall@5
0.550`, лучший гибрид с embeddings — `0.567`, а расширение вопроса через уже
настроенную LLM — **`0.583`** при `MRR@5 0.738` против `0.722`. Расширение
добавляет слова, которых нет в вопросе («физкультура» → «футбол гольф мяч»), и
не требует pgvector, новых зависимостей и моделей на диске.

Пользователь результата — агент и его бенчмарк; контракт инструмента
`search_lore` не меняется.

## Требования

- REQ-001: порт `QueryExpander` в `rag/lore/expansion.py` с асинхронным
  `expand(query) -> tuple[str, ...]`. Пустой кортеж означает «расширения нет».
- REQ-002: реализация `LiteLLMQueryExpander` использует существующую
  абстракцию `LLMProvider` (SDK LiteLLM в RAG не проникает). Промпт просит 5–10
  ключевых слов без пояснений; разбор защитный: токены по регулярному
  выражению, `casefold`, дедупликация, не более `max_terms` (по умолчанию 10),
  пустой и мусорный ответ даёт пустой кортеж.
- REQ-003: сбой расширения не ломает поиск. При `LLMProviderError` или пустом
  ответе инструмент ищет по исходному запросу, пишет событие
  `lore.query_expansion.completed` с `outcome`, `term_count`, `duration_ms` и
  `error_type` (без текста запроса и расширения) и не поднимает исключение.
- REQ-004: `SearchLoreTool` принимает необязательный `expander`. При наличии
  расширения поиск идёт по строке «исходный запрос + расширенные термины»,
  поэтому исходный сигнал не теряется. Правило «запрос из одних имён даёт
  пустой контекст» проверяется только по исходному запросу: расширение не
  должно делать такой вопрос содержательным.
- REQ-005: аргументы, результат и безопасные сообщения инструмента не
  меняются; без `expander` поведение прежнее.
- REQ-006: `BenchmarkRunner` принимает необязательный `expander`; CLI
  `lore-benchmark --expand` включает его. Без `--expand` метрики не меняются.
- REQ-007: конфигурация: `RagConfig.query_expansion_enabled`
  (`RAG_QUERY_EXPANSION_ENABLED`, по умолчанию `false`), читается только
  `load_config`; bootstrap создаёт `LiteLLMQueryExpander` только при включённом
  флаге. Шаблон `docker/.env.example` документирует флаг.
- REQ-008: документация: `docs/lore.md` (предобработка/поиск, метрики),
  `docs/rag.md`, `AGENTS.md`.

## Сценарии

### Основной сценарий

- Given включённое расширение; When агент вызывает `search_lore` с тематическим
  вопросом; Then поиск идёт по вопросу плюс ключевые слова, а модель получает
  пассажи как раньше.

### Ошибка или граничный случай

- Given LLM недоступна; When инструмент вызывается; Then поиск выполняется по
  исходному запросу, событие помечено `failed`, ошибка не выходит наружу.
- Given запрос «Крош и Ёжик»; When расширение добавило содержательные слова;
  Then контекст всё равно `empty`, потому что правило смотрит только на
  исходный запрос.
- Given расширение выключено; When выполняется бенчмарк; Then метрики совпадают
  с прежними контрольными значениями.

## Технологии и структура

`rag/lore/expansion.py` (порт, реализация, разбор), `rag/lore/tools.py`,
`rag/lore/benchmark.py`, `rag/cli.py`, `rag/config.py`, `config.py`,
`bootstrap.py`, `docker/.env.example`. Тесты: `test_expansion.py`,
`test_tool.py`, `test_benchmark.py`, `test_config.py`.

## Команды

- Бенчмарк с расширением:
  `python -m smeshariki_ai.rag lore-benchmark data/lore-golden/lore --questions data/lore-golden/questions.yaml --answers data/lore-golden/answers.json --context --expand`
- Тесты: `make test`; линт: `make lint`.

## Тестирование

- `test_expansion.py`: разбор ответа (пунктуация, дедупликация, лимит,
  пустой ответ), сбой провайдера → `()`, событие с `error_type`.
- `test_tool.py`: расширение добавляется к запросу; сбой расширителя не ломает
  инструмент; правило имён сохраняется только по исходному запросу; без
  расширителя поведение прежнее.
- `test_benchmark.py`: с фейковым расширителем метрики считаются; без него
  значения прежние.
- `test_config.py`: `RAG_QUERY_EXPANSION_ENABLED` разбирается, по умолчанию
  выключено.

## Границы

- Всегда: исходный запрос сохраняется в поиске; сбой расширения деградирует
  тихо; никакого текста в журнале.
- Сначала спросить: изменение промпта расширения после замеров, включение по
  умолчанию в коде, embeddings/pgvector.
- Никогда: не менять вопросы golden set, не подгонять расширения под отдельные
  вопросы, не передавать секреты и тексты в журнал.

## Критерии приёмки

- [ ] `make test` проходит успешно; `make lint` без замечаний.
- [ ] Замер с `--expand` фиксирует `Recall@5` и `MRR@5` на golden set.
- [ ] Без `--expand` и без флага конфигурации метрики прежние (`Recall@5 0.483`
      в чанковом бенчмарке), расширение не вызывается.
- [ ] Поведение при сбое LLM проверено тестом.
