# Нечёткий поиск имён и подсказки при `not_found`

## Цель

Улучшить работу агента с `lookup_knowledge`, когда точное имя, алиас или
название эпизода не найдены из-за опечатки, другого окончания или лишнего
пробела. Вместо пустого `not_found` инструмент возвращает несколько компактных
подсказок с каноническими именами; агент повторяет точный запрос по подсказке и
не выдумывает факты.

## Допущения

- Точный поиск не меняется и всегда выполняется первым. Нечёткий поиск —
  fallback только при отсутствии точных совпадений и загруженных знаниях.
- Подсказки строятся по нормализованным именам и алиасам персонажей, локаций и
  артефактов, а также по нормализованным названиям эпизодов. Slug в нечёткий
  поиск не входит: точный slug по-прежнему ищется.
- Статус остаётся `not_found`; подсказки — отдельное поле `suggestions`, а не
  карточки. Агент не должен считать подсказку каноническим фактом до повторного
  точного поиска.
- Порог сходства — `0.3`, лимит — `5` подсказок. Порядок: сходство по
  убыванию, затем тип и `id`. Значение сходства наружу не отдаётся.
- PostgreSQL использует `pg_trgm` и GIN-индексы. In-memory хранилище считает
  триграммное сходство детерминированно, чтобы контрактные тесты работали без
  БД.
- Новых зависимостей нет. Миграция — `0012`; расширение `pg_trgm` остаётся в
  БД при `downgrade`, удаляются только индексы RAG.

## Требования

### Порт чтения

- REQ-001: `LookupSuggestion` содержит `type` (`character`, `location`,
  `artifact`, `episode`), `id` и каноническое `name`. `KnowledgeReader`
  получает `suggest(key, limit=5) -> tuple[LookupSuggestion, ...]`; ключ уже
  нормализован вызывающим.
- REQ-002: `InMemoryKnowledgeStore.suggest` считает триграммное сходство
  нормализованного ключа с нормализованными именами, алиасами и названиями
  эпизодов; возвращает не больше `limit` подсказок с каноническим именем
  сущности и тем же порядком, что PostgreSQL-адаптер.
- REQ-003: `PostgresKnowledgeStore.suggest` читает в `REPEATABLE READ READ
  ONLY` без advisory lock, делает фиксированное число запросов (по одному на
  тип) и использует GIN-индексы `pg_trgm`. Ошибки переводятся в существующие
  безопасные типы.

### Схема и индексы

- REQ-004: Миграция `0012` выполняет `CREATE EXTENSION IF NOT EXISTS pg_trgm` и
  создаёт GIN-индексы `gin_trgm_ops` на `rag_character_names.normalized`,
  `rag_location_names.normalized`, `rag_artifact_names.normalized` и
  `rag_episodes.normalized_title`. `tables.py` повторяет индексы; `downgrade`
  удаляет только индексы и не удаляет расширение.

### Use case поиска

- REQ-005: `KnowledgeLookup.lookup` сначала вызывает точный `find`. Если есть
  карточки, поведение не меняется. Если карточек нет, но знания загружены,
  вызывается `suggest`; при непустом результате возвращается `status=not_found`,
  `total=0`, `matches=()` и `suggestions`, а `message` предлагает повторить
  точный поиск по подсказке.
- REQ-006: Если подсказок нет, возвращается прежний `not_found` с
  `NOT_FOUND_MESSAGE`. Если знания не загружены или хранилище недоступно,
  возвращается `unavailable`; нечёткий поиск не маскирует недоступность.
- REQ-007: Подсказки ограничены `limit`, не дублируются, не содержат карточек,
  фактов, `sources` и slug вместо имени. `LookupResult.suggestions` по
  умолчанию пуст, поэтому старые ответы остаются совместимыми.

### Инструмент и наблюдаемость

- REQ-008: `lookup_knowledge` возвращает `suggestions` в JSON; описание
  инструмента на английском упоминает, что при наличии подсказок нужно
  повторить поиск по одной из них, а при `not_found`/`unavailable` нельзя
  выдавать выдуманные факты за канон.
- REQ-009: Событие `rag.lookup.completed` получает `suggestion_count`; поле
  аддитивно добавляется в `observability._SAFE_FIELDS`. Текст запроса,
  подсказки и карточки в журнал не попадают.

### Документация и тесты

- REQ-010: `docs/rag.md` описывает fallback, порог, лимит, формат подсказок и
  индексы; `docs/knowledge.md` — `pg_trgm` и миграцию `0012`;
  `docs/database.md` — диапазон миграций; `docs/logging.md` —
  `suggestion_count`; `docs/README.md` и раздел «Реализованный каталог знаний»
  `AGENTS.md` получают строки о нечётком поиске.
- REQ-011: Тесты покрывают in-memory и PostgreSQL `suggest`, точный поиск без
  изменений, fallback, лимит, пустые подсказки, JSON инструмента, индексы и
  миграцию. `make lint`, `make test` и `make test-integration` проходят.

## Сценарии

### Опечатка в имени персонажа

- Given загружен персонаж `pin` с именем «Пин» и алиасом «Пин-механик»
- When агент ищет «Пинн»
- Then точного совпадения нет, `status="not_found"`, в `suggestions` есть
  `character/pin` с именем «Пин», `matches=[]`

### Опечатка в названии эпизода

- Given загружен эпизод `s01e01` с названием «Пинг-понг»
- When агент ищет «Пинг понгг»
- Then в подсказках есть `episode/s01e01` с названием «Пинг-понг»

### Точное совпадение не меняется

- Given загружен персонаж «Пин»
- When агент ищет «Пин»
- Then `status="found"`, карточка персонажа, `suggestions=[]`

### Слишком далёкий запрос

- Given загруженные знания без похожего имени
- When агент ищет «Бармалей»
- Then `status="not_found"`, `suggestions=[]`, прежний `NOT_FOUND_MESSAGE`

### Лимит подсказок

- Given несколько похожих имён
- When `suggest` вызывается с `limit=2`
- Then возвращаются ровно две подсказки в детерминированном порядке

### Знания недоступны

- Given пустая БД или недоступное хранилище
- When вызывается поиск
- Then `status="unavailable"`, подсказки не подменяют ошибку

### Миграция

- Given БД на миграции `0011`
- When применяется `0012`
- Then расширение и четыре GIN-индекса существуют; `downgrade` удаляет индексы,
  расширение остаётся

## Границы

- Всегда: точный поиск первым; подсказки только имена и идентификаторы; не
  отдавать факты из подсказок как канон; не логировать запрос и подсказки.
- Сначала спросить: изменение порога/лимита как пользовательской настройки;
  поиск по slug и нечёткий поиск по другим полям; новые зависимости; изменения
  других модулей.
- Никогда: заменять `not_found` на `found` без точного совпадения; отдавать
  карточки в `suggestions`; искать по содержимому описаний; удалять расширение
  `pg_trgm` при downgrade.

## Критерии приёмки

- [ ] `suggest` реализован для in-memory и PostgreSQL и проходит контракт.
- [ ] Точный поиск не изменился; fallback возвращает `suggestions` только при
      отсутствии точных совпадений.
- [ ] Подсказки ограничены, детерминированы и не содержат карточек/фактов.
- [ ] `lookup_knowledge` возвращает подсказки в JSON и обновлённое описание.
- [ ] Событие журнала содержит `suggestion_count` без текста и знаний.
- [ ] Миграция `0012` создаёт расширение и GIN-индексы, `downgrade` обратим.
- [ ] Документация обновлена, diff общих файлов аддитивный.
- [ ] `make lint`, `make test` и `make test-integration` проходят.
