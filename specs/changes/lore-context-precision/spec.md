# Точность контекста RAG для сказки

## Цель

Убрать из контекста сказки слабые совпадения BM25 и предметы, которые
просочились через свободные трейты `get_story_canon`. Живой прогон показал две
проблемы: запрос `Крош Ёжик дружба` оставлял только один документ и отбрасывал
«Скамейку» из-за относительного порога, а профиль Ёжика содержал трейт
«коллекционирует фантики», из-за чего фантик попадал в каждую сказку.

## Требования

- REQ-001: `LoreContextBuilder` отбрасывает фрагменты ниже абсолютного
  `min_score` (по умолчанию `2.0`); относительный порог `0.5` не используется.
- REQ-002: второй и третий релевантные документы с меньшим, но ненулевым
  баллом сохраняются, если проходят `min_score`.
- REQ-003: запрос, состоящий только из имён персонажей и служебных слов
  (`Крош`, `Крош и Ёжик`), даёт `status=empty` даже при найденных чанках.
- REQ-004: запрос с содержательным термом (`Крош строит скамейку`) не
  отбрасывается правилом содержательных термов.
- REQ-005: `SearchLore` отдаёт проанализированные термы запроса инструменту,
  чтобы анализ выполнялся один раз.
- REQ-006: `StoryCanonLookup` отбрасывает трейты, в которых назван артефакт
  или локация, по каноническим именам; трейты без предметов сохраняются.
- REQ-007: `KnowledgeReader` получает необязательный `prop_names()`; без
  поддержки он возвращает пустой кортеж, PostgreSQL и in-memory реализации
  отдают канонические имена артефактов и локаций.
- REQ-008: описание `get_story_canon` предлагает вызвать `search_lore` для
  сцены, предмета или места, не превращая профиль в сюжет.
- REQ-009: схема БД, миграции и формат пакетов не меняются.

## Сценарии

### Дружба Кроша и Ёжика

- Given в лоре есть «Настоящие ценности» и «Скамейка»
- When агент ищет `Крош Ёжик дружба`
- Then в контекст попадают оба документа, а не только первый.

### Запрос из одного имени

- Given в лоре много документов с Крошем
- When агент ищет `Крош`
- Then контекст пуст и модель не получает случайный эпизод.

### Профиль Ёжика

- Given в каноне у Ёжика есть трейт «коллекционирует фантики» и артефакт
  «Коллекция фантиков»
- When вызывается `get_story_canon`
- Then фантик в профиль не попадает, а «дорожит старыми вещами» остаётся.

## Технологии и структура

- `rag/lore/context.py` — абсолютный `min_score` и правило содержательных
  термов.
- `rag/lore/services.py` — публичный анализ запроса.
- `rag/lore/tools.py`, `rag/tools.py` — передача термов и описание инструмента.
- `rag/story_canon.py` — фильтр трейтов по каноническим именам артефактов и
  локаций.
- `rag/ports.py`, `rag/memory.py`, `rag/postgres.py` — `prop_names()`.
- Миграции и схема БД не меняются.

## Границы

- Всегда: профиль героя — ограничение на характер, а не список предметов.
- Сначала спросить: изменение схемы БД, формата пакетов, системного промпта.
- Никогда: не отдавать в сказку свободные описания отношений и предметы;
  не удалять артефакты и локации из полного канона.

## Критерии приёмки

- [x] Относительный порог заменён абсолютным `min_score`.
- [x] Запрос из одного имени даёт пустой контекст.
- [x] «Скамейка» не вытесняется более сильным первым документом.
- [x] Фантик не попадает в профиль Ёжика.
- [x] Схема БД не изменилась.
- [x] `make test` проходит.
