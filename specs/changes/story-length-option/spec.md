# Выбор длины истории

## Цель

Пользователь чата хочет управлять объёмом сказки: короткая история на пару
минут перед сном или длинная на десять минут. Рядом с кнопкой отправки
появляется выпадающий список длины, выбранное значение передаётся агенту
как ограничение объёма ответа. Текст запроса в истории диалога не меняется.

## Требования

### Frontend

- REQ-001: Слева от кнопки «Отправить» в поле ввода находится выпадающий
  список «Длина» с вариантами «Любая» (по умолчанию), «~2 мин», «~5 мин» и
  «~10 мин». Список имеет доступную подпись «Длина истории» и управляется с
  клавиатуры.
- REQ-002: Выбранная длина сохраняется до перезагрузки страницы и применяется
  к каждому следующему запросу, в том числе после переключения историй и
  «+ Новая история». В `localStorage`, cookie или URL она не сохраняется.
- REQ-003: При «Любая» запрос отправляется в прежнем формате
  `{"request": "..."}`; при выборе длины — `{"request": "...",
  "reading_minutes": 2|5|10}`.
- REQ-004: Список заблокирован в тех же состояниях, что и поле ввода (до
  `ready`, во время отправки и ответа агента).
- REQ-005: На ширине от `320px` список помещается в поле ввода рядом с кнопкой
  без горизонтальной прокрутки.

### Backend

- REQ-006: `POST /api/v1/dialogs/{dialog_id}/messages` принимает
  необязательное поле `reading_minutes` со значениями `2`, `5` или `10`.
  Любое другое значение (включая `0`, `3`, строку, дробное число и `null`
  вместе с явным ключом) даёт `422` в прежнем формате FastAPI; без поля
  поведение не меняется.
- REQ-007: При заданной длине агент получает для этого запроса отдельное
  системное сообщение после основного системного промпта: «Объём ответа:
  история примерно на N минут чтения — около W слов.», где `W = N × 150`
  (300, 750 и 1500 слов). Без длины такого сообщения нет.
- REQ-008: В историю диалога сохраняется только текст запроса пользователя;
  указание длины не попадает в историю, в `GET .../messages` и в контекст
  следующих запросов.
- REQ-009: Журнал не содержит текста запроса; значение `reading_minutes`
  допускается журналировать как число.

## Сценарии

### Короткая история

- Given пользователь выбрал «~2 мин»
- When он отправляет «Крош и Ёжик строят ракету»
- Then backend получает `reading_minutes: 2`, агент получает указание около
  300 слов, а в истории сохранено только «Крош и Ёжик строят ракету»

### Без ограничения

- Given выбрано «Любая»
- When пользователь отправляет запрос
- Then тело запроса не содержит `reading_minutes`, агент не получает указания
  длины

### Некорректное значение

- Given клиент отправляет `reading_minutes: 7`
- When backend валидирует тело
- Then ответ `422`, агент не запускается

## Технологии и структура

- Backend: `UserRequest` в `smeshariki_ai.agent` получает необязательное поле
  `reading_minutes`; `Agent` добавляет системное сообщение длины;
  `SubmitMessageRequest` в `api/schemas.py` принимает поле; `AgentService`
  передаёт `UserRequest` целиком и сохраняет только `content`.
- Frontend: `index.html` (список в композере), `styles.css`, `script.js`,
  `agent-api.js` (`submitMessage(dialogId, request, { readingMinutes })`).
- Документация: `docs/agent.md`, `docs/dialogs.md`, `frontend/README.md`,
  `AGENTS.md`.

## Команды

- Запуск: `make run`
- Тесты: `make test`
- Линтер: `make lint`

## Тестирование

- Модульные тесты `Agent` с `FakeLLMProvider`: системное сообщение длины
  присутствует с правильным числом слов для 2/5/10 и отсутствует без длины.
- Модульные тесты `AgentService`: в историю сохраняется только `content`.
- Интеграционные API-тесты: `202` с допустимыми значениями и без поля, `422`
  для недопустимых, агент не запускается при `422`.
- Node-тесты `AgentApi`: тело запроса с полем и без него.
- Node-тесты UI: выбор длины передаётся в следующий запрос, сохраняется после
  «+ Новая история», список блокируется вместе с полем.
- Скриншоты композера на `1440x900` и `320x640`; ручная проверка с реальной
  моделью: ответы на 2 и 10 минут заметно различаются по объёму.

## Границы

- Всегда: валидировать значение на backend; не сохранять указание длины в
  историю.
- Сначала спросить: произвольное значение длины, другие единицы (слова,
  абзацы), сохранение выбора между перезагрузками.
- Никогда: не встраивать указание длины в текст пользовательского сообщения.

## Критерии приёмки

- [ ] Список «Длина» с вариантами «Любая», «~2 мин», «~5 мин», «~10 мин» у
  кнопки отправки, без горизонтальной прокрутки от `320px`.
- [ ] Выбранная длина передаётся в `reading_minutes`, недопустимые значения
  дают `422`.
- [ ] Агент получает указание длины отдельным системным сообщением; история
  содержит только текст запроса.
- [ ] `make test` и `make lint` проходят успешно.

## Открытые вопросы

- Нет. Допущения: скорость чтения — 150 слов в минуту; длина — ориентир для
  модели, точное число слов не проверяется и не обрезается.
