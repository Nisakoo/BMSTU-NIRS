# Размещение статического frontend-прототипа в `src`

## Цель

Упорядочить frontend-каталог: перенести все файлы реализации статического
прототипа из корня `frontend/` в `frontend/src/`, сохранив внешний вид,
поведение и отдельный от backend способ запуска.

## Требования

- REQ-001: `smeshariki_ai.html`, `styles.css`, `script.js` и дерево
  `static/characters/` находятся внутри `frontend/src/` и отсутствуют в корне
  `frontend/`.
- REQ-002: Содержимое HTML, CSS, JavaScript и двух PNG не изменяется при
  переносе; их контрольные суммы совпадают с состоянием до рефакторинга.
- REQ-003: `frontend/README.md` и каталог `frontend/tests/` остаются на уровне
  `frontend/`; ставший ненужным `frontend/src/.gitkeep` удаляется.
- REQ-004: При раздаче `frontend/src/` как корня статического сайта страница,
  CSS, JavaScript и оба изображения загружаются по существующим ссылкам без
  изменения кода прототипа.
- REQ-005: Документация frontend и глобальный архитектурный каталог отражают
  новую структуру и актуальную команду локального запуска.

## Сценарии

### Основной сценарий

- Given реализация прототипа лежит в корне `frontend/`, а `frontend/src/`
  содержит только `.gitkeep`
- When файлы реализации и каталог `static/` переносятся в `frontend/src/`
- Then корень `frontend/` содержит документацию, `src/` и `tests/`, а весь
  исполняемый статический frontend находится внутри `src/`

### Локальный запуск после переноса

- Given прототип перенесён в `frontend/src/`
- When разработчик запускает статический HTTP-сервер с корнем `frontend/src/`
- Then `smeshariki_ai.html`, `styles.css`, `script.js` и
  `/static/characters/*.png` отвечают успешно и страница выглядит как до
  рефакторинга

### Сохранение служебных каталогов

- Given `frontend/` содержит `README.md` и `tests/.gitkeep`
- When выполняется рефакторинг структуры
- Then документация и каталог тестов не перемещаются и не удаляются

## Технологии и структура

Frontend остаётся статическим HTML/CSS/JavaScript без сборщика, package manager
и фреймворка. Итоговая структура реализации:

```text
frontend/
├── README.md
├── src/
│   ├── smeshariki_ai.html
│   ├── styles.css
│   ├── script.js
│   └── static/characters/
│       ├── krosh.png
│       └── kopatych.png
└── tests/.gitkeep
```

## Команды

- Локальный просмотр:
  `uv run --no-project python -m http.server 4173 --directory frontend/src`
- Тесты: `make test`.

## Тестирование

Автоматические тесты структуры не добавляются. Рефакторинг проверяется
сравнением SHA-256 до и после переноса, ревью дерева, HTTP smoke всех ресурсов
и визуальным снимком страницы. `make test` запускается как регрессионная
проверка существующего продукта.

## Границы

- Всегда: переносить только файлы реализации прототипа; сохранить их байтовое
  содержимое и работоспособность существующих ссылок.
- Сначала спросить: перенос `README.md` или `tests/` внутрь `src`, переименование
  HTML-файла, изменение разметки, стилей, JavaScript или подключение backend.
- Никогда: добавлять frontend в Docker Compose, вводить новый frontend-стек,
  менять backend или переписывать завершённые SDD-артефакты предыдущего
  изменения.

## Критерии приёмки

- [ ] Все пять файлов реализации находятся под `frontend/src/`; их прежние
  пути в корне `frontend/` отсутствуют.
- [ ] Контрольные суммы всех перенесённых файлов совпадают с состоянием до
  рефакторинга.
- [ ] `frontend/src/.gitkeep` удалён, а `frontend/README.md` и
  `frontend/tests/.gitkeep` сохранены.
- [ ] HTTP-проверка и визуальный снимок подтверждают корректную загрузку
  страницы и ресурсов при корне сервера `frontend/src/`.
- [ ] Документация содержит итоговую структуру и актуальную команду запуска.
- [ ] `make test` проходит успешно; новые структурные тесты не добавлены.

## Открытые вопросы

- Нет. Под «перенести в `src` всё» понимаются все файлы реализации прототипа;
  документация и тестовый каталог сохраняют обычное положение в корне
  `frontend/`.
