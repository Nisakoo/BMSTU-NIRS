# Размещение статического frontend-прототипа в `src`

## Цель

Упорядочить frontend-каталог: перенести все файлы реализации статического прототипа из корня `frontend/` в `frontend/src/`, сохранив внешний вид, поведение и отдельный от backend способ запуска.

## Требования

- REQ-001: `smeshariki_ai.html`, `styles.css`, `script.js` и дерево
  `static/characters/` находятся внутри `frontend/src/` и отсутствуют в корне
  `frontend/`.
- REQ-002: Содержимое HTML, CSS, JavaScript и двух PNG не изменяется при переносе; их контрольные суммы совпадают с состоянием до рефакторинга.
- REQ-003: `frontend/README.md` и каталог `frontend/tests/` остаются на уровне
  `frontend/`; ставший ненужным `frontend/src/.gitkeep` удаляется.
- REQ-004: При раздаче `frontend/src/` как корня статического сайта страница, CSS, JavaScript и оба изображения загружаются по существующим ссылкам без изменения кода прототипа.
- REQ-005: Документация frontend и глобальный архитектурный каталог отражают новую структуру и актуальную команду локального запуска.

## Границы

- Всегда: переносить только файлы реализации прототипа; сохранить их байтовое содержимое и работоспособность существующих ссылок.
- Сначала спросить: перенос `README.md` или `tests/` внутрь `src`, переименование HTML-файла, изменение разметки, стилей, JavaScript или подключение backend.
- Никогда: добавлять frontend в Docker Compose, вводить новый frontend-стек, менять backend или переписывать завершённые SDD-артефакты предыдущего изменения.
