# Структура frontend в `src`

## Цель

Сохранить чат, вход и регистрацию, панель администратора и их адреса при переносе реализации на Svelte и TypeScript. Первоначальный перенос статического прототипа в `src/` зафиксирован в [плане](plan.md) и [проверке](verification.md).

## Требования

- REQ-001. Vite собирает три HTML-точки входа из `frontend/src/`. Адреса `/`, `/login/` и `/admin/` открываются напрямую.
- REQ-002. Svelte-компоненты на TypeScript сохраняют оформление, адаптивность, доступные действия и ролевые переходы. Динамические значения выводятся как текст.
- REQ-003. Слои Feature-Sliced Design разделяют монтаж приложения, страницы, виджеты, пользовательские действия, предметные сущности и общий код. Внешние потребители используют публичный интерфейс модуля.
- REQ-004. По Flux изменение состояния сценария проходит через действие и редьюсер. Компоненты подписываются на хранилище. Эффекты обращаются к API и отправляют действия с результатом.
- REQ-005. HTTP и SSE используют существующие same-origin контракты. Пути запросов, семантика сессии и порядок потоковых сообщений сохраняются.
- REQ-006. README, тесты и настройки сборки остаются на уровне `frontend/`. Корневой `AGENTS.md` указывает на [правила фронтенда](../../../frontend/AGENTS.md).

## Проверка

Проверяются типы и шаблоны Svelte, сценарии трёх страниц, сетевые клиенты, production-сборка и Vite proxy для HTTP и SSE. Команды приведены в [руководстве frontend](../../../frontend/README.md).
