# План: размещение статического frontend-прототипа в `src`

## Основание

План реализует согласованную спецификацию
`specs/changes/frontend-src-layout/spec.md`. Это структурный рефакторинг без
изменения содержимого и поведения прототипа.

## Зависимости и порядок

1. Сначала фиксируются контрольные суммы текущих файлов и проверяется отсутствие
   конфликтующих путей в `frontend/src/`.
2. Затем в `src/` переносятся текстовые файлы реализации и удаляется ставший
   ненужным `.gitkeep`.
3. После этого туда же переносится дерево статических изображений.
4. Документация обновляется только после формирования фактической структуры.
5. Итог проверяется HTTP smoke, визуальным снимком и полным регрессионным
   набором тестов.

Новые зависимости не требуются.

## Задача 1. Перенести HTML, CSS и JavaScript

**Связанные требования:** REQ-001–REQ-003.

**Критерии приёмки:** три текстовых файла находятся в `frontend/src/`, их
прежние пути отсутствуют, контрольные суммы сохранены, `.gitkeep` удалён.

**Зависимости:** нет.

**Файлы:**

- `frontend/src/smeshariki_ai.html`;
- `frontend/src/styles.css`;
- `frontend/src/script.js`;
- `frontend/src/.gitkeep`.

**Действия:**

1. Зафиксировать SHA-256 трёх исходных файлов и проверить целевые пути.
2. Удалить `.gitkeep` и переместить файлы в `frontend/src/`.
3. Повторно вычислить SHA-256 и сравнить результаты.

**Проверка ревью:**

```sh
shasum -a 256 frontend/src/smeshariki_ai.html frontend/src/styles.css frontend/src/script.js
```

## Задача 2. Перенести статические изображения

**Связанные требования:** REQ-001–REQ-004.

**Критерии приёмки:** оба PNG находятся в
`frontend/src/static/characters/`, старое дерево `frontend/static/`
отсутствует, контрольные суммы сохранены.

**Зависимости:** задача 1.

**Файлы:**

- `frontend/src/static/characters/krosh.png`;
- `frontend/src/static/characters/kopatych.png`.

**Действия:**

1. Зафиксировать SHA-256 изображений.
2. Переместить всё дерево `frontend/static/` в `frontend/src/`.
3. Проверить итоговые пути, отсутствие старого дерева и контрольные суммы.

**Проверка ревью:**

```sh
find frontend -maxdepth 5 -print | sort
shasum -a 256 frontend/src/static/characters/krosh.png frontend/src/static/characters/kopatych.png
```

## Задача 3. Обновить документацию

**Связанные требования:** REQ-005.

**Критерии приёмки:** описание состава и команда запуска используют
`frontend/src/`, глобальный каталог отражает новое расположение реализации.

**Зависимости:** задачи 1 и 2.

**Файлы:**

- `frontend/README.md`;
- `docs/README.md`.

**Действия:**

1. Обновить дерево файлов и команду статического сервера в frontend README.
2. Обновить путь реализации и ссылки SDD в глобальном каталоге.
3. Сохранить описание текущего демонстрационного ограничения JavaScript.

**Проверка ревью:**

```sh
sed -n '1,260p' frontend/README.md
sed -n '1,280p' docs/README.md
```

## Задача 4. Проверить runtime и регрессии

**Связанные требования:** REQ-001–REQ-005.

**Критерии приёмки:** все ресурсы получают HTTP 200 при корне
`frontend/src/`, страница визуально совпадает с состоянием до рефакторинга,
полный набор продуктовых тестов проходит.

**Зависимости:** задачи 1–3.

**Изменяемые файлы:** нет.

**Действия:**

1. Запустить статический сервер с корнем `frontend/src/`.
2. Проверить HTML, CSS, JavaScript и оба PNG по HTTP.
3. Получить и просмотреть снимок страницы в headless Chrome.
4. Запустить `make test`, `git diff --check` и проверить итоговое дерево.

**Команды проверки:**

```sh
uv run --no-project python -m http.server 4173 --directory frontend/src
make test
git diff --check
git status --short
```

## Итоговая проверка реализации

1. Сопоставить REQ-001–REQ-005 и критерии приёмки с результатами проверок.
2. Убедиться, что файлы реализации отсутствуют в корне `frontend/` и целиком
   находятся в `frontend/src/`.
3. Убедиться, что байтовое содержимое файлов не менялось, backend и зависимости
   не затронуты.
4. Записать результаты в `verification.md` и установить `done` только после
   успешного verify.
