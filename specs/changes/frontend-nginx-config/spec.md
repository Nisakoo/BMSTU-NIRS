# Конфигурация Nginx для frontend: относительные редиректы и кэширование

## Цель

Frontend-контейнер использует стандартный `nginx:stable-alpine` с
`default.conf`. Для каталога без завершающего слеша Nginx отвечает абсолютным
редиректом со своим внутренним портом: при `make run`
`http://localhost:8080/login` ведёт на `http://localhost/login/` (порт 80), и
страница не открывается. То же для `/admin`. Диагностика подтвердила первопричину: после `absolute_redirect off;` редирект сохраняет порт. Кроме того, `Cache-Control` не задан, и браузер может эвристически кэшировать
HTML-страницы после пересборки.

Изменение добавляет собственный конфиг Nginx в `docker/`, чтобы сайт открывался по любому адресу без слеша и всегда получал актуальные HTML.

## Требования

- REQ-001: `GET /login` и `GET /admin` через Caddy отвечают редиректом с относительным `Location` (`/login/`, `/admin/`), так что браузер остаётся на том же host и порту (`APP_PORT`). Переход по редиректу отдаёт `200` и
  страницу.
- REQ-002: `/`, `/login/`, `/admin/` и прямые пути к `index.html` отдают HTML с
  `Cache-Control: no-cache`.
- REQ-003: Хешированные Vite-ассеты в `/assets/` отдаются с
  `Cache-Control: public, max-age=31536000, immutable`; несуществующий ассет —
  `404`, а не HTML.
- REQ-004: Несуществующие пути вне `/api` отвечают `404`, как и раньше; SPA fallback не вводится. Маршрутизация `/api` в Caddy не меняется.
- REQ-005: Конфиг хранится в `docker/` и копируется в образ в
  `docker/frontend.Dockerfile`; healthcheck frontend продолжает работать.
- REQ-006: `docker/README.md`, `frontend/README.md` (раздел о production запуске) и при необходимости `docs/README.md` и `AGENTS.md` («Реализованный
  frontend») упоминают собственный конфиг Nginx, относительные редиректы и политику кэширования со ссылками на артефакты этой спецификации.

## Границы

- Всегда: все файлы контейнерного запуска — в `docker/`.
- Сначала спросить: SPA fallback, изменение Caddyfile, security-заголовки (CSP и т. п.).
- Никогда: публиковать порт Nginx на хосте; проксировать `/api` через Nginx.
