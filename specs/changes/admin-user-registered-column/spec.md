# Дата регистрации вместо статуса пользователя

## Цель

В списке «Последние пользователи» панели `/admin/` колонка «Статус»
показывает «Новый», «Активен» или «Неактивен» по сложному правилу:
«Новый» — регистрация в периоде отчёта, и он важнее активности. Поэтому
почти все недавние пользователи выглядят «Новыми», даже если активно пишут
истории, и статус мало что сообщает. Активность и так видна в соседней
колонке. Пользователь выбрал заменить статус датой регистрации.

## Требования

- REQ-001: Колонка «Статус» заменяется колонкой «Регистрация» в заголовке
  списка и в каждой строке (`data-label="Регистрация"` для мобильной
  раскладки).
- REQ-002: Значение — дата `registered_at` без времени: «сегодня», «вчера»,
  иначе «12 окт.»; для другого года — с годом («2 янв. 2025 г.»).
- REQ-003: Статусы «Новый / Активен / Неактивен» в панели больше не
  показываются. HTTP-контракт `GET /api/v1/admin/stats` не меняется: поле
  `status` остаётся в ответе.
- REQ-004: Остальные колонки, порядок пользователей и пустой список не
  меняются; нет горизонтальной прокрутки на 1280 и 390 px.

## Технологии и структура

- `frontend/src/admin/admin.js`: ячейка регистрации вместо статуса,
  форматирование даты.
- `frontend/src/admin/index.html`: заголовок колонки.
- `frontend/src/admin/admin.css`: стили ячейки, удаление стилей статуса.
- Документация: `docs/admin.md`, `frontend/README.md`.

## Тестирование

- UI-тест списка пользователей: даты «сегодня», «вчера», с месяцем и с
  годом; статусов нет.
- Ручная проверка через CDP на 1280 и 390 px, скриншоты.

## Критерии приёмки

- [ ] В списке пользователей колонка «Регистрация» с датой вместо статуса.
- [ ] `make test` проходит; Python-код не меняется.

## Открытые вопросы

- Нет. Спецификация повторяет выбор пользователя («Заменить на дату
  регистрации»).
