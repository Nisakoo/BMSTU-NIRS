# Выбор голоса, компактный плеер и хранение озвучки в Ceph

## Цель

Добавить выбор голоса рассказчика прямо в интерфейсе чата, сохранять выбор только во frontend, показывать аккуратный компактный плеер и кнопку скачивания, а
MP3-файлы хранить в Ceph. Метаданные генерации остаются в PostgreSQL. Изменение расширяет `silero-narrator-tts`: вместо одного голоса из `SPEECH_VOICE`
пользователь выбирает один из встроенных голосов Silero v5. `SPEECH_VOICE` остаётся значением по умолчанию, если голос не передан.

## Требования

### Frontend: выбор голоса
- REQ-001: Кнопка выбора голоса показывает название текущего голоса и стрелку вниз. На экране шириной до 360 px кнопка показывает значок микрофона. Доступное имя во всех вариантах включает текущий голос.
- REQ-002: Над кнопкой открывается компактное меню с двумя голосами, Айдар (`aidar`) и Ксения (`xenia`). Каждый занимает одну строку, текущий отмечен галочкой. Меню закрывается по `Escape`, повторному нажатию и клику вне.
- REQ-003: Меню управляется с клавиатуры: стрелки перемещают выбор, `Enter` применяет, `Escape` закрывает без изменения. У контрола есть доступное имя вроде «Выбрать голос рассказчика, сейчас Айдар».
- REQ-004: Выбранный голос хранится в `localStorage` под ключом `smeshariki.voice`. Значение читается при загрузке страницы, записывается при каждом изменении и применяется ко всем сообщениям, диалогам и кнопкам озвучки.
- REQ-005: Устаревшее или неизвестное значение в `localStorage` заменяется на `aidar`. При первом посещении выбран Айдар.
- REQ-006: Выбор голоса не сохраняется на backend и не меняет `SPEECH_VOICE`; он действует только в текущем браузере. ### Frontend: плеер и скачивание
- REQ-007: Для выбранного голоса `POST .../audio` отправляет JSON `{"voice":"<id>"}`. Если для выбранного голоса уже есть запись, рядом с плеером показывается «Скачать», а отдельная компактная кнопка «Озвучить заново» запускает новую
  генерацию.
- REQ-008: Плеер компактный, высотой около 36–40 px, в стиле чата: play/pause, полоса прогресса, текущее время и длительность. Нативный `<audio>` используется только как источник звука; управление оформлено своими элементами.
- REQ-009: Кнопка «Скачать» маленькая и аккуратная, с иконкой и доступной подписью. Она скачивает MP3 через авторизованный `GET .../audio?download=1` с именем `smeshariki-<message_id>-<voice_id>.mp3`.
- REQ-010: На ширине до 820 px плеер и кнопки занимают ширину пузыря, не создают горизонтальной прокрутки и не перекрывают мордашки и жалобу.
- REQ-011: При смене голоса плеер и состояние кнопок пересчитываются для нового голоса. Если для него нет записи, показывается «Озвучить»; если есть — плеер и «Скачать».
- REQ-012: Пока идёт перегенерация, старый плеер и скачивание остаются доступными; кнопка показывает «Готовим озвучку…». После успеха плеер обновляется, после ошибки остаётся старая запись и безопасное сообщение.
- REQ-013: При переключении диалога или новой истории плеер останавливается, незавершённый polling прекращается, выбранный голос при этом не сбрасывается. ### Backend: голос в запросе
- REQ-014: `POST /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio` принимает необязательное тело `{"voice":"<id>"}`. Без тела используется `SPEECH_VOICE`; неизвестный голос даёт `422`.
- REQ-015: `GET /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio` принимает необязательный `?voice=<id>`. Без параметра используется `SPEECH_VOICE`; неизвестный голос даёт `422`.
- REQ-016: Каждый `POST` создаёт новую генерацию, даже если для пары `(message_id, voice_id)` уже есть готовый MP3. Кэш-хит по готовой записи запрещён.
- REQ-017: Новая генерация не удаляет и не скрывает старый MP3 до успешного завершения. При ошибке старый объект и метаданные остаются доступными.
- REQ-018: После успешной генерации новый объект становится текущим, а старый объект удаляется из Ceph. При ошибке удаление старого объекта не выполняется.
- REQ-019: `GET /api/v1/dialogs/{dialog_id}/messages` для каждого сообщения возвращает `audio_voices` — список голосов, для которых есть готовая запись. Поле не раскрывает ключи Ceph и ошибки генерации. ### Backend: Ceph и метаданные
- REQ-020: MP3-байты хранятся только в Ceph. PostgreSQL не содержит бинарного аудио для новых записей.
- REQ-021: `message_audio` хранит метаданные по паре `(message_id, voice_id)`: `status`, `text_hash`, `voice_version`, `object_key`, `size_bytes`, `etag`, `duration_ms`, `mime_type`, `error_code`, `created_at`, `updated_at`.
- REQ-022: `object_key` имеет вид `smeshariki-audio/{dialog_id}/{message_id}/{voice_id}/{generation_id}.mp3`. Ceph bucket приватный; прямой публичный URL не используется.
- REQ-023: Для Ceph вводится порт `AudioObjectStore` с реализациями `CephS3AudioObjectStore` и `InMemoryAudioObjectStore` для тестов.
- REQ-024: Ceph-клиент использует S3-совместимый API, path-style addressing и не логирует содержимое объектов, access key и secret key.
- REQ-025: При недоступности Ceph ручки озвучки возвращают безопасный `503`; текст сказки, object key и ключи доступа в ответ и лог не попадают.
- REQ-026: Существующие строки `message_audio` с `audio_data` переносятся в Ceph лениво: при первом чтении/озвучке backend загружает байты в Ceph, записывает `object_key` и очищает `audio_data`. Колонка `audio_data` остаётся nullable для
  обратной совместимости этого изменения и больше не заполняется новыми генерациями.
- REQ-027: После рестарта строка `pending` с существующим `object_key` считается готовой; `pending` без объекта переводится в `failed`. ### Ceph в Compose
- REQ-028: В `docker/compose.yaml` добавляется сервис `ceph-rgw` на Ceph RGW-совместимом образе `quay.io/s3gw/s3gw` с файловым backend и внутренним портом `7480`. Порт не публикуется на хосте.
- REQ-029: Данные Ceph сохраняются в именованном томе `ceph-data` и переживают перезапуск контейнеров.
- REQ-030: Backend получает настройки Ceph через environment: `CEPH_S3_ENDPOINT`, `CEPH_S3_BUCKET`, `CEPH_S3_ACCESS_KEY`, `CEPH_S3_SECRET_KEY`, `CEPH_S3_REGION`, `CEPH_S3_PREFIX`.
- REQ-031: Bucket создаётся идемпотентно при старте сервиса озвучки, если его ещё нет. Ошибка создания bucket не раскрывает credentials.
- REQ-032: `docker/.env.example` и `docker/README.md` содержат локальные значения Ceph без секретов production. ### Документация
