# Выбор голоса, компактный плеер и хранение озвучки в Ceph

## Цель

Добавить выбор голоса рассказчика прямо в интерфейсе чата, сохранять выбор
только во frontend, показывать аккуратный компактный плеер и кнопку скачивания,
а MP3-файлы хранить в Ceph. Метаданные генерации остаются в PostgreSQL.

Изменение расширяет `silero-narrator-tts`: вместо одного голоса из
`SPEECH_VOICE` пользователь выбирает один из встроенных голосов Silero v5.
`SPEECH_VOICE` остаётся значением по умолчанию, если голос не передан.

## Допущения

- Встроенные голоса Silero v5: `aidar`, `baya`, `kseniya`, `xenia`, `eugene`.
- Список голосов и их подписи задаются на frontend; backend не отдаёт каталог
  голосов, но проверяет переданный `voice`.
- Выбранный голос хранится только в `localStorage` браузера. Серверного
  профиля голоса, cookie и поля пользователя нет.
- Значение по умолчанию — `aidar`.
- Каждый `POST` озвучки запускает новую генерацию, даже если готовая запись
  уже есть.
- MP3 хранится в приватном Ceph bucket. PostgreSQL хранит только метаданные,
  статус и `object_key`.
- В `docker/compose.yaml` добавляется внутренний Ceph RGW-совместимый сервис
  `ceph-rgw` на образе `quay.io/s3gw/s3gw` с файловым backend. Это
  облегчённый Ceph RGW gateway, а не полноценный Ceph-кластер.
- Существующая запись `message_audio` с голосом `eugene` переносится в Ceph
  лениво при первом обращении.

## Требования

### Frontend: выбор голоса

- REQ-001: В интерфейсе чата есть компактный контрол выбора голоса. Надписи
  «Голос» нет: контрол показывает человекочитаемое название текущего голоса и
  небольшую стрелку вниз, намекающую на раскрытие.
- REQ-002: По нажатию контрол раскрывает аккуратное меню со всеми встроенными
  голосами, их короткими описаниями и отметкой текущего варианта. Меню
  закрывается по `Escape`, повторному нажатию и клику вне.
- REQ-003: Меню управляется с клавиатуры: стрелки перемещают выбор, `Enter`
  применяет, `Escape` закрывает без изменения. У контрола есть доступное имя
  вроде «Выбрать голос рассказчика, сейчас Айдар».
- REQ-004: Выбранный голос хранится в `localStorage` под ключом
  `smeshariki.voice`. Значение читается при загрузке страницы, записывается
  при каждом изменении и применяется ко всем сообщениям, диалогам и кнопкам
  озвучки.
- REQ-005: Неизвестное или повреждённое значение в `localStorage`
  игнорируется и заменяется `aidar`.
- REQ-006: Выбор голоса не сохраняется на backend и не меняет
  `SPEECH_VOICE`; он действует только в текущем браузере.

### Frontend: плеер и скачивание

- REQ-007: Для выбранного голоса `POST .../audio` отправляет JSON
  `{"voice":"<id>"}`. Если для выбранного голоса уже есть запись, рядом с
  плеером показывается «Скачать», а отдельная компактная кнопка
  «Озвучить заново» запускает новую генерацию.
- REQ-008: Плеер компактный, высотой около 36–40 px, в стиле чата: play/pause,
  полоса прогресса, текущее время и длительность. Нативный `<audio>`
  используется только как источник звука; управление оформлено своими
  элементами.
- REQ-009: Кнопка «Скачать» маленькая и аккуратная, с иконкой и доступной
  подписью. Она скачивает MP3 через авторизованный `GET .../audio?download=1`
  с именем `smeshariki-<message_id>-<voice_id>.mp3`.
- REQ-010: На ширине до 820 px плеер и кнопки занимают ширину пузыря, не
  создают горизонтальной прокрутки и не перекрывают мордашки и жалобу.
- REQ-011: При смене голоса плеер и состояние кнопок пересчитываются для
  нового голоса. Если для него нет записи, показывается «Озвучить»; если есть
  — плеер и «Скачать».
- REQ-012: Пока идёт перегенерация, старый плеер и скачивание остаются
  доступными; кнопка показывает «Готовим озвучку…». После успеха плеер
  обновляется, после ошибки остаётся старая запись и безопасное сообщение.
- REQ-013: При переключении диалога или новой истории плеер останавливается,
  незавершённый polling прекращается, выбранный голос при этом не сбрасывается.

### Backend: голос в запросе

- REQ-014: `POST /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio`
  принимает необязательное тело `{"voice":"<id>"}`. Без тела используется
  `SPEECH_VOICE`; неизвестный голос даёт `422`.
- REQ-015: `GET /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio`
  принимает необязательный `?voice=<id>`. Без параметра используется
  `SPEECH_VOICE`; неизвестный голос даёт `422`.
- REQ-016: Каждый `POST` создаёт новую генерацию, даже если для пары
  `(message_id, voice_id)` уже есть готовый MP3. Кэш-хит по готовой записи
  запрещён.
- REQ-017: Новая генерация не удаляет и не скрывает старый MP3 до успешного
  завершения. При ошибке старый объект и метаданные остаются доступными.
- REQ-018: После успешной генерации новый объект становится текущим, а старый
  объект удаляется из Ceph. При ошибке удаление старого объекта не выполняется.
- REQ-019: `GET /api/v1/dialogs/{dialog_id}/messages` для каждого сообщения
  возвращает `audio_voices` — список голосов, для которых есть готовая
  запись. Поле не раскрывает ключи Ceph и ошибки генерации.

### Backend: Ceph и метаданные

- REQ-020: MP3-байты хранятся только в Ceph. PostgreSQL не содержит бинарного
  аудио для новых записей.
- REQ-021: `message_audio` хранит метаданные по паре `(message_id, voice_id)`:
  `status`, `text_hash`, `voice_version`, `object_key`, `size_bytes`, `etag`,
  `duration_ms`, `mime_type`, `error_code`, `created_at`, `updated_at`.
- REQ-022: `object_key` имеет вид
  `smeshariki-audio/{dialog_id}/{message_id}/{voice_id}/{generation_id}.mp3`.
  Ceph bucket приватный; прямой публичный URL не используется.
- REQ-023: Для Ceph вводится порт `AudioObjectStore` с реализациями
  `CephS3AudioObjectStore` и `InMemoryAudioObjectStore` для тестов.
- REQ-024: Ceph-клиент использует S3-совместимый API, path-style addressing и
  не логирует содержимое объектов, access key и secret key.
- REQ-025: При недоступности Ceph ручки озвучки возвращают безопасный `503`;
  текст сказки, object key и ключи доступа в ответ и лог не попадают.
- REQ-026: Существующие строки `message_audio` с `audio_data` переносятся в
  Ceph лениво: при первом чтении/озвучке backend загружает байты в Ceph,
  записывает `object_key` и очищает `audio_data`. Колонка `audio_data`
  остаётся nullable для обратной совместимости этого изменения и больше не
  заполняется новыми генерациями.
- REQ-027: После рестарта строка `pending` с существующим `object_key`
  считается готовой; `pending` без объекта переводится в `failed`.

### Ceph в Compose

- REQ-028: В `docker/compose.yaml` добавляется сервис `ceph-rgw` на
  Ceph RGW-совместимом образе `quay.io/s3gw/s3gw` с файловым backend и
  внутренним портом `7480`. Порт не публикуется на хосте.
- REQ-029: Данные Ceph сохраняются в именованном томе `ceph-data` и переживают
  перезапуск контейнеров.
- REQ-030: Backend получает настройки Ceph через environment:
  `CEPH_S3_ENDPOINT`, `CEPH_S3_BUCKET`, `CEPH_S3_ACCESS_KEY`,
  `CEPH_S3_SECRET_KEY`, `CEPH_S3_REGION`, `CEPH_S3_PREFIX`.
- REQ-031: Bucket создаётся идемпотентно при старте сервиса озвучки, если его
  ещё нет. Ошибка создания bucket не раскрывает credentials.
- REQ-032: `docker/.env.example` и `docker/README.md` содержат локальные
  значения Ceph без секретов production.

### Документация

- REQ-033: Обновляются `docs/audio.md`, `docs/database.md`,
  `docs/configuration.md`, `docs/dialogs.md`, `docker/README.md`,
  `frontend/README.md` и `AGENTS.md`.

## Сценарии

### Первая озвучка выбранным голосом

- Given пользователь выбрал в меню «Айдар»
- When он нажимает «Озвучить»
- Then frontend отправляет `POST` с `voice: "aidar"`
- Then backend генерирует MP3, кладёт его в Ceph и сохраняет метаданные в
  PostgreSQL
- Then в ленте появляется компактный плеер и кнопка «Скачать»

### Повторная генерация

- Given для сообщения уже есть запись `aidar`
- When пользователь нажимает «Озвучить заново»
- Then старый плеер продолжает работать
- Then после успеха новый MP3 заменяет старый объект и метаданные
- Then при ошибке старый MP3 остаётся доступным

### Смена голоса

- Given сообщение озвучено голосом `aidar`
- When пользователь выбирает `xenia`
- Then `localStorage` сохраняет `xenia`
- Then для сообщения показывается «Озвучить», если записи `xenia` нет
- When генерация завершается
- Then плеер переключается на MP3 голосом `xenia`

### Перезагрузка страницы

- Given пользователь ранее выбрал `eugene` и озвучил сообщение
- When он открывает сайт снова
- Then `localStorage` восстанавливает `eugene`
- Then в сохранённой истории для этого сообщения доступны плеер и «Скачать»

### Неизвестный голос

- Given клиент отправляет `voice: "shrek"`
- When backend валидирует запрос
- Then ответ `422`, генерация не запускается

### Ceph недоступен

- Given Ceph RGW недоступен
- When пользователь запрашивает озвучку
- Then backend отвечает безопасным `503`, старые метаданные не раскрываются

## Технологии и структура

- Frontend: `frontend/src/script.js`, `agent-api.js`, `styles.css`,
  локальный модуль выбора голоса или функции в `script.js`; тесты в
  `frontend/tests/`.
- Backend: расширение `smeshariki_ai.speech`:
  - `config.py` — `CephS3Config`;
  - `objects.py` — `AudioObjectStore`;
  - `ceph.py` — S3-клиент Ceph;
  - `service.py` — голос в запросе, перегенерация, old-object retention;
  - `store.py`/`db/audio.py` — метаданные без `audio_data`.
- PostgreSQL: миграция `0014_message_audio_ceph` (`voice_id`, `object_key`,
  `size_bytes`, `etag`, составной ключ).
- Ceph: сервис `ceph-rgw` в `docker/compose.yaml`, том `ceph-data`,
  настройки в `docker/.env.example`.
- Docker backend: зависимость `boto3`, сетевой доступ к `ceph-rgw:7480`;
  `ffmpeg` остаётся для MP3.
- Документация и тесты.

## Команды

- Запуск: `make run`
- Тесты: `make test`
- Интеграционные тесты: `make test-integration`
- Линтер: `make lint`

## Тестирование

- Модульные тесты `SpeechConfig`: голос по умолчанию, `voice` в запросе,
  неизвестный голос.
- Модульные тесты `AudioObjectStore`: put/get/delete, Ceph fake, ошибки.
- Тесты `NarratorSpeechService`: перегенерация при каждом `POST`, сохранение
  старого объекта при ошибке, замена после успеха, `audio_voices`.
- Интеграционные тесты API: `voice` в теле и query, `422` для неизвестного,
  `audio_voices`, старый объект доступен во время перегенерации.
- Интеграционные тесты с Compose Ceph: загрузка MP3, скачивание, удаление,
  сохранение после перезапуска контейнера.
- Node-тесты frontend: меню голосов, `localStorage`, отправка `voice`,
  переключение плеера, компактный плеер, скачивание, отсутствие надписи
  «Голос».
- Ручная проверка в браузере: меню, клавиатура, мобильная ширина, плеер,
  скачивание и повторное открытие истории.

## Границы

- Всегда: хранить выбор голоса только во frontend; проверять голос на
  backend; хранить MP3 в Ceph; метаданные — в PostgreSQL; оставлять старую
  запись до успешной замены; не логировать текст, аудио и credentials.
- Сначала спросить: полноценный Ceph-кластер вместо s3gw, серверный профиль
  голоса, публичный доступ к Ceph, хранение нескольких версий одной озвучки.
- Никогда: не хранить MP3 в `message_audio.audio_data` для новых записей; не
  делать Ceph bucket публичным; не отдавать audio без авторизации; не
  клонировать голоса персонажей.

## Критерии приёмки

- [ ] В Compose есть внутренний `ceph-rgw` с томом `ceph-data`, backend
  использует его S3 endpoint.
- [ ] Новые MP3 сохраняются в Ceph, а в PostgreSQL остаются только метаданные
  и `object_key`.
- [ ] `POST .../audio {"voice":"aidar"}` всегда запускает новую генерацию;
  старый MP3 доступен до успеха новой.
- [ ] `GET messages` возвращает `audio_voices`; frontend показывает плеер и
  «Скачать» для выбранного голоса.
- [ ] Выбор голоса отображается контролом без надписи «Голос», со стрелкой и
  аккуратным меню; сохраняется в `localStorage` и восстанавливается после
  перезагрузки.
- [ ] Плеер компактный, в стиле чата; кнопка скачивания аккуратная и работает
  на мобильной ширине.
- [ ] `make test`, `make test-integration` и `make lint` проходят.
- [ ] Документация обновлена.

## Открытые вопросы

- Подтвердить, что для Compose достаточно Ceph RGW-совместимого `s3gw`, а не
  полноценного Ceph-кластера.
- Подтвердить отображаемые названия голосов, особенно пары `kseniya`/`xenia`.
- Нужно ли показывать в истории, что сообщение озвучено и другими голосами,
  или только выбранным.
