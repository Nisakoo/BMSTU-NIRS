# Полное название истории, обрезка только по ширине

## Цель

Название истории — это первый запрос пользователя. Его показывают
заголовок чата и пункт в «Мои истории». Сейчас сервер обрезает его до 60
символов и ставит «…». Поэтому даже на широком экране заголовок обрывается
на полуслове или предлоге: «…перед сном про…». Так решено в
[user-dialog-history](../user-dialog-history/spec.md).

Пользователь выбрал вариант: название хранится полностью, а обрезает его
только ширина экрана. Полный текст виден при наведении.

## Требования

- REQ-001: Название диалога — первый запрос пользователя в одну строку:
  пробелы и переносы схлопываются, как сейчас. Оно хранится целиком до
  200 символов. Только если текст длиннее 200 символов, он обрезается до
  200 с «…». Название по-прежнему задаётся первым запросом и потом не
  меняется.
- REQ-002: Миграция `0005` пересчитывает названия уже сохранённых
  диалогов из их первого сообщения пользователя по правилу REQ-001.
  Downgrade ничего не меняет: прежнее обрезанное название восстановить
  нельзя, а полное название подходит и старой версии.
- REQ-003: Заголовок чата и пункты списка «Мои истории» показывают
  название в одну строку. Если оно не помещается по ширине, CSS обрезает
  его многоточием. Сейчас это уже так.
- REQ-004: Полное название видно в подсказке при наведении (атрибут
  `title`): у пунктов списка, как сейчас, и у заголовка чата — это новое.
  У новой истории без названия подсказка «Новая история».
- REQ-005: Адаптивность. На экранах ≤ 820px (планшеты и телефоны) наведения
  нет, поэтому заголовок чата может занимать до двух строк и только потом
  обрезается многоточием (`line-clamp: 2`). Пункты списка остаются в одну
  строку. На 1440, 1280, 1024, 820, 768, 390 и 360px:
  - нет горизонтальной прокрутки;
  - заголовок не наезжает на кнопку «Истории» и статус;
  - строка ввода и лента остаются на месте.
- REQ-006: API не меняется: поле `title` в `GET /api/v1/dialogs` и
  `GET /api/v1/dialogs/{id}/messages` просто бывает длиннее.

## Сценарии

### Длинный запрос

- Given пользователь отправил первый запрос «Расскажи короткую, спокойную и
  уютную историю перед сном про Бараша и Нюшу.»
- When ответ сохранён
- Then название — весь запрос. На широком экране заголовок показывает его
  целиком, на узком обрезает многоточием. При наведении виден полный
  текст.

### Старые истории

- Given история сохранена с названием, обрезанным до 60 символов
- When применяется `make migrate`
- Then название пересчитано из первого сообщения и стало полным

## Технологии и структура

- Backend:
  - `dialogs/models.py`: лимит 200;
  - миграция `0005_full_dialog_titles.py`.
- Frontend: `script.js` — атрибут `title` у заголовка чата; `styles.css` — две строки заголовка на ≤ 820px.
- Документация: `docs/dialogs.md`, `docs/database.md`, `AGENTS.md`.

## Команды

- Тесты: `make test`
- Миграции: `make migrate`
- Линтер: `make lint`

## Тестирование

- Модульный тест `dialog_title`:
  - 200 символов остаются как есть;
  - 201 символ превращается в 200 и «…»;
  - пробелы схлопываются.
- Интеграционный тест PostgreSQL:
  - диалог с обрезанным названием, записанный на `0004`, после upgrade
    получает полное название из первого сообщения;
  - диалог без сообщений остаётся без названия.
- Node-тест UI: у заголовка чата `title` — полное название сохранённой
  истории и «Новая история» у новой.
- Ручная проверка в `make run` с длинным названием на 1440, 1280, 1024,
  820, 768, 390 и 360px:
  - заголовок в одну строку с многоточием на компьютере, до двух строк на
    ≤ 820px;
  - `scrollWidth` равен ширине экрана;
  - заголовок не перекрывает соседние элементы;
  - скриншоты.

## Границы

- Всегда: схлопывать пробелы; хранить не больше 200 символов.
- Сначала спросить: генерацию названия моделью, переименование истории.
- Никогда: менять API и миграции `0001`–`0004`.

## Критерии приёмки

- [ ] Новые истории получают полное название до 200 символов.
- [ ] `make migrate` восстанавливает полные названия старых историй.
- [ ] Заголовок обрезается только по ширине, полный текст при наведении.
- [ ] На планшетах и телефонах заголовок до двух строк, раскладка не
  ломается ни на одной из проверенных ширин.
- [ ] `make test` и `make lint` проходят.
