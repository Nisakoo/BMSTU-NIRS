# Локальная озвучка сказок голосом рассказчика на Silero v5

## Цель

Дать пользователю возможность прослушать готовую сказку, не покидая чат. Озвучка выполняется локально в backend на CPU встроенным русским голосом Silero TTS v5.
В одной сказке используется один голос — голос рассказчика; роли персонажей и клонирование голосов в это изменение не входят. Изменение добавляет кнопку
«Озвучить» у завершённого ответа ассистента, фоновую локальную генерацию, хранение готового аудио, воспроизведение во frontend и скачивание готовой записи.
После успешной генерации кнопка «Озвучить» заменяется на «Скачать».

## Требования

### Backend
- REQ-001: Локальный провайдер синтеза использует Silero TTS v5 и работает на CPU. Во время выполнения запроса он не обращается к внешним TTS-сервисам и не скачивает модель из сети.
- REQ-002: Голос рассказчика берётся из фиксированного набора встроенных голосов Silero v5. Допустимый набор и значение по умолчанию задаются конфигурацией; неизвестное имя голоса останавливает запуск конфигурации до создания приложения.
- REQ-003: Модель Silero загружается один раз при старте приложения. Если модель отсутствует, повреждена или не может быть загружена, backend завершает запуск контролируемой ошибкой и не начинает обслуживать запросы с нерабочей озвучкой.
- REQ-004: Текст ответа нормализуется для синтеза: схлопываются лишние пробелы и переводы строк, нормализуются кавычки и тире, удаляются случайные Markdown-маркеры, если модель их всё же вернула. Смысл и порядок текста не меняются.
- REQ-005: Нормализованный текст разбивается на фрагменты не длиннее настроенного предела по границам предложений и абзацев. Между абзацами добавляется пауза. Ни один фрагмент не теряется и не дублируется.
- REQ-006: Синтез выполняется в отдельном потоке и не блокирует event loop FastAPI. Одновременно в процессе выполняется не более `SPEECH_MAX_CONCURRENCY` синтезов; по умолчанию — один. Остальные запросы ожидают в очереди.
- REQ-007: Для одного сообщения одновременно выполняется не более одной генерации. Повторный запрос во время генерации не создаёт вторую задачу и наблюдает тот же результат.
- REQ-008: Готовое аудио кэшируется. Повторный запрос для того же сообщения, того же текста и той же версии голоса возвращает сохранённое аудио без повторного синтеза.
- REQ-009: Кэш учитывает хэш исходного текста и версию голоса. Версия голоса включает идентификатор Silero-голоса, версию модели Silero v5, скорость речи и версию правил нормализации. При изменении любого из этих параметров аудио
  генерируется заново.
- REQ-010: Аудио и статус генерации хранятся в таблице `message_audio` с первичным ключом `message_id` и внешним ключом на `messages(id)` с `ON DELETE CASCADE`. Удаление диалога или сообщения удаляет связанное аудио.
- REQ-011: Статусы `message_audio` — `pending`, `ready` и `failed`. Строка `ready` содержит непустые `audio_data`, `mime_type` и `duration_ms`. Строка `failed` содержит безопасный `error_code` и не содержит аудио.
- REQ-012: Незавершённые генерации после рестарта не остаются вечно в `pending`: при старте приложения такие строки переводятся в `failed` с безопасным кодом прерывания, после чего повторный запрос может запустить генерацию заново.
- REQ-013: Фоновые задачи озвучки отслеживаются и отменяются при shutdown приложения. Отмена не оставляет новую строку `ready` и не логирует текст сказки.
- REQ-014: Ошибка Silero или кодирования аудио преобразуется в безопасную ошибку без текста сказки, аудиоданных, пути к модели и текста внешнего исключения. `asyncio.CancelledError` распространяется без преобразования.
- REQ-015: Результат сохраняется как MP3 (`audio/mpeg`), моно, с частотой дискретизации и битрейтом, достаточными для разборчивой русской речи. Конкретные параметры кодирования фиксируются в конфигурации или константах реализации. MP3
  пригоден и для встроенного воспроизведения, и для скачивания файла; перекодирование при скачивании не выполняется.
- REQ-016: Логи содержат стабильные события начала, завершения и ошибки синтеза с `message_id`, числом символов, длительностью, исходом и безопасным типом ошибки. Текст сказки, аудио, путь к модели и содержимое исключения в лог не
  передаются. ### HTTP API
- REQ-017: `POST /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio` запускает озвучку сохранённого ответа ассистента и не принимает тело запроса. При новой генерации или уже идущей генерации возвращается `202 Accepted` с JSON
  `{"status":"pending"}`. Если аудио уже готово и актуально, возвращается `200 OK` с JSON `{"status":"ready"}`.
- REQ-018: `GET /api/v1/dialogs/{dialog_id}/messages/{message_id}/audio` (и его вариант `?download=1`) возвращает: - `202 Accepted` и `{"status":"pending"}`, пока аудио генерируется; - `200 OK` и тело `audio/mpeg`, когда аудио готово; -
  `404 Not Found`, если сообщение не существует, принадлежит чужому диалогу, не является ответом ассистента или аудио ещё не запрашивалось; - `503 Service Unavailable` с безопасным JSON, если последняя генерация завершилась ошибкой или
  сервис озвучки недоступен.
- REQ-019: Обе ручки требуют действительный access-токен и проверяют владельца диалога. Для чужого диалога ответ такой же, как для несуществующего — `404`. Роль `admin` не даёт доступа к чужим диалогам.
- REQ-020: Озвучивать можно только сообщения с ролью `assistant`. Для пользовательского сообщения обе ручки отвечают `404`.
- REQ-021: Ответ с готовым аудио содержит `Content-Type: audio/mpeg`, корректный `Content-Length`, `ETag` по тексту и версии голоса и приватную политику кэширования. Без параметра `download` аудио отдаётся с `Content-Disposition: inline`; с
  `?download=1` — с `Content-Disposition: attachment; filename="smeshariki-<message_id>.mp3"`. Аудио не должно быть доступно без авторизации.
- REQ-022: Одновременные запросы к одной и той же озвучке не создают параллельных синтезов и не приводят к гонке при записи `message_audio`. ### Конфигурация и окружение
- REQ-023: Новый неизменяемый `SpeechConfig` принадлежит модулю озвучки. Корневой `Config` получает подконфиг `speech`; `load_config` читает его из process environment, а внутренние компоненты environment не читают.
- REQ-024: Поддерживаются как минимум настройки: - `SPEECH_ENABLED` — включает локальную озвучку, по умолчанию `true`; - `SPEECH_VOICE` — встроенный голос Silero, по умолчанию `baya`; - `SPEECH_SPEED` — скорость речи в допустимом диапазоне,
  по умолчанию `1.0`; - `SPEECH_MAX_CONCURRENCY` — целое положительное число, по умолчанию `1`; - `SPEECH_MAX_TEXT_CHARS` — максимальная длина озвучиваемого текста, по умолчанию `20000`; - `SPEECH_MODEL_PATH` — путь к локальному файлу
  Silero v5, по умолчанию `/models/silero/v5_ru.pt`. Невалидные значения останавливают загрузку конфигурации.
- REQ-025: `docker/.env.example` содержит безопасные значения новых переменных без секретов. `docker/compose.yaml` передаёт их backend.
- REQ-026: Используется официальная русская модель Silero v5 (`v5_ru`) из официального источника Silero Models. Модель и её файлы не коммитятся в публичный репозиторий. На этапе сборки скрипт в `docker/` скачивает зафиксированный файл по
  официальному URL, проверяет SHA-256 и кладёт его в образ или read-only volume; URL, версия, checksum и лицензия модели документируются. Для offline-сборки допускается заранее подготовленный `docker/models/silero/v5_ru.pt`. Во время работы
  приложения сеть для загрузки модели не используется. ### Frontend
- REQ-027: У каждого завершённого ответа ассистента — и в живой ленте после `message_end`, и в загруженной сохранённой истории — есть кнопка «Озвучить» с доступной подписью. Если для сохранённого ответа уже есть готовое актуальное аудио,
  кнопка сразу показывается как «Скачать».
- REQ-028: Нажатие кнопки запускает `POST`, затем опрашивает `GET` до получения аудио или безопасной ошибки. Во время ожидания кнопка показывает состояние «Готовим озвучку…» и не запускает повторную генерацию.
- REQ-029: После получения аудио в ленте появляется встроенный `<audio controls>` с готовым MP3, а кнопка «Озвучить» заменяется на «Скачать». Автовоспроизведение не используется: браузер может заблокировать его после асинхронной генерации.
- REQ-030: При переключении диалога, создании новой истории, выходе или повторной загрузке страницы текущее аудио останавливается, незавершённый polling прекращается, а состояние кнопки сбрасывается.
- REQ-031: Ошибки запуска, генерации и загрузки аудио показываются пользователю безопасным текстом; динамический текст вставляется только как текст, без `innerHTML`.
- REQ-032: Запросы озвучки используют существующую обработку сессии: при `401` выполняется один `refresh` и повтор, как у остальных операций чата.
- REQ-033: Кнопка озвучки не блокирует ввод, отправку сообщений и переключение истории. Озвучка одного сообщения не мешает озвучке другого, если backend принял оба запроса. ### Документация
- REQ-034: Добавляется тематическая страница `docs/audio.md` с описанием границ модуля, локального Silero-провайдера, API, хранения, кэша и ограничений CPU.
- REQ-035: Обновляются `docs/README.md`, `docs/dialogs.md`, `docs/database.md`, `docs/configuration.md`, `docker/README.md`, `frontend/README.md` и `AGENTS.md` в объёме нового компонента, контракта и настроек. ### Дополнительные контракты
- REQ-036: `GET /api/v1/dialogs/{dialog_id}/messages` для каждого сообщения возвращает `audio_available: bool`: `true` только для ответа ассистента с актуальной строкой `message_audio.status = ready`, иначе `false`. Поле не раскрывает
  текст, аудио или внутренние ошибки синтеза.
- REQ-037: Скачивание выполняется авторизованным запросом `GET .../audio?download=1` через существующий клиент с обработкой `401` и одним `refresh`. Frontend получает blob, создаёт object URL и инициирует скачивание с именем
  `smeshariki-<message_id>.mp3`, после чего освобождает URL. Скачивание не запускает повторный синтез.

Действующий контракт и архитектурные границы описаны в [каталоге](../../../docs/README.md).
