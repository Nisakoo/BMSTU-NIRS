# Проверка: бенчмарк точного поиска по канону

## Результат

Добавлена команда `knowledge-benchmark`: офлайн-оценка `lookup_knowledge` на
пакете знаний через `InMemoryKnowledgeStore`. Собран golden set из реального
канона. Заполнены пустые списки `characters` в лоре.

## Контрольный прогон канона

```text
uv run --project backend --locked --no-sync python -m smeshariki_ai.rag \
  knowledge-benchmark data/knowledge \
  --questions data/knowledge-golden/questions.yaml
```

```text
Вопросов: 145 (точных 119, опечаток 16, ловушек 10).
Accuracy: 0.986
Exact match rate: 1.000
Suggestion rate: 0.875
False positive rate: 0.000
```

Точные имена, алиасы и все 84 названия эпизодов находятся; 14 из 16 опечаток
дают подсказку; ни одно чужое имя не принято за канон. Промахи:
`typo_krosh` («Крш») и `typo_nyusha` («Нюш») — слишком короткие строки для
порога `pg_trgm 0.3`, подсказка не выдаётся.

## Данные

- `characters` заполнены по фактическим упоминаниям имён в тексте: 52 документа
  в рабочем корпусе и 52 в golden-копии; метрики лора не изменились, потому что
  поле не индексируется;
- golden set канона не коммитится: он лежит в игнорируемом `data/`.

## Ограничения

- Порог `pg_trgm` не настраивался: короткие опечатки (3–4 символа) остаются
  без подсказки — это кандидат в отдельное изменение;
- разметка канона точная (имя → id), в отличие от тематической разметки лора,
  поэтому метрики канона следует читать как абсолютные.
