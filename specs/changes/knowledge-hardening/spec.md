# Надёжность каталога и хранилища знаний

## Цель

Исправить найденные при ревью дефекты `knowledge-catalog` и
`knowledge-postgres-store` до того, как на них появятся данные: ложную ошибку
конфигурации при загрузке, нормализацию имён без учёта Unicode, отсутствие
версии формата у пакетов и снимков ревизий, слабую типизацию отчёта и
символьные ссылки в пакете. Заодно без изменения поведения убираются
архитектурные запахи: детали адаптеров в домене, параллельные реестры типов
сущностей и разнесённое по коду преобразование агрегатов в строки БД.

## Допущения

- Реальных данных в БД ещё нет, а миграция `0003` не влита в `main` и нигде,
  кроме временных тестовых БД, не применялась. Поэтому колонка версии формата
  добавляется в саму миграцию `0003`, без новой миграции.
- Версия формата фиксирует, в каком формате записаны пакет и снимок.
  Преобразование старых версий в новые — изменение, которое меняет формат;
  сейчас поддерживается только версия `1`.
- Изменение не трогает другие модули и общие файлы, кроме собственной
  документации RAG.

## Требования

### Ошибки загрузки

- REQ-001: Ошибка конфигурации backend сообщается кодом `configuration_error`
  только тогда, когда не удалось загрузить конфиг. Остальные ошибки
  валидации при загрузке не выдаются за ошибку конфигурации.
- REQ-002: Если данные в БД не проходят доменные модели при чтении, загрузка
  отменяется с кодом `stored_data_invalid`; БД не меняется, процесс не
  завершается трассировкой, сообщение не содержит данных из БД.

### Нормализация имён

- REQ-003: `normalize_name` сначала приводит строку к Unicode NFC, затем
  применяет `casefold`, схлопывает пробелы и заменяет `ё` на `е`. Имя с «ё»,
  записанной как «е» и комбинирующая диарезиса, нормализуется так же, как с
  составной «ё».

### Версия формата

- REQ-004: Корень пакета обязательно содержит `package.yaml` с полем
  `format_version`. Поддерживается версия `1`; отсутствие файла — ошибка
  `missing_manifest`, неподдерживаемая версия — `unsupported_format_version`,
  лишние поля — ошибки схемы. Заменяет в REQ-003 `knowledge-catalog` правило,
  что любой файл в корне пакета — ошибка.
- REQ-005: Каждая ревизия в `rag_revisions` хранит обязательный
  `format_version` снимка; порт возвращает его вместе с ревизией. Загрузка
  записывает текущую версию формата.
- REQ-006: Текущая версия формата — одна константа домена; `schema` выводит
  её вместе со схемами сущностей.

### Строгость и безопасность

- REQ-007: Итог загрузки в порте типизирован: счётчики по типам — модели
  `ChangeCounts`, а не произвольный словарь.
- REQ-008: Значения, которые `CHECK`-ограничения БД допускают для словарей
  (`kind`, `age_group`, типы отношений и взаимодействий, тип сущности и
  операция ревизии), в точности совпадают с реестрами домена.
- REQ-009: Символьная ссылка в пакете — ошибка `symlink_not_allowed`; её
  содержимое не читается.

### Рефакторинг без изменения поведения

- REQ-010: Домен не знает о файлах пакета: правила целостности возвращают
  нарушения с ссылкой на сущность и путём поля, а адрес файла, номер строки и
  адрес `db:<тип>/<id>` добавляет адаптер пакета или use case. Модель ошибки
  с файлом и строкой принадлежит адаптеру пакета.
- REQ-011: Сведения о непрошедших проверку файлах передаются правилам
  целостности отдельным параметром, а не полем `KnowledgeSet`.
- REQ-012: Типы сущностей описаны одним реестром домена (модель и поле
  набора); остальные отображения адаптеров выводятся из него. Тест проверяет,
  что каждый реестр адаптеров покрывает все типы.
- REQ-013: PostgreSQL-адаптер описывает каждый агрегат одним
  преобразователем с таблицами, сборкой строк из модели и модели из строк.
  Наблюдаемое поведение хранилища, число запросов и контрактный набор не
  меняются.

### Документация

- REQ-014: `docs/knowledge.md` описывает `package.yaml`, версию формата,
  нормализацию имён и новые коды ошибок; синтетические примеры проходят
  `check`.

## Сценарии

### Повреждённые данные в БД

- Given в БД есть строка, которая не проходит доменную модель
- When выполняется `load`
- Then отчёт содержит `stored_data_invalid`, а не `configuration_error`, код
  `1`

### Разложенная «ё»

- Given персонаж «Ёжик» и другой персонаж с алиасом «Ёжик», где «Ё» записана
  как «Е» и комбинирующая диарезиса
- When пакет проверяется
- Then возвращается `duplicate_name`

### Пакет без версии формата

- Given пакет без `package.yaml`
- When выполняется `check`
- Then возвращается `missing_manifest`

## Технологии и структура

Без новых зависимостей. Затрагиваются `rag/models.py`, `rag/package.py`,
`rag/ports.py`, `rag/memory.py`, `rag/postgres.py`, `rag/tables.py`,
`rag/services.py`, `rag/cli.py`, `rag/integrity.py`, миграция `0003`, тесты
RAG и `docs/knowledge.md`.

- Тесты: `make test`, `make lint`; PostgreSQL-тесты —
  `TEST_DATABASE_URL=… uv run --project backend --locked pytest backend/tests/integration/rag`.

## Границы

- Всегда: сохранять наблюдаемое поведение, кроме перечисленного; рефакторинг
  подтверждать существующими тестами, а не их переписыванием.
- Сначала спросить: поддержку нескольких версий формата; изменения других
  модулей.
- Никогда: менять миграции, применённые в `main`.

## Критерии приёмки

- [ ] Порча данных в БД и ошибка конфигурации различаются.
- [ ] Нормализация устойчива к разложенным символам.
- [ ] Пакеты и снимки ревизий несут версию формата.
- [ ] `CHECK`-ограничения и реестры домена совпадают, символьные ссылки
  отвергаются.
- [ ] Домен не импортирует адаптеры и не знает о файлах; типы сущностей
  описаны одним реестром; агрегаты преобразуются в строки и обратно в одном
  месте.
- [ ] `make lint`, `make test` и PostgreSQL-тесты RAG проходят.
