# Настоящая статистика диалогов в панели администратора

## Цель

В `/admin/` карточки «Диалоги» и «Сообщения», график «Активность диалогов» и колонка «Диалоги» в списке пользователей до сих пор показывают демо-данные из `frontend/src/admin/demo-data.js`: когда панель делалась,
диалоги не хранились. После [user-dialog-history](../user-dialog-history/spec.md) диалоги и сообщения лежат в PostgreSQL и принадлежат пользователям, поэтому
все эти показатели можно считать по-настоящему. Изменение убирает демо-данные из панели полностью.

## Определения

- **Диалог (история)** — диалог, в котором есть хотя бы одно сообщение. Пустые диалоги создаются при каждом открытии чата и не считаются.
- **Окно** — `[now − period дней, now]`, как у остальной статистики.
- Удалённые пользователем истории не учитываются: их больше нет в базе.

## Требования

### Backend

- REQ-001: `GET /api/v1/admin/stats` дополнительно возвращает:
  - `dialogs` — число историй, созданных в окне (`dialogs.created_at`);
  - `messages` — число сообщений пользователя и ассистента, созданных в окне;
  - `activity` — список равных по длине отрезков окна от старого к новому:
    `[{"start": "<UTC ISO>", "dialogs": n}]`, где `n` — истории, созданные в
    отрезке. Для 7 дней — 7 отрезков по 1 дню, для 30 — 10 по 3 дня, для 90 — 9 по 10 дней. Сумма `dialogs` по отрезкам равна `dialogs`.
- REQ-002: У каждого из `recent_users` появляется `dialogs` — число историй пользователя за всё время.
- REQ-003: Права, ошибки (`401`/`403`/`503`/`422`) и остальные поля ручки не меняются; данные считаются одним соединением, как сейчас. Тексты сообщений и названия историй не читаются и не возвращаются.

### Frontend

- REQ-004: Карточки «Диалоги» и «Сообщения» показывают `dialogs` и
  `messages` за период без метки «демо-данные».
- REQ-005: График «Активность диалогов» строится по `activity`: столбец на отрезок, подпись — дата начала отрезка («12.10»), значение — число
  историй; у пустого отрезка столбик не рисуется; без метки «демо-данные». Если за период историй нет, график показывает нулевые столбцы и подпись «Историй за период нет».
  Описание для скринридера (`#adminChartDescription`) перечисляет отрезки.
- REQ-006: Колонка «Диалоги» в списке пользователей показывает число их историй вместо «—».
- REQ-007: В панели не остаётся демо-данных: удаляются `demo-data.js`, его тесты, метки «демо-данные» и общая подсказка о демо-данных. Период отчёта, его подпись и кнопки работают как раньше.

## Границы

- Всегда: считать только истории с сообщениями; не читать тексты.
- Сначала спросить: другие показатели (длина историй, среднее число сообщений), учёт удалённых историй, другое разбиение графика.
- Никогда: не менять миграции; не хранить отдельные счётчики.
