# Чистый stdout у `make knowledge-load`

## Цель

Сделать stdout цели `make knowledge-load` пригодным для разбора программой.
ИИ-агент автора знаний запускает загрузку с `FORMAT=json` и разбирает отчёт,
но перед JSON в stdout попадает лог сборки образа: цель вызывает
`make migrate`, а та выполняет `docker compose run --build`. Docker Compose
без терминала пишет прогресс BuildKit в stdout, и отчёт перестаёт быть
валидным JSON. Сам `python -m smeshariki_ai.rag load` выводит чистый JSON —
ломается только обёртка в `Makefile`.

## Допущения

- Изменение затрагивает только собственные строки цели `knowledge-load` в
  общем `Makefile`. Цель `migrate` принадлежит другому модулю и не меняется:
  её вывод перенаправляется вызывающей стороной.
- Docker Compose пишет служебные сообщения о контейнерах (`Creating`,
  `Started`, `Healthy`) в stderr; это поведение проверяется, но не меняется.
- Вывод подготовительных шагов не скрывается, а переносится в stderr: человек
  видит его в терминале, а при сбое миграции — причину ошибки.
- Изменение также фиксирует проверки, которые не удалось выполнить в
  `knowledge-postgres-store` и `knowledge-hardening` из-за сбоя Docker:
  полный `make knowledge-load` и PostgreSQL-тесты на PostgreSQL 17.

## Требования

- REQ-001: stdout `make knowledge-load DIR=<path>` содержит только вывод
  команды `load`. Вывод подготовительных шагов — сборки образа, миграций и
  сообщений Compose — идёт в stderr.
- REQ-002: С `FORMAT=json` stdout цели целиком является одним валидным
  JSON-документом — как при первой сборке образа, так и при сборке из кэша,
  при успешной и при отменённой загрузке.
- REQ-003: Поведение цели в остальном не меняется: при ошибке миграции
  загрузка не выполняется и цель завершается с ненулевым кодом, текстовый
  отчёт и подсказки без `DIR` и с несуществующим каталогом прежние.
- REQ-004: `docs/rag.md` сообщает, что stdout цели содержит только отчёт
  `load`, а вывод подготовительных шагов идёт в stderr.

## Сценарии

### Агент загружает пакет

- Given валидный пакет, локальный `docker/.env` и работающий Docker
- When агент выполняет `make knowledge-load DIR=<path> FORMAT=json` и
  перенаправляет stdout в файл
- Then файл содержит один JSON-документ с `"loaded": true`, а лог сборки и
  миграций виден в stderr

### Загрузка отменена

- Given пакет, который нарушает правила целостности вместе с данными БД
- When агент выполняет ту же команду
- Then stdout — один JSON-документ с `"loaded": false` и списком ошибок,
  код возврата ненулевой

### Миграция не прошла

- Given окружение, при котором сервис `migrate` завершается ошибкой
- When пользователь выполняет `make knowledge-load DIR=<path>`
- Then команда `load` не запускается, причина ошибки видна в stderr, stdout
  пуст, код возврата ненулевой

## Технологии и структура

- В цели `knowledge-load` вызов `$(MAKE) --no-print-directory migrate`
  перенаправляет свой stdout в stderr (`>&2`).
- Строка таблицы команд в `docs/rag.md` дополняется контрактом stdout.
- Новых файлов кода, зависимостей и тестов нет.

## Команды

- Загрузка: `make knowledge-load DIR=<path> [FORMAT=json]`
- Проверка: `make lint`, `make test`

## Тестирование

Изменение касается только `Makefile`, поэтому автоматические тесты не
добавляются: правила проекта запрещают тесты конфигурации репозитория, а
JSON-вывод самого `load` уже покрыт `test_cli.py`. Требования проверяются
ручным запуском цели в изолированном Compose-проекте (`COMPOSE_PROJECT_NAME`,
временный env-файл вне репозитория) с синтетическим пакетом из примеров
`docs/knowledge.md`:

| Требования | Проверка |
| --- | --- |
| REQ-001, REQ-002 | stdout в файл, разбор `json.load`: сборка без кэша, из кэша, отменённая загрузка |
| REQ-003 | Ошибка миграции: stdout пуст, код ненулевой; текстовый отчёт; подсказки без `DIR` и с несуществующим каталогом |
| REQ-004 | Ревью `docs/rag.md` и diff `Makefile` |

`make test` запускается с `TEST_DATABASE_URL` на PostgreSQL 17 и
`TEST_REDIS_URL`, чтобы закрыть ограничение проверки прошлых изменений.

## Границы

- Всегда: менять только собственные строки цели `knowledge-load`; сохранять
  вывод подготовительных шагов в stderr.
- Сначала спросить: изменение цели `migrate` или других чужих целей; подавление
  вывода сборки (`--quiet`, `--progress`).
- Никогда: коммитить env-файл проверки или данные; удалять Docker-ресурсы,
  не созданные проверкой.

## Критерии приёмки

- [ ] `make knowledge-load DIR=<path> FORMAT=json > out.json` даёт валидный
      JSON при сборке без кэша и из кэша.
- [ ] Отменённая загрузка с `FORMAT=json` даёт валидный JSON и ненулевой код.
- [ ] При ошибке миграции stdout пуст, код ненулевой, причина в stderr.
- [ ] Текстовый отчёт и подсказки цели не изменились.
- [ ] `docs/rag.md` описывает контракт stdout; diff `Makefile` затрагивает
      только цель `knowledge-load`.
- [ ] `make lint` и `make test` проходят; полный набор с PostgreSQL 17 и Redis
      проходит без пропусков.
