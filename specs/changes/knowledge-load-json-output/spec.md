# Чистый stdout у `make knowledge-load`

## Цель

Сделать stdout цели `make knowledge-load` пригодным для разбора программой. ИИ-агент автора знаний запускает загрузку с `FORMAT=json` и разбирает отчёт, но перед JSON в stdout попадает лог сборки образа: цель вызывает
`make migrate`, а та выполняет `docker compose run --build`. Docker Compose
без терминала пишет прогресс BuildKit в stdout, и отчёт перестаёт быть валидным JSON. Сам `python -m smeshariki_ai.rag load` выводит чистый JSON — ломается только обёртка в `Makefile`.

## Допущения

- Изменение затрагивает только собственные строки цели `knowledge-load` в общем `Makefile`. Цель `migrate` принадлежит другому модулю и не меняется: её вывод перенаправляется вызывающей стороной.
- Docker Compose пишет служебные сообщения о контейнерах (`Creating`,
  `Started`, `Healthy`) в stderr; это поведение проверяется, но не меняется.
- Вывод подготовительных шагов не скрывается, а переносится в stderr: человек видит его в терминале, а при сбое миграции — причину ошибки.
- Изменение также фиксирует проверки, которые не удалось выполнить в
  `knowledge-postgres-store` и `knowledge-hardening` из-за сбоя Docker:
  полный `make knowledge-load` и PostgreSQL-тесты на PostgreSQL 17.

## Требования

- REQ-001: stdout `make knowledge-load DIR=<path>` содержит только вывод команды `load`. Вывод подготовительных шагов — сборки образа, миграций и сообщений Compose — идёт в stderr.
- REQ-002: С `FORMAT=json` stdout цели целиком является одним валидным JSON-документом — как при первой сборке образа, так и при сборке из кэша, при успешной и при отменённой загрузке.
- REQ-003: Поведение цели в остальном не меняется: при ошибке миграции загрузка не выполняется и цель завершается с ненулевым кодом, текстовый отчёт и подсказки без `DIR` и с несуществующим каталогом прежние.
- REQ-004: `docs/rag.md` сообщает, что stdout цели содержит только отчёт
  `load`, а вывод подготовительных шагов идёт в stderr.

## Границы

- Всегда: менять только собственные строки цели `knowledge-load`; сохранять вывод подготовительных шагов в stderr.
- Сначала спросить: изменение цели `migrate` или других чужих целей; подавление вывода сборки (`--quiet`, `--progress`).
- Никогда: коммитить env-файл проверки или данные; удалять Docker-ресурсы, не созданные проверкой.
