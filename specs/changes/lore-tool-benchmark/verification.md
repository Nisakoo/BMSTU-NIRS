# Проверка: бенчмарк лора через путь search_lore

Исторический оригинал: `git show 5af56b5:specs/changes/lore-tool-benchmark/verification.md`.

## Результат

- Реализован режим `--context` у `lore-benchmark`: те же вопросы прогоняются через точную продакшн-логику выбора пассажей `search_lore` — общую с инструментом функцию `LoreContextBuilder.select`. Прежние метрики и вывод без флага не изменились.
- `make test`: 1045 passed, 140 skipped (интеграционные корректно ждут `TEST_DATABASE_URL`; их запускает `make test-integration`). `make lint` чист.
- Golden set (84 документа, 20 обычных + 10 ловушек), `k=5`, без `--context` — прежние контрольные значения:
- `Trap Passage Rate = 1.000` на обоих наборах: инструмент сам не отказывает ловушкам; корректный отказ остаётся ответственностью LLM. Бенчмарк это фиксирует, а не имитирует.
- `LiteLLMAnswerer` по-прежнему получает сырые хиты (граница спеки); выравнивание его контекста с путём инструмента — отдельное изменение.
- Контекстные метрики измеряют выборку пассажей, а не генерацию живой LLM; для оценки модели запускать без `--answers`.
- Прогон без `--context` побайтово совпадает с прежним выводом (проверено на golden set).
