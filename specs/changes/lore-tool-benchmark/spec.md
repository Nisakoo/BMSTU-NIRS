# Бенчмарк лора через путь search_lore

## Цель

Offline-бенчмарк лора сегодня измеряет сырой BM25: первые `k` чанков без фильтрации. Агент при этом получает другой результат — контекст после
`LoreContextBuilder` (top-10 хитов, не более 3 пассажей, один на документ,
абсолютный `min_score`, отказ от запросов из одних имён). Добавляем режим
`--context`: те же вопросы прогоняются через точную продакшн-логику выбора
пассажей, и отчёт получает контекстные метрики, включая честное поведение ловушек. Сейчас `Correct Rejection Rate` в offline-режиме обеспечен
заготовленными ответами, а инструмент в продакшне отдаёт фрагменты всем ловушкам golden set — это расхождение бенчмарк не показывает.

Пользователь бенчмарка — автор контента и разработчик RAG: по контекстным метрикам видно, что реально видит агент, а не что находит индекс.

## Требования

- REQ-001: выборка пассажей выделяется из `LoreContextBuilder` в отдельный метод
  `select(result, query_terms)`, возвращающий выбранные хиты (с `document_id`)
  и их финальные тексты; `build` формирует `LoreContext` из результата
  `select`. Состав пассажей и обрезка текстов для агента не меняются:
  существующие тесты `test_context.py` проходят без правок.
- REQ-002: `BenchmarkRunner` принимает необязательный именованный аргумент
  `context: LoreContextBuilder | None = None`; без него поведение и метрики
  прежние. При заданном билдере вопрос ищется один раз с
  `top_k = max(k, retrieval_k)`: `Recall@k` и `MRR@k` считаются по первым `k`
  хитам как раньше, а выборка контекста — из первых `retrieval_k` хитов, как в
  `SearchLoreTool`.
- REQ-003: в `BenchmarkReport` добавляются метрики, равные `None` без
  `--context`: `context_recall` — средняя по обычным вопросам доля релевантных
  документов, дошедших до контекста; `context_any_relevant` — доля обычных вопросов хотя бы с одним релевантным пассажем; `context_found_rate` — доля
  обычных вопросов со статусом `found`; `trap_passage_rate` — доля ловушек, которым инструмент отдал пассажи.
- REQ-004: результат вопроса дополняется полями `context_status` (`found`/`empty`), `context_documents` (id документов выбранных пассажей по порядку) и `context_relevant` (число релевантных среди них; для ловушек
  `None`). Без `--context` поля принимают значения по умолчанию.
- REQ-005: CLI `lore-benchmark` получает флаг `--context` (по умолчанию выключен). Текстовый вывод печатает новые метрики только при `--context`;
  JSON всегда содержит поля (значения `None` без флага). Контрольные значения существующих метрик не меняются: Recall@5 golden set остаётся `0.450`, MRR@5 — `0.637`.
- REQ-006: `make lore-benchmark` принимает `CONTEXT=1` и передаёт `--context`.
- REQ-007: правило «имена без содержания» и абсолютный `min_score` применяются к бенчмарку той же функцией `select`, что и в продакшне; дублирование логики выбора пассажей запрещено.
- REQ-008: документация обновляется в том же изменении: раздел Benchmark в
  `docs/lore.md`, строка о бенчмарке в `docs/rag.md` и пункт каталога в
  `AGENTS.md`; SDD-артефакты — в `specs/changes/lore-tool-benchmark/`.

## Границы

- Всегда: один путь выборки пассажей (`select`) для инструмента и бенчмарка; прежние метрики и их зафиксированные контрольные значения не меняются.
- Сначала спросить: изменение `LiteLLMAnswerer` (пока он получает сырые хиты, как раньше); вынос стоп-слов и подбор `min_score`.
- Никогда: не менять формулировки вопросов golden set, не подгонять их под выдачу, не коммитить содержимое `data/`.
