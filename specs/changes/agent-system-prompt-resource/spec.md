# Системный промпт агента как версионируемый ресурс

## Цель

Хранить production-системный промпт агента рядом с его backend-кодом в Markdown-файле под контролем Git, чтобы фактическое поведение агента было ревьюируемым и воспроизводимым и не зависело от deployment environment.

## Требования

- REQ-001: Production-системный промпт хранится в Markdown-файле внутри импортируемого пакета `smeshariki_ai.agent` и включается в Python-дистрибутив.
- REQ-002: Загрузчик backend читает системный промпт как package resource, не зависит от текущей рабочей директории и передаёт готовый текст в
  `AgentConfig`.
- REQ-003: `Agent` не читает файл промпта или environment и продолжает получать неизменяемый `AgentConfig` через конструктор.
- REQ-004: Переменная `AGENT_SYSTEM_PROMPT` удаляется из поддерживаемого environment-контракта, Docker Compose и шаблона локального `.env`; её наличие во входном environment не изменяет системный промпт.
- REQ-005: Пустой или состоящий только из пробельных символов resource не может стать системным промптом: конфигурация завершается контролируемой ошибкой до создания приложения.
- REQ-006: Остальная environment-конфигурация, включая
  `AGENT_MAX_ITERATIONS` и параметры LLM, сохраняет текущее поведение.
- REQ-007: Архитектурная документация описывает новый источник промпта, ответственность загрузчика и обновлённый environment-контракт.

## Границы

- Всегда: хранить production-промпт в Git и передавать его агенту через
  `AgentConfig`.
- Сначала спросить: добавление нескольких профилей промпта, шаблонизации, runtime reload или внешнего хранилища промптов.
- Никогда: читать resource внутри `Agent`, восстанавливать env override или журналировать содержимое системного промпта.
