# Системный промпт агента как версионируемый ресурс

## Цель

Хранить production-системный промпт агента рядом с его backend-кодом в
Markdown-файле под контролем Git, чтобы фактическое поведение агента было
ревьюируемым и воспроизводимым и не зависело от deployment environment.

## Требования

- REQ-001: Production-системный промпт хранится в Markdown-файле внутри
  импортируемого пакета `smeshariki_ai.agent` и включается в Python-дистрибутив.
- REQ-002: Загрузчик backend читает системный промпт как package resource, не
  зависит от текущей рабочей директории и передаёт готовый текст в
  `AgentConfig`.
- REQ-003: `Agent` не читает файл промпта или environment и продолжает получать
  неизменяемый `AgentConfig` через конструктор.
- REQ-004: Переменная `AGENT_SYSTEM_PROMPT` удаляется из поддерживаемого
  environment-контракта, Docker Compose и шаблона локального `.env`; её наличие
  во входном environment не изменяет системный промпт.
- REQ-005: Пустой или состоящий только из пробельных символов resource не может
  стать системным промптом: конфигурация завершается контролируемой ошибкой до
  создания приложения.
- REQ-006: Остальная environment-конфигурация, включая
  `AGENT_MAX_ITERATIONS` и параметры LLM, сохраняет текущее поведение.
- REQ-007: Архитектурная документация описывает новый источник промпта,
  ответственность загрузчика и обновлённый environment-контракт.

## Сценарии

### Загрузка production-промпта

- Given backend запускается из произвольной рабочей директории
- When `load_config` собирает корневую конфигурацию
- Then системный промпт загружается из Markdown-resource пакета и передаётся в
  `Config.agent.system_prompt`

### Попытка переопределения через environment

- Given во входном environment присутствует `AGENT_SYSTEM_PROMPT`
- When `load_config` собирает конфигурацию
- Then значение переменной не заменяет версионируемый системный промпт

### Некорректный resource

- Given Markdown-resource системного промпта пуст или содержит только пробелы
- When загрузчик пытается прочитать промпт
- Then загрузка конфигурации завершается контролируемой ошибкой и приложение не
  создаётся

## Технологии и структура

- Добавить `agent/prompts/system.md` и небольшой Python API загрузки внутри
  `smeshariki_ai.agent`.
- Для чтения использовать стандартный `importlib.resources`, чтобы не
  вычислять путь относительно CWD или структуры исходного checkout.
- Сохранить `AgentConfig.system_prompt: str` и существующий dependency
  injection в runtime.
- Удалить `AGENT_SYSTEM_PROMPT` из `docker/compose.yaml`,
  `docker/.env.example` и документации конфигурации.

## Команды

- Запуск: `make run`
- Тесты: `make test`

## Тестирование

- Модульные тесты проверяют загрузку непустого package resource и независимость
  результата от текущей рабочей директории.
- Модульные тесты конфигурации проверяют, что `load_config` использует
  версионируемый промпт, не применяет `AGENT_SYSTEM_PROMPT` и сохраняет
  поведение остальных переменных.
- Модульный тест проверяет контролируемую ошибку для пустого текста resource на
  границе загрузчика промпта.
- Состав wheel и согласованность документации проверяются на этапе verify без
  добавления искусственных продуктовых тестов на наличие файлов.

## Границы

- Всегда: хранить production-промпт в Git и передавать его агенту через
  `AgentConfig`.
- Сначала спросить: добавление нескольких профилей промпта, шаблонизации,
  runtime reload или внешнего хранилища промптов.
- Никогда: читать resource внутри `Agent`, восстанавливать env override или
  журналировать содержимое системного промпта.

## Критерии приёмки

- [ ] Production-промпт загружается из `agent/prompts/system.md` независимо от
  рабочей директории.
- [ ] Собранный Python wheel содержит Markdown-resource системного промпта.
- [ ] `AGENT_SYSTEM_PROMPT` отсутствует в поддерживаемом Docker/environment
  контракте и не влияет на `load_config`.
- [ ] Пустой resource отклоняется до создания приложения.
- [ ] `Agent` по-прежнему получает готовый immutable `AgentConfig` и не читает
  внешние источники.
- [ ] Архитектурная документация соответствует реализации.
- [ ] `make lint` проходит успешно.
- [ ] `make test` проходит успешно.
