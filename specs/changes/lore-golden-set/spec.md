# Golden set лора

## Цель

Получить честную оценку BM25 на полном корпусе без подгонки вопросов под
выдачу. Отделить её от синтетического и «реального, но подобранного» наборов.

## Требования

- REQ-001: набор лежит в игнорируемом `data/lore-golden/` и содержит полный
  корпус 84 документов.
- REQ-002: 20 обычных вопросов (не менее трёх релевантных документов) и 10
  ловушек.
- REQ-003: вопросы фиксируются до прогона, формулировки не подгоняются.
- REQ-004: `lore-benchmark` запускается один раз и фиксирует `Recall@5`,
  `MRR@5`, `Accuracy`, `Correct Rejection Rate`.
- REQ-005: `answers.json` служит только офлайн-проверке правил, а не оценке
  живой LLM.
- REQ-006: данные не коммитятся.

## Сценарии

- Given golden set, When выполняется benchmark, Then метрики записываются в
  verification без изменения вопросов.
- Given вопрос-ловушка, When ответ содержит маркер отказа, Then он засчитан.

## Технологии и структура

`data/lore-golden/`, существующий `rag/lore/benchmark.py`, документация.

## Команды

- `uv run --project backend --locked --no-sync python -m smeshariki_ai.rag lore-benchmark data/lore-golden/lore --questions data/lore-golden/questions.yaml --answers data/lore-golden/answers.json`

## Тестирование

Прогон benchmark и запись метрик; ревью, что вопросы не менялись после
первого прогона.

## Границы

- Всегда: полный корпус и фиксированные вопросы.
- Сначала спросить: изменение вопросов после прогона.
- Никогда: не коммитить golden set и не подгонять формулировки.

## Критерии приёмки

- [x] 30 вопросов, полный корпус.
- [x] Метрики зафиксированы: `Recall@5 0.450`, `MRR@5 0.637`.
- [x] Набор не коммитится.
