# Реальная статистика пользователей в панели администратора

## Цель

Панель `/admin/` сейчас целиком построена на локальных demo-данных и помечена
как «не подключённая к backend». Пользователи и их входы уже хранятся в
PostgreSQL, поэтому показатели аудитории можно брать из базы. Изменение
добавляет защищённую ролью `admin` backend-ручку статистики пользователей,
выводит её данные в панели и оставляет демонстрационными только показатели,
связанные с ответами агента (диалоги, сообщения, активность, качество): для
них пока нет постоянного хранения. Метки «демо» переносятся с панели целиком
на эти блоки.

## Требования

### Backend

- REQ-001: `GET /api/v1/admin/stats?period=<7|30|90>` возвращает `200` и JSON:
  `{"period":"30","users_total":<int>,"active_users":<int>,"new_users":<int>,
  "recent_users":[{"id":"<uuid>","login":"<login>","role":"user"|"admin",
  "registered_at":"<ISO-8601 UTC>","last_active_at":"<ISO-8601 UTC>"|null,
  "status":"new"|"active"|"inactive"}]}`.
- REQ-002: Показатели считаются на момент запроса для окна
  `[now − period дней, now]`:
  - `users_total` — все пользователи в базе;
  - `new_users` — зарегистрированные в окне (`users.created_at`);
  - `active_users` — различные пользователи, у которых в окне создана
    refresh-сессия (вход или продление сессии);
  - `recent_users` — не более 5 пользователей, упорядоченных по
    `last_active_at` (время последней созданной refresh-сессии, при её
    отсутствии — `registered_at`) по убыванию;
  - `status` — `new`, если пользователь зарегистрирован в окне; иначе
    `active`, если была активность в окне; иначе `inactive`.
- REQ-003: Без действительного access-токена ручка отвечает `401`
  `{"error":"unauthorized"}`, пользователю с ролью `user` — `403`
  `{"error":"forbidden"}`, при недоступности PostgreSQL или Redis — `503`
  `{"error":"unavailable"}`. Проверка выполняется до валидации `period`;
  администратору с неверным `period` ручка отвечает `422`.
- REQ-004: Ответ не содержит хешей паролей, токенов и данных refresh-сессий;
  журнал не содержит логинов из ответа.
- REQ-005: Подсчёт выполняется в PostgreSQL через адаптер в
  `smeshariki_ai.db`; HTTP-слой и сервис статистики не зависят от SQLAlchemy.

### Frontend

- REQ-006: После проверки роли `admin` панель запрашивает статистику для
  выбранного периода (по умолчанию 30 дней) и при переключении периода. Пока
  запрос выполняется, кнопки периода заблокированы.
- REQ-007: Карточки «Всего пользователей» и «Активные пользователи» и список
  «Последние пользователи» показывают данные backend. Рядом с периодом
  выводится число новых пользователей за период вместо вымышленного сравнения.
  В списке отображаются логин, роль, время последней активности
  («сегодня, 12:48», «вчера, 21:17» или дата) и статус. Колонка «Диалоги»
  показывает «—», так как диалоги пока не связаны с пользователями.
- REQ-008: Карточки «Диалоги» и «Сообщения», панели «Активность диалогов» и
  «Качество ответов» продолжают показывать demo-данные и имеют заметную метку
  «демо-данные» с пояснением, что статистика агента пока не сохраняется.
- REQ-009: Общие метки «Demo mode — Макет не подключён к backend»,
  «Демонстрационные данные» в шапке и «Локальная демонстрационная выборка» у
  списка пользователей удаляются.
- REQ-010: Ответ `401` переводит на `/login/`, `403` — в чат `/`; сетевая
  ошибка, `503` или некорректный ответ показывают «Не удалось загрузить
  статистику. Попробуйте обновить страницу» без устаревших или вымышленных
  данных пользователей.
- REQ-011: Логины и другие данные backend выводятся только через
  `textContent`.

### Документация

- REQ-012: `docs/auth.md` (или новая страница `docs/admin.md`),
  `docs/README.md`, `frontend/README.md` и `AGENTS.md` описывают ручку
  статистики, её защиту и то, какие блоки панели остаются
  демонстрационными.

## Сценарии

### Администратор открывает панель

- Given в базе 3 пользователя, один вошёл сегодня, один зарегистрирован
  неделю назад и не входил, администратор вошёл
- When администратор открывает `/admin/`
- Then карточка «Всего пользователей» показывает 3, «Активные» — число
  вошедших за 30 дней, список содержит логины без demo-имён
- And блоки диалогов, сообщений, активности и качества помечены «демо-данные»

### Переключение периода

- Given открыта панель за 30 дней
- When администратор выбирает «7 дней»
- Then выполняется `GET /api/v1/admin/stats?period=7`, показатели и статусы
  пересчитаны для 7 дней

### Обычный пользователь обращается к API

- Given вошёл пользователь с ролью `user`
- When он вызывает `GET /api/v1/admin/stats?period=30`
- Then ответ `403 {"error":"forbidden"}`

### База недоступна

- Given PostgreSQL недоступен
- When администратор открывает панель
- Then ручка отвечает `503`, панель показывает сообщение об ошибке без данных
  пользователей

## Технологии и структура

- Backend: новый пакет `smeshariki_ai.admin` с моделью статистики,
  контрактом хранилища и сервисом; `PostgresAdminStatsStore` в
  `smeshariki_ai.db`; HTTP-роутер `api/admin.py` с зависимостью проверки роли
  на основе `current_user`. Миграции не нужны: используются существующие
  таблицы `users` и `refresh_sessions`. Bootstrap передаёт хранилище в
  `create_app`.
- Frontend: клиент `admin-api.js` без зависимости от DOM, изменения в
  `admin/admin.js`, `admin/index.html`, `admin/admin.css`; `demo-data.js`
  остаётся только источником demo-показателей агента.

## Команды

- Запуск: `make run`
- Тесты: `make test`

## Тестирование

- Backend unit: сервис статистики и вычисление статусов на in-memory
  хранилище с фиксированными часами.
- Backend integration (HTTP): `401`, `403`, `503`, `422`, успешный ответ и
  порядок проверок на фиктивном хранилище.
- Backend integration (PostgreSQL, `TEST_DATABASE_URL`): подсчёт
  `users_total`, `new_users`, `active_users`, порядок и ограничение
  `recent_users` на реальной схеме. Для проверки поднимается временный
  PostgreSQL.
- Frontend Node-тесты: клиент статистики (коды ошибок, валидация ответа),
  отображение реальных данных, переключение периода, блокировка кнопок, метки
  «демо-данные» только на блоках агента, переходы при `401`/`403`, ошибка без
  данных, вывод логинов как текста.
- Ручная проверка в `make run`: панель администратора с реальными
  пользователями.

## Границы

- Всегда: проверка роли `admin` на backend; только агрегаты и публичные поля
  пользователей в ответе.
- Сначала спросить: сохранение диалогов и сообщений в базу, сбор метрик
  ответов агента, управление пользователями (блокировка, смена роли),
  пагинация полного списка пользователей.
- Никогда: возврат хешей паролей или токенов, кэширование статистики в
  browser storage.

## Критерии приёмки

- [ ] Администратор видит реальные «Всего пользователей», «Активные
  пользователи», число новых и список последних пользователей из базы.
- [ ] Обычный пользователь и гость не получают статистику (`403`/`401`).
- [ ] Метки «демо-данные» есть только у блоков диалогов, сообщений,
  активности и качества; общие demo-надписи панели удалены.
- [ ] Ошибка загрузки показывает сообщение без данных пользователей.
- [ ] Документация обновлена по REQ-012.
- [ ] `make test` и `make lint` проходят успешно.
