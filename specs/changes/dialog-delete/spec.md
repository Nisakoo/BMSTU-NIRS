# Удаление истории из «Мои истории»

## Цель

Пользователь не может убрать ненужную историю: она навсегда остаётся в списке «Мои истории». Изменение даёт возможность удалить свою историю. Удаление окончательное: история, её сообщения и оценки ответов стираются
из базы. Перед удалением в самом списке появляется подтверждение.

Изменение дополняет [user-dialog-history](../user-dialog-history/spec.md).

## Требования

### Backend и API

- REQ-001: `DELETE /api/v1/dialogs/{dialog_id}` удаляет диалог текущего пользователя и отвечает `204` без тела. В PostgreSQL удаляются строка
  `dialogs`, сообщения и оценки этих сообщений: срабатывает каскад, новая
  миграция не нужна.
- REQ-002: Ошибки — как у остальных ручек диалога:
  - чужой или несуществующий диалог — `404 {"detail":"Dialog not found."}`, чужой диалог при этом не удаляется;
  - некорректный UUID — `422`;
  - гость — `401` раньше `404` и `422`;
  - сбой PostgreSQL — `503`.
- REQ-003: После удаления история пропадает из `GET /api/v1/dialogs`. Запросы `GET .../messages`, `POST .../messages`, `GET .../events` и оценки по этому диалогу отвечают `404`.
- REQ-004: Если ответ по этому диалогу ещё генерируется, он не сохраняется. Подписчики событий получают `message_error`, сервис не падает.
- REQ-005: Удаление журналируется событием `dialog.deleted` с `dialog_id`, без названия и текстов.
- REQ-006: Оценки удалённых ответов больше не учитываются в блоке «Качество ответов» админки. Это ожидаемо и описано в документации.

### Frontend

- REQ-007: У каждой истории в «Мои истории» есть кнопка удаления со значком корзины. Доступное имя: «Удалить историю «<название>»», у истории без названия — «Удалить историю «Без названия»».
  - На компьютере корзина появляется при наведении на строку или фокусе внутри неё. У текущей истории корзина видна всегда.
  - На экранах ≤ 820px наведения нет, поэтому корзина видна всегда.
- REQ-008: Нажатие на корзину заменяет строку подтверждением «Удалить историю?» с двумя кнопками: «Удалить» (заметная, розово-красная) и «Отмена». Фокус переходит на «Отмена». «Отмена» или `Escape`
  возвращают строку, фокус — на её корзину. Одновременно открыто не больше одного подтверждения.
- REQ-009: «Удалить» отправляет `DELETE`. На время запроса кнопки подтверждения заблокированы. При `204` история убирается из списка:
  - если удалена открытая история, чат начинает новую, как «+ Новая история», с Крошем;
  - если удалена другая история, открытая остаётся на месте.
- REQ-010: Ошибки удаления:
  - при ошибке строка возвращается, а статус показывает «Не удалось удалить историю»;
  - `401` — один `refresh` и повтор, как у остальных операций;
  - `404` считается уже удалённой историей: строка просто убирается.
- REQ-011: Пока агент отвечает или переключается история, корзины и кнопки подтверждения заблокированы, как остальные пункты списка.

## Границы

- Всегда: проверять владельца на backend; подтверждение перед удалением.
- Сначала спросить:
  - корзину и восстановление;
  - удаление всех историй разом;
  - удаление отдельных сообщений.
- Никогда: удалять чужие данные; писать в журнал названия и тексты.
