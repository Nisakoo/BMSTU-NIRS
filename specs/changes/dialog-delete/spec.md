# Удаление истории из «Мои истории»

## Цель

Пользователь не может убрать ненужную историю: она навсегда остаётся в
списке «Мои истории». Изменение даёт возможность удалить свою историю.
Удаление окончательное: история, её сообщения и оценки ответов стираются
из базы. Перед удалением в самом списке появляется подтверждение.

Изменение дополняет [user-dialog-history](../user-dialog-history/spec.md).

## Требования

### Backend и API

- REQ-001: `DELETE /api/v1/dialogs/{dialog_id}` удаляет диалог текущего
  пользователя и отвечает `204` без тела. В PostgreSQL удаляются строка
  `dialogs`, сообщения и оценки этих сообщений: срабатывает каскад, новая
  миграция не нужна.
- REQ-002: Ошибки — как у остальных ручек диалога:
  - чужой или несуществующий диалог — `404 {"detail":"Dialog not found."}`,
    чужой диалог при этом не удаляется;
  - некорректный UUID — `422`;
  - гость — `401` раньше `404` и `422`;
  - сбой PostgreSQL — `503`.
- REQ-003: После удаления история пропадает из `GET /api/v1/dialogs`.
  Запросы `GET .../messages`, `POST .../messages`, `GET .../events` и
  оценки по этому диалогу отвечают `404`.
- REQ-004: Если ответ по этому диалогу ещё генерируется, он не
  сохраняется. Подписчики событий получают `message_error`, сервис не
  падает.
- REQ-005: Удаление журналируется событием `dialog.deleted` с `dialog_id`,
  без названия и текстов.
- REQ-006: Оценки удалённых ответов больше не учитываются в блоке «Качество
  ответов» админки. Это ожидаемо и описано в документации.

### Frontend

- REQ-007: У каждой истории в «Мои истории» есть кнопка удаления со
  значком корзины. Доступное имя: «Удалить историю «<название>»», у
  истории без названия — «Удалить историю «Без названия»».
  - На компьютере корзина появляется при наведении на строку или фокусе
    внутри неё. У текущей истории корзина видна всегда.
  - На экранах ≤ 820px наведения нет, поэтому корзина видна всегда.
- REQ-008: Нажатие на корзину заменяет строку подтверждением «Удалить
  историю?» с двумя кнопками: «Удалить» (заметная, розово-красная) и
  «Отмена». Фокус переходит на «Отмена». «Отмена» или `Escape`
  возвращают строку, фокус — на её корзину. Одновременно открыто не
  больше одного подтверждения.
- REQ-009: «Удалить» отправляет `DELETE`. На время запроса кнопки
  подтверждения заблокированы. При `204` история убирается из списка:
  - если удалена открытая история, чат начинает новую, как «+ Новая
    история», с Крошем;
  - если удалена другая история, открытая остаётся на месте.
- REQ-010: Ошибки удаления:
  - при ошибке строка возвращается, а статус показывает «Не удалось удалить
    историю»;
  - `401` — один `refresh` и повтор, как у остальных операций;
  - `404` считается уже удалённой историей: строка просто убирается.
- REQ-011: Пока агент отвечает или переключается история, корзины и кнопки
  подтверждения заблокированы, как остальные пункты списка.

## Сценарии

### Удаление другой истории

- Given открыта история «Ракета», в списке есть «Пирог»
- When пользователь нажимает корзину у «Пирога», затем «Удалить»
- Then «Пирог» исчез из списка, «Ракета» осталась открытой

### Удаление открытой истории

- Given открыта история «Ракета»
- When пользователь удаляет «Ракету»
- Then её нет в списке, чат показывает новую историю с Крошем

### Передумал

- Given показано «Удалить историю?»
- When пользователь нажимает «Отмена» или `Escape`
- Then строка вернулась, ничего не удалено

### Чужая история

- Given `dialog_id` принадлежит другому пользователю
- When отправлен `DELETE /api/v1/dialogs/{dialog_id}`
- Then `404`, диалог не удалён

  - маршрут в `api/app.py`.

  - `agent-api.js` — `deleteDialog`;

  `frontend/README.md`, `AGENTS.md`.

## Команды

- Тесты: `make test`
- Линтер: `make lint`

## Тестирование

- Модульные тесты:
  - хранилище в памяти: удаление, чужой и несуществующий диалог;
  - `AgentService`: удаление, журнал, генерация по удалённому диалогу даёт
    `message_error`.
- Интеграционные API-тесты:
  - `204`;
  - после удаления — `404` на истории, отправке, событиях и оценке; список
    без диалога;
  - чужой — `404`, и он не удалён;
  - `401` раньше `422`;
  - `422`;
  - `503`.
- Интеграционный тест PostgreSQL: каскад сообщений и оценок, чужой
  диалог.
- Node-тесты:
  - `AgentApi.deleteDialog`: `204`, `401`, `404`, `503`, сеть;
  - UI:
    - корзины и их имена;
    - подтверждение, «Отмена», `Escape`;
    - удаление открытой и другой истории;
    - ошибка с откатом;
    - `404` убирает строку;
    - `401` с повтором;
    - блокировка во время ответа.
- Ручная проверка в `make run` на 1280 и 390px:
  - корзина при наведении и всегда на телефоне;
  - подтверждение;
  - удаление открытой и другой истории;
  - нет горизонтальной прокрутки;
  - скриншоты.

## Границы

- Всегда: проверять владельца на backend; подтверждение перед удалением.
- Сначала спросить:
  - корзину и восстановление;
  - удаление всех историй разом;
  - удаление отдельных сообщений.
- Никогда: удалять чужие данные; писать в журнал названия и тексты.

## Критерии приёмки

- [ ] У историй есть корзина с подтверждением в списке; удаление стирает
  историю, её сообщения и оценки.
- [ ] Удаление открытой истории начинает новую; другой — не трогает
  открытую.
- [ ] Чужую историю удалить нельзя (`404`).
- [ ] `make test` и `make lint` проходят; на 390px нет горизонтальной
  прокрутки.
