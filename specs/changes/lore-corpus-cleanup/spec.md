# Чистка корпуса лора

## Цель

Убрать из лора системный технический мусор, который попадает в индекс и в
контекст агента. Обследование 84 документов показало: единственный
однозначный мусор — YouTube-ссылка первой строкой в **каждом** документе
(ровно 28 символов). Её токены (`https`, `youtu`, `be`, идентификатор видео)
индексируются BM25, а агент видит URL в начале первого пассажа. Остальные
найденные особенности — живая стилистика («Ха-ха-ха», «Бац-бац-бац»), время в
диалоге («в 9:00 утра»), обычная пунктуация (`...`) и единичные дубли строк —
автоматически не правятся: риск удалить авторский текст выше пользы.

Изменение касается **только чистки данных**. Стоп-слова, параметры BM25,
`min_score`, `k`, выборка пассажей, вопросы и ответы бенчмарков не меняются.

## Требования

- REQ-001: добавляется команда `python -m smeshariki_ai.rag lore-clean <path>
  [--apply] [--format text|json]`. По умолчанию выполняется dry-run: пакет не
  изменяется, печатается отчёт. `--apply` перезаписывает файлы документов.
  Коды возврата: `0` — успех или допустимый dry-run, `1` — ошибка пакета или
  записи, `2` — неверные аргументы.
- REQ-002: правило чистки удаляет из `text` строки, целиком состоящие из URL
  (`http://`, `https://`, `www.`), и отдельные URL в начале текста; пустые
  строки, оставшиеся после удаления, схлопываются. Затем нормализуются пробелы:
  обрезаются пробелы в конце строк, три и более переводов строки заменяются
  двумя, текст обрезается по краям.
- REQ-003: правило не удаляет и не изменяет реплики с повторами (`Ха-ха-ха`,
  `Бац-бац-бац`), время в тексте (`9:00`), многоточия и дубли строк. Это
  закреплено тестами как защита от расширения правила.
- REQ-004: чистка идемпотентна: повторный `--apply` на очищенном пакете не
  меняет файлы и сообщает об отсутствии изменений.
- REQ-005: поля `id`, `title`, `source`, `continuity`, `characters`, `tags` не
  меняются; меняется только `text`. После записи пакет проходит `lore-check`.
- REQ-006: `--apply` перед записью создаёт резервную копию исходного пакета в
  `data/.backups/<имя-пакета>-<UTC-время>/` (вне каталога пакета, чтобы
  `lore-check` не считал её лишним каталогом) и печатает путь копии; запись
  файлов атомарная (временный файл рядом, затем замена).
- REQ-007: команда добавляется в `Makefile` как `make lore-clean DIR=<path>
  [APPLY=1]`, работает без БД и без Docker (как `lore-check`).
- REQ-008: очищаются рабочий корпус `data/lore`, golden set
  `data/lore-golden/lore` и подобранный набор `data/lore-benchmark/lore`;
  вопросы, ответы и списки релевантных документов не изменяются.
- REQ-009: после чистки бенчмарки прогоняются заново, новые значения
  фиксируются в документации; расхождение с прежними контрольными числами
  объясняется в `verification.md`.
- REQ-010: `docs/lore.md` и `AGENTS.md` описывают команду и правило чистки;
  в `docs/lore.md` зафиксировано, что не чистится автоматически и почему.

## Сценарии

### Основной сценарий

- Given пакет лора с YouTube-ссылкой первой строкой;
- When выполняется `lore-clean <path> --apply`;
- Then ссылка удалена, текст начинается с первой реплики, остальные поля
  прежние, пакет валиден, создана резервная копия.

### Ошибка или граничный случай

- Given dry-run без `--apply`; When команда выполнена; Then ни один файл не
  изменён, отчёт показывает, сколько документов и строк было бы изменено.
- Given уже очищенный пакет; When повторный `--apply`; Then изменений нет,
  отчёт это подтверждает, резервная копия не создаётся.
- Given невалидный пакет; When команда выполнена; Then отчёт содержит ошибки
  пакета, файлы не изменяются, код возврата `1`.
- Given текст с репликой «Ха-ха-ха!» и временем «в 9:00»; When чистка; Then
  текст не изменяется.

## Технологии и структура

Python: новый модуль `rag/lore/cleanup.py` (правила и use case), проводка в
`rag/cli.py`, цель в `Makefile`. Тесты:
`backend/tests/unit/rag/lore/test_cleanup.py`,
`backend/tests/unit/rag/lore/test_lore_cli.py`. Документация: `docs/lore.md`,
`AGENTS.md`.

## Команды

- Прогон: `make lore-clean DIR=data/lore [APPLY=1]`
- Прямой запуск: `uv run --project backend --locked --no-sync python -m
  smeshariki_ai.rag lore-clean data/lore --apply`
- Тесты: `make test`; линт: `make lint`.

## Тестирование

- `test_cleanup.py`: удаление URL-строки и URL в начале текста; сохранение
  реплик с повторами, времени, многоточий и дублей строк; неизменность
  метаданных; идемпотентность; dry-run не пишет; резервная копия создаётся
  только при `--apply` и содержит исходный текст; невалидный пакет даёт отчёт
  с ошибками без записи.
- `test_lore_cli.py`: коды возврата и текстовый/JSON-вывод `lore-clean`,
  dry-run по умолчанию.

## Границы

- Всегда: только `text`; вопросы и ответы бенчмарков не трогать; резервная
  копия перед записью.
- Сначала спросить: любое расширение правил (удаление дублей строк, правка
  опечаток распознавания), стоп-слова, изменение параметров поиска.
- Никогда: не менять вопросы golden set, не подгонять метрики, не коммитить
  `data/`, не трогать `data/knowledge`.

## Критерии приёмки

- [ ] `make test` проходит успешно; `make lint` без замечаний.
- [ ] Все три пакета очищены, `lore-check` валиден, резервные копии созданы.
- [ ] Повторный `--apply` не вносит изменений (идемпотентность подтверждена).
- [ ] Бенчмарки перепрогнаны, новые значения зафиксированы в документации.
- [ ] Изменение не затронуло стоп-слова, параметры BM25 и выборку пассажей.
