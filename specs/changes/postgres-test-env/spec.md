# Тестовое окружение PostgreSQL и Redis одной командой

## Цель

Дать разработчикам одну команду для полного прогона backend-тестов на
настоящих PostgreSQL и Redis. Сейчас интеграционные тесты пропускаются без
`TEST_DATABASE_URL` и `TEST_REDIS_URL`, и каждое изменение, которому они
нужны, вручную поднимает временные контейнеры с собственными портами и
паролями (`backend-auth-jwt`, `admin-user-stats`, `auth-rate-limit`,
`knowledge-*`). Команда убирает ручную работу и делает полный прогон
воспроизводимым: одни версии образов, чистая БД, гарантированная уборка.

## Допущения

- Команда — `make test-integration`: она поднимает и PostgreSQL, и Redis,
  поэтому имя `test-postgres` из дорожной карты было бы неточным.
- `make test` не меняется: он остаётся быстрым и не требует Docker.
- pytest запускается на хосте через `uv`, как в `make test`; в контейнерах
  работают только PostgreSQL и Redis. Сборка образа backend не нужна.
- Версии образов совпадают с основным `docker/compose.yaml`:
  `postgres:17-alpine` и `redis:7-alpine`.
- Тесты сами сбрасывают схему `public` и применяют миграции; команда отдаёт
  им пустую БД и не выполняет миграции сама.
- Изменение не трогает тесты, код продукта и основной Compose-проект.
  Длительность прогона тестов других модулей с недоступной БД (см.
  «Открытые вопросы») не исправляется.

## Требования

### Запуск

- REQ-001: `make test-integration` поднимает временные PostgreSQL и Redis,
  дожидается их готовности по healthcheck и запускает полный backend-набор
  pytest с `TEST_DATABASE_URL` и `TEST_REDIS_URL`, указывающими на них.
- REQ-002: Окружение — отдельный Compose-проект `smeshariki-ai-test` из
  отдельного файла `docker/compose.test.yaml`. Он не использует `docker/.env`,
  тома и сеть основного проекта `smeshariki-ai` и может работать
  одновременно с `make run`.
- REQ-003: Порты PostgreSQL и Redis публикуются только на `127.0.0.1` и
  выбираются Docker динамически; команда узнаёт их у Compose. Занятые порты
  хоста не мешают запуску.
- REQ-004: Данные PostgreSQL хранятся в `tmpfs` ограниченного размера
  (512 МБ): каждый запуск начинается с пустой БД и не пишет данные на диск.
  Учётные данные — фиксированные тестовые значения, не секреты.
- REQ-005: `PYTEST_ARGS` передаёт аргументы pytest вместо полного набора,
  например `make test-integration PYTEST_ARGS=backend/tests/integration/rag`.

### Результат и уборка

- REQ-006: Скрипт `docker/test-integration.sh` возвращает код pytest, а
  `make test-integration` — `0` при успехе pytest и ненулевой код иначе (GNU
  Make сводит ненулевые коды к `2`, исходный код виден в его сообщении
  `Error <код>`). При ошибке запуска окружения код ненулевой, а pytest не
  запускается.
- REQ-007: Контейнеры, сеть и анонимные тома проекта `smeshariki-ai-test`
  удаляются после завершения — при успехе, падении тестов, ошибке запуска и
  прерывании `Ctrl+C`.
- REQ-008: Если остались ресурсы от прерванного ранее запуска, новый запуск
  удаляет их перед стартом и проходит.
- REQ-009: Без запущенного Docker команда завершается ненулевым кодом с
  понятным сообщением в stderr и не запускает pytest.

### Документация

- REQ-010: `make help`, `docker/README.md`, `docs/README.md` и раздел
  «Процесс разработки» `AGENTS.md` описывают команду (правка `AGENTS.md`
  согласована). Изменения общих файлов только аддитивные.

## Сценарии

### Полный прогон

- Given запущенный Docker и свободное от проекта `smeshariki-ai-test` окружение
- When разработчик выполняет `make test-integration`
- Then PostgreSQL- и Redis-тесты выполняются, а не пропускаются; после
  прогона контейнеров проекта нет; код равен коду pytest

### Подмножество тестов

- Given тот же Docker
- When разработчик выполняет
  `make test-integration PYTEST_ARGS="backend/tests/integration/rag -x"`
- Then выполняются только тесты RAG с флагом `-x`

### Тесты упали или прерваны

- Given тест, который падает, или прогон, прерванный `Ctrl+C`
- When команда завершается
- Then код ненулевой, ресурсы проекта удалены

### Docker не запущен

- Given недоступный Docker daemon
- When разработчик выполняет `make test-integration`
- Then команда сообщает, что Docker недоступен, и завершается ненулевым кодом

## Технологии и структура

- `docker/compose.test.yaml` — сервисы `postgres` и `redis` с healthcheck,
  `tmpfs` для данных PostgreSQL и динамическими портами на `127.0.0.1`.
- `docker/test-integration.sh` — POSIX `sh`-скрипт: проверка Docker, уборка
  остатков, `docker compose up --wait`, определение портов через
  `docker compose port`, запуск pytest, уборка в `trap` с сохранением кода.
- `Makefile` — цель `test-integration` и строка в `help`.
- `docker/README.md`, `docs/README.md`, `AGENTS.md` — описание команды.

## Команды

- Полный прогон с инфраструктурой: `make test-integration`
- Быстрые тесты: `make test`
- Проверка кода: `make lint`

## Тестирование

Изменение касается только инфраструктуры запуска тестов, поэтому
автоматические тесты не добавляются: правила проекта запрещают тесты
конфигурации репозитория. Требования проверяются ручными запусками:

| Требования | Проверка |
| --- | --- |
| REQ-001, REQ-006 | Полный прогон: нет пропусков PostgreSQL- и Redis-тестов, код `0`; число тестов совпадает с ручным прогоном (649) |
| REQ-002, REQ-003 | Прогон при занятом порте `5432` на хосте и одновременно с другим Compose-проектом; `docker compose ls` во время прогона |
| REQ-004 | Повторный прогон начинается с пустой БД; ревью `compose.test.yaml` |
| REQ-005 | `PYTEST_ARGS` с подмножеством и флагом |
| REQ-006, REQ-007 | Намеренно падающий подмножеством запуск (`-k` с несуществующим тестом даёт код `5`); прерывание `Ctrl+C`; после каждого — `docker ps -a` и `docker volume ls` без ресурсов проекта |
| REQ-008 | Запуск после оставленного вручную `docker compose up` проекта |
| REQ-009 | Запуск с недоступным `DOCKER_HOST` |
| REQ-010 | Ревью документации и diff общих файлов |

## Границы

- Всегда: удалять только ресурсы проекта `smeshariki-ai-test`; сохранять код
  возврата pytest; в общих файлах только добавлять.
- Сначала спросить: изменение `make test`, тестов или `docker/compose.yaml`;
  добавление сборки образа backend; правки `AGENTS.md` сверх строки о команде.
- Никогда: использовать `docker/.env` или реальные секреты; выполнять
  глобальные `docker system/volume/builder prune`; трогать ресурсы других
  Compose-проектов.

## Критерии приёмки

- [ ] `make test-integration` выполняет полный backend-набор без пропусков
      PostgreSQL- и Redis-тестов и завершается успешно только при успехе pytest.
- [ ] Команда работает при занятых портах хоста и рядом с другими
      Compose-проектами.
- [ ] После успеха, падения, ошибки запуска и `Ctrl+C` ресурсов проекта
      `smeshariki-ai-test` не остаётся.
- [ ] `PYTEST_ARGS` запускает подмножество.
- [ ] Без Docker — понятная ошибка и ненулевой код.
- [ ] `make help`, `docker/README.md`, `docs/README.md` и `AGENTS.md`
      описывают команду; diff общих файлов только аддитивный.
- [ ] `make lint` и `make test` проходят.

## Открытые вопросы

- Тесты других модулей проверяют недоступность через `127.0.0.1:1`. В WSL с
  `networkingMode=mirrored` подключение к закрытому порту не отклоняется, а
  ждёт таймаута, поэтому полный прогон длится около 5 минут вместо секунд.
  Исправление — в тестах владельцев модулей (`auth`, `admin`), вне этого
  изменения; сообщить им.
