# Ноутбучный базовый масштаб и упрощённый мобильный чат

## Цель

Вернуть композицию и размеры исходного frontend на 13-дюймовых ноутбуках,
использовать их как базовую точку для плавного увеличения на более широких
экранах и упростить мобильную версию до оформленного чата без декоративных
рисунков.

## Требования

- REQ-001: На viewport шириной от `821px` до `1440px` основные размеры должны
  соответствовать виду до изменения `frontend-responsive-layout`: контейнер не
  шире `1180px`, чат не шире `860px`, сцена имеет базовую высоту `650px`, а
  типографика, отступы и персонажи сохраняют прежний визуальный масштаб.
- REQ-002: На viewport шире `1440px` контейнер, чат, сцена, заголовок, отступы
  и персонажи должны плавно увеличиваться относительно ноутбучной базы, без
  резкого скачка на breakpoint и без чрезмерно длинных строк сообщений.
- REQ-003: На viewport до `820px` страница должна показывать сам чат в прежнем
  визуальном стиле, но скрывать hero-заголовок и декоративную сцену: луну,
  пейзаж, теги, персонажей Кроша и Копатыча и подсказку Кроша.
- REQ-004: В мобильном режиме обёртка сцены не должна оставлять фон, рамку,
  скругление, тень или зарезервированное место от скрытых рисунков; чат занимает
  доступную ширину с небольшими безопасными полями.
- REQ-005: На ширине от `320px` не должно быть горизонтальной прокрутки
  страницы; заголовок чата, сообщения, textarea, отправка и тематические кнопки
  не обрезаются и остаются доступными.
- REQ-006: На мобильных устройствах тематические кнопки могут прокручиваться
  горизонтально внутри своего ряда, не расширяя страницу.
- REQ-007: Существующее поведение подсказки Кроша сохраняется на desktop:
  автоматический фокус её не скрывает, первое пользовательское взаимодействие
  со строкой ввода или тематической кнопкой скрывает её до перезагрузки.
- REQ-008: Реализация остаётся на vanilla JavaScript и CSS; backend API,
  SSE-контракт и Docker topology не меняются.
- REQ-009: Документация frontend и архитектурный каталог должны описывать
  ноутбучную базу, увеличение на широких экранах и упрощённый мобильный режим.

## Сценарии

### Ноутбук 13 дюймов

- Given frontend открыт на viewport шириной `1280px`, `1366px` или `1440px`
- When страница отрисовывается
- Then контейнер, чат, сцена, заголовок и персонажи имеют исходный масштаб до
  изменения адаптивности
- And интерактивные области не перекрываются декорациями

### Широкий экран

- Given frontend открыт на viewport `1920x1080`
- When страница отрисовывается
- Then элементы заметно крупнее ноутбучной базы
- And увеличение начинается плавно после `1440px`
- And сообщения сохраняют читаемую максимальную ширину

### Мобильный экран

- Given frontend открыт на viewport `320x568` или `375x667`
- When страница отрисовывается
- Then виден оформленный чат без hero-заголовка, пейзажа, луны, тегов,
  персонажей и подсказки
- And вокруг чата нет пустого места, оставшегося от сцены
- And страница не имеет горизонтальной прокрутки

### Взаимодействие с подсказкой на desktop

- Given подсказка Кроша видна и textarea получила только программный фокус
- When пользователь взаимодействует со строкой ввода или тематической кнопкой
- Then подсказка скрывается, а существующая отправка и autosize продолжают
  работать

## Технологии и структура

- `frontend/src/styles.css`: базовые исходные размеры для ноутбучного
  диапазона, отдельное fluid-масштабирование после `1440px`; на mobile
  breakpoint `@media (max-width: 820px)` декоративные элементы скрываются
  через `display: none`, без JavaScript-проверки ширины viewport.
- `frontend/tests/ui.test.js`: сохранение тестов поведения подсказки; при
  необходимости — поведенческая проверка mobile DOM без тестирования текста
  CSS как служебной структуры.
- `frontend/README.md` и `docs/README.md`: актуализация описания адаптивности и
  ссылок на SDD-артефакты.

## Команды

- Запуск: `make run`
- Frontend dev server: `make frontend`
- Тесты: `make test`
- Frontend-тесты: `npm --prefix frontend test`
- Production-сборка: `npm --prefix frontend run build`

## Тестирование

| Требования | Способ проверки |
| --- | --- |
| REQ-001–REQ-006 | Рендеринг frontend в реальном браузере на `320x568`, `375x667`, `820x900`, `1280x800`, `1366x768`, `1440x900` и `1920x1080`; сравнение ноутбучной геометрии с исходными CSS-размерами, проверка отсутствия overflow и скрытия мобильных декораций |
| REQ-007 | Существующие Node DOM-тесты пользовательских событий подсказки и проверка desktop в браузере |
| REQ-008 | Ревью diff, успешные frontend-тесты и Vite production build |
| REQ-009 | Ревью документации без искусственных структурных тестов |

Новые тесты на этапе `specify` не реализуются.

## Границы

- Всегда: сохранять текущую тёмную стилистику и сетевое поведение чата;
  использовать исходный ноутбучный вид как базу; проверять мобильный,
  ноутбучный и широкий viewport.
- Сначала спросить: менять тексты, цветовую тему, структуру чата или breakpoint
  мобильного режима `820px`; скрывать на мобильном функциональные части чата.
- Никогда: масштабировать интерфейс через browser zoom; оставлять скрытые
  рисунки доступными для screen reader; допускать горизонтальную прокрутку всей
  страницы; менять backend ради визуальной адаптивности.

## Критерии приёмки

- [ ] На `1280px`, `1366px` и `1440px` восстановлены исходные максимальные
  размеры контейнера `1180px`, чата `860px` и базовой сцены `650px`.
- [ ] На `1920px` элементы плавно увеличены относительно ноутбучной базы и не
  перекрывают друг друга.
- [ ] До `820px` виден только функциональный чат без hero и декоративных
  рисунков, а обёртка сцены не создаёт лишнего фона или места.
- [ ] На `320px` и `375px` нет горизонтального overflow и обрезанных элементов
  управления.
- [ ] Поведение подсказки на desktop и сетевые сценарии чата не регрессировали.
- [ ] `make test` и `npm --prefix frontend run build` проходят успешно.
- [ ] Документация соответствует фактическому поведению.
