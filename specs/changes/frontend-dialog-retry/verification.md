# Проверка: повторное создание диалога

## Результат

Проверка завершена 22 сентября 2026 года. Временная недоступность backend при
первой загрузке страницы больше не оставляет frontend в постоянной ошибке:
запрос создания диалога повторяется через три секунды. Форма остаётся
заблокированной до SSE `ready`. Браузер не использовался по указанию
пользователя.

## Требования и доказательства

| Требования | Доказательство | Результат |
| --- | --- | --- |
| REQ-001–REQ-003 | `frontend/tests/ui.test.js`: первая и повторные ошибки, контролируемые таймеры, успех после восстановления | Один повтор через 3000 мс; после `201` нет нового POST или второго EventSource; форма разблокируется только после `ready` |
| REQ-004 | Node-тест `beforeunload` | Запланированный повтор отменяется, нового запроса нет |
| REQ-005 | `test:proxy`, ревью diff | Относительные `/api/v1/...` работают через Vite; backend API, Docker Compose и proxy-конфигурация не менялись |
| REQ-006 | `make test` | 17 frontend Node-тестов и 132 backend Pytest-теста прошли |

## Команды и результаты

```sh
UV_CACHE_DIR=/private/tmp/smeshariki-uv-cache UV_NO_SYNC=1 make test
npm --prefix frontend run build
npm --prefix frontend run test:proxy
UV_CACHE_DIR=/private/tmp/smeshariki-uv-cache UV_NO_SYNC=1 make lint
git diff --check
```

Все команды прошли. `UV_CACHE_DIR` и `UV_NO_SYNC` понадобились только для
доступа к существующему Python-окружению в текущей песочнице. Перед
исправлением запрос через `http://localhost:5173/api/v1/dialogs` и напрямую
к backend возвращал `201`, что позволило локализовать застревание в
одноразовой попытке frontend. В тесте RED сценарии повтора и отмены падали,
после исправления проходят.

## Границы и ограничения

- Новые UI-контролы, пакеты и серверные маршруты не добавлялись.
- Браузерная отрисовка и нативный EventSource не проверялись. Lifecycle
  проверен детерминированным fake DOM/EventSource; HTTP/SSE proxy проверен
  локальными запросами без браузера.
- Диалоги и история по-прежнему хранятся в памяти backend. После его
  перезапуска старый `dialog_id` не восстанавливается, а SSE replay нет.
