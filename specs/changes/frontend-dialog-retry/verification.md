# Проверка: повторное создание диалога

Исторический оригинал: `git show 5af56b5:specs/changes/frontend-dialog-retry/verification.md`.

## Результат

- Проверка завершена 22 сентября 2026 года. Временная недоступность backend при первой загрузке страницы больше не оставляет frontend в постоянной ошибке: запрос создания диалога повторяется через три секунды. Форма остаётся заблокированной до SSE `ready`. Браузер не использовался по указанию пользователя.
- Все команды прошли. `UV_CACHE_DIR` и `UV_NO_SYNC` понадобились только для доступа к существующему Python-окружению в текущей песочнице. Перед исправлением запрос через `http://localhost:5173/api/v1/dialogs` и напрямую к backend возвращал `201`, что позволило локализовать застревание в одноразовой попытке frontend. В тесте RED сценарии повтора и отмены падали, после исправления проходят.
- Новые UI-контролы, пакеты и серверные маршруты не добавлялись.
- Браузерная отрисовка и нативный EventSource не проверялись. Lifecycle проверен детерминированным fake DOM/EventSource; HTTP/SSE proxy проверен локальными запросами без браузера.
- Диалоги и история по-прежнему хранятся в памяти backend. После его перезапуска старый `dialog_id` не восстанавливается, а SSE replay нет.
