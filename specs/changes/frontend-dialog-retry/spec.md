# Повторное создание диалога после временной недоступности backend

## Цель

Если backend запустился после открытия frontend, интерфейс должен сам восстановить подключение. Сейчас единственная неудачная попытка
`POST /api/v1/dialogs` оставляет статус «backend недоступен» до перезагрузки
страницы, даже когда API и Vite proxy уже работают.

## Требования

- REQ-001: После неудачной попытки создать диалог frontend показывает ошибку, оставляет форму заблокированной и повторяет попытку через три секунды.
- REQ-002: После успешного `201` frontend прекращает повторы, открывает один
  `EventSource` и разблокирует форму только после `ready`.
- REQ-003: Одновременно допускается не более одной попытки создания диалога и одного запланированного повтора.
- REQ-004: При закрытии страницы запланированный повтор отменяется, а активный
  `EventSource` закрывается.
- REQ-005: Повторное подключение использует прежние относительные `/api/v1/...` URL и не меняет backend API, Docker Compose и Vite proxy.
- REQ-006: Node-тесты проверяют ошибку, повтор, восстановление, отсутствие лишнего запроса после успеха и отмену повтора при закрытии страницы.

## Границы

- Всегда: сохранять форму заблокированной до `ready`, не дублировать подписки и не обращаться из браузера к cross-origin backend URL.
- Сначала спросить: добавлять кнопку повтора, менять backend API или долговременное хранение диалога.
- Никогда: открывать браузер для проверки в этой задаче согласно указанию пользователя.
