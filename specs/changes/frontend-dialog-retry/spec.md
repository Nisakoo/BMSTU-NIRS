# Повторное создание диалога после временной недоступности backend

## Цель

Если backend запустился после открытия frontend, интерфейс должен сам
восстановить подключение. Сейчас единственная неудачная попытка
`POST /api/v1/dialogs` оставляет статус «backend недоступен» до перезагрузки
страницы, даже когда API и Vite proxy уже работают.

## Требования

- REQ-001: После неудачной попытки создать диалог frontend показывает ошибку,
  оставляет форму заблокированной и повторяет попытку через три секунды.
- REQ-002: После успешного `201` frontend прекращает повторы, открывает один
  `EventSource` и разблокирует форму только после `ready`.
- REQ-003: Одновременно допускается не более одной попытки создания диалога и
  одного запланированного повтора.
- REQ-004: При закрытии страницы запланированный повтор отменяется, а активный
  `EventSource` закрывается.
- REQ-005: Повторное подключение использует прежние относительные `/api/v1/...`
  URL и не меняет backend API, Docker Compose и Vite proxy.
- REQ-006: Node-тесты проверяют ошибку, повтор, восстановление, отсутствие
  лишнего запроса после успеха и отмену повтора при закрытии страницы.

## Сценарии

### Backend стартует после frontend

- Given страница открыта, но backend пока недоступен
- When первая попытка создания диалога завершается ошибкой
- Then форма остаётся заблокированной и показан статус повтора
- When backend становится доступен и проходит следующий повтор
- Then создаётся диалог, подключается SSE и после `ready` форма доступна

### Закрытие страницы во время ожидания

- Given повтор создания диалога запланирован
- When страница закрывается
- Then повтор отменяется и новых HTTP-запросов не происходит

## Технологии и структура

Изменяются только lifecycle в `frontend/src/script.js`, его Node-тесты,
документация frontend и архитектурный контракт диалогов. Новых сервисов,
пакетов и UI-контролов нет.

## Команды

- Тесты: `make test`
- Сборка: `npm --prefix frontend run build`
- Proxy smoke: `npm --prefix frontend run test:proxy`

## Тестирование

| Требования | Проверка |
| --- | --- |
| REQ-001–REQ-004, REQ-006 | Детерминированные Node-тесты UI с fake `fetch`, EventSource и таймерами |
| REQ-005 | Ревью URL и diff backend/Compose; локальный `test:proxy` без браузера |

## Границы

- Всегда: сохранять форму заблокированной до `ready`, не дублировать
  подписки и не обращаться из браузера к cross-origin backend URL.
- Сначала спросить: добавлять кнопку повтора, менять backend API или
  долговременное хранение диалога.
- Никогда: открывать браузер для проверки в этой задаче согласно указанию
  пользователя.

## Критерии приёмки

- [ ] Страница восстанавливается после временной ошибки создания диалога без
  перезагрузки; до `ready` форма заблокирована.
- [ ] После успеха нет новых POST и второго EventSource; при закрытии
  страницы повтор отменяется.
- [ ] Node-тесты, `make test`, Vite build и proxy smoke проходят.
- [ ] Документация описывает поведение повтора и текущие ограничения.

## Открытые вопросы

- Нет. Интервал повтора — три секунды; пользователь уже попросил устранить
  застревание статуса при доступном backend.
