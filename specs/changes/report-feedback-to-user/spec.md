# Ответ пользователю о разборе жалобы

## Цель

После [message-report](../message-report/spec.md) пользователь отправляет
жалобу на ответ, но никогда не узнаёт, что её посмотрели. Ребёнку важно
знать, что его услышали, иначе он перестанет сообщать о проблемах. Новость
должна прийти сама: когда пользователь открывает чат, Крош в плашке сверху
говорит, что взрослые посмотрели его жалобу. Искать историю для этого не
нужно. Разницу между «рассмотрено» и «отклонено» пользователю не показываем:
слово «отклонено» звучит для ребёнка как «ты не прав». Отдельная система
уведомлений (колокольчик, письма, push) не вводится.

## Требования

### Хранение

- REQ-001: Миграция `0007` добавляет в `message_reports` столбец `seen_at`
  (`timestamptz`, nullable): когда пользователь закрыл новость о разборе.
  Существующие жалобы получают `NULL`.
- REQ-002: Перевод жалобы администратором в `resolved` или `dismissed` не
  трогает `seen_at`. Возврат жалобы в `new` обнуляет `seen_at`, чтобы после
  повторного разбора пользователь снова получил новость.

### API пользователя

- REQ-003: `GET /api/v1/reports/news` возвращает новости текущего
  пользователя — его разобранные (`resolved` или `dismissed`) жалобы с
  `seen_at IS NULL`, от недавно разобранных, не больше 20:
  `{"news":[{"report_id", "dialog_id", "dialog_title"}]}`. Если история
  удалена, `dialog_id` и `dialog_title` равны `null`. Статус, причина и тексты
  жалобы не возвращаются.
- REQ-004: `POST /api/v1/reports/news/seen` с `{"report_ids":[...]}` (1–20
  целых) отмечает эти новости просмотренными (`seen_at = now()`) и отвечает
  `204`. Чужие, неразобранные, уже просмотренные и несуществующие id
  молча пропускаются. Некорректное тело — `422`.
- REQ-005: Обе ручки требуют вход (`401` раньше `422`), при сбое хранилища —
  `503`, как у ручек диалогов.
- REQ-006: `GET /api/v1/dialogs/{dialog_id}/messages` возвращает у каждого
  сообщения поле `report`: `null` (жалобы нет; у сообщений пользователя
  всегда), `"sent"` (статус `new`) или `"reviewed"` (`resolved` или
  `dismissed`). Поле `reported` сохраняется и равно `report !== null`.
  Чтение истории ничего не отмечает.

### Frontend чата

- REQ-007: После входа и создания диалога чат один раз запрашивает новости.
  Если они есть, над лентой сообщений появляется плашка Кроша
  (`role="status"`):
  - одна новость: «Взрослые посмотрели твою жалобу на историю «<название>».
    Спасибо, что рассказал!»;
  - несколько: «Взрослые посмотрели твои жалобы (N). Спасибо, что
    рассказал!»;
  - история удалена или без названия: «…твою жалобу на одну историю…».
- REQ-008: В плашке кнопка «Хорошо» скрывает её и отправляет
  `POST …/news/seen` со всеми показанными id. Для одной новости с
  существующей историей есть ещё кнопка «Открыть историю»: она открывает эту
  историю обычным способом и тоже отмечает новость. Ошибка отметки скрывает
  плашку без сообщения об ошибке; новость придёт снова при следующем
  открытии чата.
- REQ-009: Ошибка загрузки новостей не показывается пользователю и не мешает
  чату. Плашка не блокирует форму и не появляется повторно в той же сессии
  страницы.
- REQ-010: Флажок под ответом отражает `report`: `"sent"` — «Жалоба
  отправлена» (как сейчас), `"reviewed"` — «Взрослые посмотрели — спасибо!»
  с отдельным классом и `aria-label`.
- REQ-011: Динамический текст, включая название истории, выводится только
  через `textContent`.

### Безопасность и журнал

- REQ-012: Отметка просмотра журналирует `dialog.report.news_seen` с числом
  отмеченных новостей; тексты и названия не журналируются.

## Сценарии

### Ребёнок узнаёт о разборе

- Given ребёнок пожаловался на ответ в истории «Ракета», админ нажал
  «Рассмотрено»
- When ребёнок открывает чат
- Then сверху плашка Кроша «Взрослые посмотрели твою жалобу на историю
  «Ракета». Спасибо, что рассказал!»; после «Хорошо» она исчезает и после
  перезагрузки не возвращается

### Жалоба отклонена

- Given админ нажал «Отклонить»
- When ребёнок открывает чат
- Then плашка такая же; слова «отклонено» нет ни в интерфейсе, ни в ответе API

### Открыть историю из плашки

- Given одна новость, история существует
- When ребёнок нажимает «Открыть историю»
- Then открывается эта история, под ответом «Взрослые посмотрели — спасибо!»,
  новость отмечена

### Жалоба ещё не разобрана

- Given жалоба в статусе `new`
- When ребёнок открывает чат
- Then плашки нет

### Повторный разбор

- Given ребёнок уже закрыл новость
- When админ возвращает жалобу в «новые», затем снова закрывает её
- Then при следующем открытии чата плашка появляется снова

## Технологии и структура

- Backend: миграция `0007`, `db/tables.py`; в `dialogs` — модель новости,
  состояние жалобы (`sent`/`reviewed`) в `StoredMessage`, операции новостей в
  `HistoryStore` (in-memory и PostgreSQL); `PostgresReportStore` обнуляет
  `seen_at` при возврате в `new`; методы новостей в `AgentService` с
  журналом; ручки `/api/v1/reports/news` в `api/app.py` под `current_user`,
  схемы в `api/schemas.py`.
- Frontend: `agent-api.js` (`getReportNews`, `markReportNewsSeen`, разбор
  `report`), `script.js`, `index.html` (контейнер плашки), `styles.css`.
- Документация: `docs/dialogs.md`, `docs/database.md`, `docs/admin.md`
  (пользователь получает нейтральную новость), `frontend/README.md`,
  `AGENTS.md`, `docs/README.md`.

## Тестирование

- Модульные тесты in-memory хранилища и `AgentService`: новости только по
  разобранным непросмотренным жалобам владельца, порядок и лимит, удалённая
  история, отметка с пропуском чужих и неподходящих id, обнуление `seen_at`
  при возврате в `new`, `report` в истории, журнал без текстов.
- Интеграционные API-тесты: `GET`/`POST` новостей, `401` раньше `422`,
  `422` для тела, `503`; в ответах нет статуса `resolved`/`dismissed`.
- Интеграционные тесты PostgreSQL (`TEST_DATABASE_URL`): миграция `0007`,
  новости, отметка, повторный разбор после возврата в `new`.
- Node-тесты: `AgentApi` (новости, отметка, разбор `report`); UI чата
  (плашка для одной, нескольких и удалённой истории, «Хорошо», «Открыть
  историю», ошибки без сообщений, две подписи флажка).
- Ручная проверка в `make run`: жалоба → разбор в `/admin/` → плашка при
  открытии чата → после «Хорошо» не возвращается.

## Границы

- Всегда: не показывать пользователю различие `resolved`/`dismissed`;
  отдавать и отмечать только новости текущего пользователя.
- Сначала спросить: текстовый ответ администратора ребёнку, push/email,
  обновление в реальном времени по SSE, точку у истории в списке.
- Никогда: не менять миграции `0001`–`0006`; не логировать тексты.

## Критерии приёмки

- [ ] После разбора жалобы при открытии чата появляется плашка Кроша без
  поиска истории; подпись одна для «Рассмотрено» и «Отклонить».
- [ ] «Хорошо» убирает новость навсегда, пока жалобу снова не разберут после
  возврата в «новые»; «Открыть историю» открывает нужную историю.
- [ ] Под разобранным ответом подпись «Взрослые посмотрели — спасибо!».
- [ ] API не раскрывает пользователю `resolved`/`dismissed`.
- [ ] `make migrate` применяет `0007` без потери данных.
- [ ] `make test` и `make lint` проходят успешно.

## Открытые вопросы

- Нет. Допущения: новости приходят при открытии чата, а не в реальном
  времени; одна нейтральная подпись для обоих исходов; без текстового ответа
  администратора.
