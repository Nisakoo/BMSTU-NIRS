# Смена пароля в настройках аккаунта

## Цель

Вошедший пользователь сейчас не может поменять свой пароль: его можно задать только при регистрации. Изменение добавляет в боковую панель чата кнопку
«Настройки» с шестерёнкой. Она открывает окно настроек, в котором есть раздел «Сменить пароль». После смены пароля остальные устройства пользователя выходят из аккаунта, а текущее остаётся в нём.

Изменение дополняет контракт аутентификации из [auth-route-guard](../auth-route-guard/spec.md) и [backend-auth-jwt](../backend-auth-jwt/spec.md). Восстановление забытого пароля в этот объём не входит.

## Требования

### Backend и API

- REQ-001: `PUT /api/v1/users/me/password` с телом
  `{"current_password":"<пароль>","new_password":"<пароль>"}` меняет пароль
  текущего пользователя и отвечает `204` без тела. Новый пароль хешируется тем же argon2id, что и при регистрации, и сохраняется в
  `users.password_hash`. После этого вход со старым паролем даёт `401`
  `invalid_credentials`, а с новым — `200`.
- REQ-002: Тело проверяется по тем же правилам, что и пароль при регистрации: оба поля — строки длиной 8–128 символов. Лишние поля, отсутствие поля, невалидный JSON и пустое тело дают `422`
  `{"error":"invalid_fields"}`. Если новый пароль совпадает с текущим, ответ
  — `422` `{"error":"same_password"}`, пароль не меняется.
- REQ-003: Если `current_password` неверный, ответ — `400`
  `{"error":"wrong_password"}`, пароль и сессии не меняются. Для этого ответа
  не используется `401`: `401` означает отсутствие сессии, а frontend на него выполняет `refresh`.
- REQ-004: Без действительного access-токена ручка отвечает `401`
  `{"error":"unauthorized"}` раньше `422` и `400`. При сбое PostgreSQL или
  Redis — `503` `{"error":"unavailable"}`, пароль не считается изменённым.
- REQ-005: После успешной смены отзываются все активные refresh-сессии пользователя, кроме текущей: её `sid` берётся из access-токена запроса. На других устройствах следующий `POST /auth/refresh` даёт `401`; их уже
  выданные access-токены остаются действительными не дольше своего TTL (15 минут). Текущие cookie не меняются, и пользователь остаётся в аккаунте.
- REQ-006: Успешная смена журналируется событием `auth.password.changed` с
  `user_id`, отказ из-за неверного пароля — событием
  `auth.password.rejected` с `user_id` и `outcome=rejected`. Пароли и их
  хеши в журнал не попадают.
- REQ-007: Тело ошибок ручки — `{"error":"<code>"}` без введённых значений, как у остальных ручек аутентификации.

### Frontend

- REQ-008: В нижней строке боковой панели чата, между логином и кнопкой «Выйти», есть кнопка-шестерёнка с доступным именем «Настройки» и подсказкой `title="Настройки"`. Ссылка «Панель администратора» не меняется.
- REQ-009: Кнопка открывает модальное окно (`role="dialog"`,
  `aria-modal="true"`) с заголовком «Настройки» и разделом «Сменить пароль».
  В разделе три поля пароля — «Текущий пароль», «Новый пароль», «Повторите новый пароль» — и кнопка «Сохранить». Фокус переходит на первое поле. Окно закрывают кнопка «Закрыть», `Escape` и щелчок по затемнению; после
  закрытия фокус возвращается на шестерёнку, а поля очищаются.
- REQ-010: До отправки форма проверяет поля и показывает ошибку, не делая запроса:
  - пустое поле или новый пароль короче 8 либо длиннее 128 символов — «Пароль должен быть от 8 до 128 символов»;
  - повтор не совпадает с новым паролем — «Пароли не совпадают»;
  - новый пароль совпадает с текущим — «Новый пароль совпадает с текущим».
- REQ-011: «Сохранить» отправляет `PUT /api/v1/users/me/password`. На время запроса поля и кнопки окна заблокированы. Ответы:
  - `204` — поля очищаются, окно показывает «Пароль изменён. На других устройствах нужно войти заново»;
  - `400` `wrong_password` — «Неверный текущий пароль», поле текущего пароля очищается и получает фокус;
  - `422` `same_password` — «Новый пароль совпадает с текущим»;
  - `401` — один `POST /auth/refresh` и повтор запроса, как у остальных операций чата; если сессии нет, страница переходит на `/login/`;
  - сетевая ошибка, `503` и любой другой ответ — «Не удалось сменить пароль. Попробуйте ещё раз».
- REQ-012: Сообщения окна выводятся как текст в области с
  `aria-live="polite"`. Пароли не сохраняются в `localStorage`,
  `sessionStorage`, URL и cookie, доступных JavaScript.
- REQ-013: Окно доступно и на экранах до `820px`: шестерёнка находится в выдвижной панели историй, а окно помещается по ширине экрана без горизонтальной прокрутки.
- REQ-014: Открытие окна не прерывает генерацию ответа и не меняет текущую историю и `EventSource`.

## Границы

- Всегда: проверять текущий пароль на backend; отвечать без введённых значений; не журналировать пароли и хеши.
- Сначала спросить: добавление смены пароля в `/admin/`; ограничение частоты попыток; изменение текущих cookie после смены.
- Никогда: возвращать хеш пароля клиенту; хранить пароль в браузерных хранилищах; сливать ветку с `main` или пушить в рамках этого изменения.
