# Улучшение агента под DeepSeek Flash 1017

## Цель

Сделать поведение агента предсказуемым для генерации сказок на DeepSeek Flash 1017: убрать лишний демонстрационный инструмент и устаревшую переменную
окружения, задать параметры генерации через конфигурацию, связать лимит
`max_tokens` с выбранной в UI длительностью истории и переписать системный
промпт так, чтобы модель отвечала готовым русским текстом без Markdown, служебных пометок и «переводного» стиля.

## Допущения

- Под «DeepSeek Flash 1017» понимается текущая модель
  `deepseek/deepseek-flash`, доступная через настроенный `LLM_BASE_URL`;
  отдельный прокси или новый провайдер не добавляется.
- UI уже передаёт `reading_minutes` со значениями `2`, `5`, `10` или `null` («Любая»). Новые варианты длины и изменения frontend не требуются.
- «Ответ в plain text» обеспечивается системным промптом. Runtime не удаляет Markdown постобработкой: если модель всё равно нарушит формат, это дефект модели, а не скрытая трансформация текста.
- `AGENT_SYSTEM_PROMPT` уже не читается текущим `load_config`; изменение закрепляет это как поддерживаемый контракт и убирает оставшиеся упоминания
  из активной конфигурации, документации и тестов. Исторические SDD-артефакты не переписываются.
- `get_context` — демонстрационный инструмент, не нужный production-агенту. Удаляется из runtime, bootstrap, тестов и актуальной документации; история
  спецификации `get-context-example` сохраняется как исторический артефакт.
- Локальный `docker/.env` не отслеживается Git. Строку
  `AGENT_SYSTEM_PROMPT` из него разработчик удаляет вручную; приложение не
  должно от неё зависеть.

## Требования

- REQ-001: В поддерживаемом environment-контракте отсутствует
  `AGENT_SYSTEM_PROMPT`: `load_config` его не читает, `docker/compose.yaml` и
  `docker/.env.example` его не передают, актуальная документация не предлагает
  его как настройку. Наличие переменной в process environment не меняет системный промпт.
- REQ-002: Production bootstrap регистрирует в `ToolRegistry` только
  `lookup_knowledge`. Модуль `agent/get_context.py`, его тесты, импорт и
  регистрация в bootstrap удаляются. Модель не получает описание
  `get_context` и не может его вызвать.
- REQ-003: Системный промпт `agent/prompts/system.md` переписывается под DeepSeek Flash 1017 и требует: писать только готовую сказку на естественном
  русском языке; не использовать Markdown, HTML, списки, таблицы, блоки кода и эмодзи; не показывать рассуждения, план, черновик и служебные пометки; не
  упоминать инструменты, поиск, источники и системный контекст; не вставлять иероглифы и иноязычные кальки. Допустимы обычные абзацы, название обычной строкой и реплики героев с тире.
- REQ-004: В `LiteLLMProviderConfig` добавляется температура генерации. Значение читается из `LLM_TEMPERATURE`, по умолчанию `0.8`, допускается число от `0` до `2` включительно; невалидное значение останавливает загрузку
  конфигурации. Значение передаётся в `litellm.acompletion` как `temperature`.
- REQ-005: В `LiteLLMProviderConfig` добавляется флаг thinking. Значение читается из `LLM_THINKING`, по умолчанию `false`. Для DeepSeek-модели провайдер передаёт `thinking={"type": "enabled"}` при `true` и
  `thinking={"type": "disabled"}` при `false`. Для не-DeepSeek модели
  `LLM_THINKING=true` отклоняется при загрузке конфигурации; при `false`
  параметр `thinking` не передаётся.
- REQ-006: `LLMProvider.stream` принимает необязательный `max_tokens`. `Agent` вычисляет его из `UserRequest.reading_minutes`: `2` → `1200`, `5` → `3000`,
  `10` → `6000`; `null` → `max_tokens` не передаётся. Ограничение действует на
  каждый отдельный вызов LLM в agent loop.
- REQ-007: Если thinking включён, `LiteLLMProvider` добавляет к вычисленному
  `max_tokens` резерв `3000` токенов на скрытые рассуждения. Если `max_tokens`
  не задан, резерв не добавляется и действует лимит провайдера по умолчанию. Итоговое значение передаётся в `litellm.acompletion`.
- REQ-008: `FakeLLMProvider` и тестовые провайдеры принимают новый аргумент
  `max_tokens` без изменения детерминированного поведения.
- REQ-009: `docker/.env.example`, `docker/compose.yaml` и
  `docs/configuration.md` содержат `LLM_TEMPERATURE` и `LLM_THINKING` с
  безопасными значениями по умолчанию; реальные секреты не добавляются.
- REQ-010: `docs/agent.md`, `docs/rag.md`, `docs/README.md`, `docker/README.md` и `AGENTS.md` описывают удаление `get_context`, новый набор инструментов, параметры генерации, связь `max_tokens` с длительностью и правила
  plain-text ответа.
- REQ-011: Журналирование остаётся безопасным: значения температуры, thinking и `max_tokens` могут попадать в стабильные события, но текст промпта, сообщений, рассуждений и ответов в журнал не передаётся.
- REQ-012: Существующие сценарии диалогов, SSE, RAG, аутентификации и frontend не меняются, кроме удаления `get_context` из набора инструментов.

## Границы

- Всегда: сохранять существующие правила сказки, безопасное журналирование и контракт `LLMProvider`.
- Сначала спросить: изменение значений по умолчанию температуры, таблицы
  `max_tokens`, резерва thinking, а также поддержку thinking у не-DeepSeek
  моделей.
- Никогда: не добавлять отдельный RAG-сервис, новый LLM-провайдер, скрытую постобработку текста, Markdown-рендеринг во frontend и не переписывать исторические SDD-спецификации.
