# План: перенос статического frontend-прототипа

## Основание

План реализует согласованную спецификацию
`specs/changes/frontend-static-ui-import/spec.md`. Перенос не меняет содержимое
прототипа, не выбирает новый frontend-стек и не подключает интерфейс к backend.

## Зависимости и порядок

1. До перемещения фиксируются контрольные суммы и полный состав исходных
   проектных файлов, затем проверяется отсутствие конфликтов в `frontend/`.
2. Проектные файлы перемещаются с сохранением структуры; существующий каркас
   `frontend/` остаётся на месте, а `.DS_Store` удаляются как служебные файлы.
3. После появления реализации обновляются описание frontend и глобальная карта
   проекта.
4. Реализация проверяется статическим HTTP-сервером, ревью дерева и
   регрессионными тестами продукта.

Новые программные зависимости не требуются. Для визуальной проверки
используются стандартный статический HTTP-сервер и браузер.

## Задача 1. Зафиксировать источник и перенести прототип

**Связанные требования:** REQ-001–REQ-004.

**Критерии приёмки:** пять проектных файлов находятся в `frontend/` по
согласованным путям, их контрольные суммы совпадают с исходными, существующий
каркас не изменён, а исходное дерево очищено.

**Зависимости:** нет.

**Файлы:**

- `frontend/smeshariki_ai.html`;
- `frontend/styles.css`;
- `frontend/script.js`;
- `frontend/static/characters/krosh.png`;
- `frontend/static/characters/kopatych.png`.

**Действия:**

1. Получить SHA-256 пяти исходных проектных файлов и проверить, что целевые
   пути не заняты.
2. Переместить HTML, CSS, JavaScript и каталог изображений в `frontend/`, не
   меняя содержимое файлов.
3. Удалить исходные `.DS_Store` и опустевшие каталоги `static/characters/`,
   `static/` и `NIRS/`.
4. Сравнить итоговые SHA-256 с зафиксированными значениями и проверить
   сохранность `frontend/README.md`, `frontend/src/` и `frontend/tests/`.

**Проверка ревью:**

```sh
find frontend -maxdepth 4 -print | sort
find frontend -name .DS_Store -print
shasum -a 256 frontend/smeshariki_ai.html frontend/styles.css frontend/script.js frontend/static/characters/krosh.png frontend/static/characters/kopatych.png
```

Автоматические структурные тесты не добавляются.

## Задача 2. Обновить документацию фактического состояния

**Связанные требования:** REQ-005.

**Критерии приёмки:** документация описывает статический прототип, способ его
локального просмотра, автономный демонстрационный ответ JavaScript и отсутствие
интеграции с dialog/SSE API.

**Зависимости:** задача 1.

**Файлы:**

- `frontend/README.md`;
- `docs/README.md`.

**Действия:**

1. Заменить описание пустого frontend-каркаса на описание фактических файлов,
   запуска и текущих ограничений прототипа.
2. Обновить глобальную карту и список нереализованных возможностей.
3. Добавить ссылки на спецификацию, план и позднее — verification-отчёт.

**Проверка ревью:**

```sh
sed -n '1,240p' frontend/README.md
sed -n '1,260p' docs/README.md
```

Автоматические тесты документации не добавляются.

## Задача 3. Проверить статический runtime и регрессии

**Связанные требования:** REQ-001–REQ-005.

**Критерии приёмки:** статический сервер отдаёт страницу и все четыре
подключаемых ресурса без ошибок, страница визуально отображается, а существующие
тесты продукта проходят.

**Зависимости:** задачи 1 и 2.

**Изменяемые файлы:** нет.

**Действия:**

1. Запустить локальный HTTP-сервер с корнем `frontend/`.
2. Проверить HTTP 200 для HTML, CSS, JavaScript и обоих PNG и визуально открыть
   страницу в браузере.
3. Проверить, что локальные ссылки HTML соответствуют итоговой структуре.
4. Запустить полный набор существующих продуктовых тестов.

**Команды проверки:**

```sh
make test
git diff --check
git status --short
```

## Итоговая проверка реализации

1. Сопоставить REQ-001–REQ-005 и каждый критерий приёмки с результатами
   ревью или runtime-проверки.
2. Убедиться, что содержимое перенесённых проектных файлов не менялось.
3. Убедиться, что не добавлены зависимости, frontend-фреймворк, сборщик,
   Docker-конфигурация или изменения backend.
4. Записать команды, результаты и ограничение демонстрационного JavaScript в
   `verification.md`, затем установить статус `done` только при успехе всех
   проверок.
