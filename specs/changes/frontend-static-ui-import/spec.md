# Перенос статического frontend-прототипа

## Цель

Перенести подготовленный статический прототип пользовательского интерфейса из
`/Users/kseniablinkova/Desktop/NIRS` в каталог `frontend/` репозитория, сохранив
его структуру, содержимое и существующие файлы каркаса frontend.

## Требования

- REQ-001: В `frontend/` находятся без изменения содержимого файлы
  `smeshariki_ai.html`, `styles.css`, `script.js`,
  `static/characters/krosh.png` и `static/characters/kopatych.png` из исходного
  каталога.
- REQ-002: Существующие `frontend/README.md`, `frontend/src/` и
  `frontend/tests/` сохраняются без удаления или перезаписи.
- REQ-003: Относительные связи HTML с `styles.css` и `script.js`, а также пути
  `/static/characters/*.png` сохраняют работоспособность при раздаче
  `frontend/` как корня статического сайта.
- REQ-004: После успешного переноса исходный каталог
  `/Users/kseniablinkova/Desktop/NIRS` не содержит переносимых файлов;
  служебные файлы Finder `.DS_Store` в репозиторий не добавляются и удаляются
  при очистке опустевшего исходного дерева.
- REQ-005: Архитектурный каталог и описание frontend отражают появление
  статического прототипа и явно отмечают, что JavaScript пока возвращает
  демонстрационный ответ и не интегрирован с существующим dialog/SSE API.

## Сценарии

### Основной сценарий

- Given в `/Users/kseniablinkova/Desktop/NIRS` находятся HTML, CSS, JavaScript
  и изображения прототипа, а в репозитории существует каркас `frontend/`
- When файлы переносятся в `frontend/` с сохранением исходной структуры
- Then статический прототип доступен из `frontend/smeshariki_ai.html`, его
  локальные ресурсы разрешаются, а исходные переносимые файлы отсутствуют

### Сохранение существующего каркаса

- Given `frontend/` уже содержит README и нейтральные каталоги `src/` и
  `tests/`
- When выполняется перенос
- Then существующие файлы и каталоги не перезаписаны и не удалены

### Служебные файлы macOS

- Given исходное дерево содержит `.DS_Store`
- When выполняется перенос
- Then `.DS_Store` не появляется в репозитории, а служебные файлы удалены из
  исходного дерева

## Технологии и структура

Прототип остаётся статическим HTML/CSS/JavaScript без добавления frontend-
фреймворка, сборщика и новых зависимостей. В `frontend/` добавляются три файла
верхнего уровня и дерево `static/characters/` с двумя PNG. Обновляются
`frontend/README.md` и глобальный каталог `docs/README.md`; отдельная
тематическая страница не создаётся, пока frontend не имеет собственной
архитектуры или внешнего контракта.

## Команды

- Запуск: отдельная команда frontend пока не определена; прототип проверяется
  как статический сайт с корнем `frontend/`.
- Тесты продукта: `make test`.

## Тестирование

Автоматические тесты для одного только перемещения структуры не добавляются.
Проверка выполняется сравнением контрольных сумм исходных и перенесённых
проектных файлов, проверкой итогового дерева, отсутствия `.DS_Store`, ссылок на
локальные ресурсы и визуальным открытием страницы через локальный статический
HTTP-сервер. `make test` запускается как регрессионная проверка существующего
продукта.

## Границы

- Всегда: сохранить байтовое содержимое проектных файлов и существующий каркас
  `frontend/`; обновить архитектурную документацию фактического состояния.
- Сначала спросить: изменение разметки, стилей, поведения JavaScript, имён
  файлов или подключение прототипа к backend API.
- Никогда: добавлять frontend в `docker/compose.yaml`, переносить `.DS_Store`,
  внедрять новый frontend-стек или менять backend в рамках этого изменения.

## Критерии приёмки

- [ ] Пять проектных файлов из исходного каталога находятся в `frontend/` с
  прежними путями относительно корня прототипа и совпадающими контрольными
  суммами.
- [ ] `frontend/README.md`, `frontend/src/` и `frontend/tests/` сохранены.
- [ ] В репозитории и исходном дереве отсутствуют `.DS_Store`; исходный каталог
  очищен после успешного переноса.
- [ ] При раздаче `frontend/` как корня статического сайта HTML, CSS,
  JavaScript и оба PNG загружаются без ошибок, страница визуально отображается.
- [ ] `frontend/README.md` и `docs/README.md` соответствуют фактическому
  состоянию и ссылаются на SDD-артефакты изменения.
- [ ] `make test` проходит успешно как регрессионная проверка продукта; новые
  структурные тесты не добавлены.
