# Чат с боковой панелью «Мои истории»

## Цель

Команде не нравится, что чат `/` выглядит как два вложенных слоя: крупный
заголовок, скруглённая «сцена» с рамкой и уже внутри неё окно чата. По
выбранному макету (вариант «Компактно по центру») чат становится
приложением во весь экран: слева боковая панель с новой историей, списком
сохранённых историй пользователя и выходом, справа сам чат. Список и история
берутся из API постоянных диалогов
[user-dialog-history](../user-dialog-history/spec.md), поэтому это изменение
реализуется после него. Изменение заменяет визуальные требования
[frontend-responsive-layout](../frontend-responsive-layout/spec.md),
[frontend-laptop-baseline-mobile-chat](../frontend-laptop-baseline-mobile-chat/spec.md)
и [frontend-krosh-hint-input-dismiss](../frontend-krosh-hint-input-dismiss/spec.md)
для страницы `/`; сетевой протокол чата из
[frontend-agent-integration](../frontend-agent-integration/spec.md) и
проверка сессии из [auth-route-guard](../auth-route-guard/spec.md)
сохраняются.

## Требования

### Раскладка

- REQ-001: Страница занимает весь viewport без внешней рамки, крупного
  заголовка над чатом, пузырей с персонажами, луны и подсказки Кроша. На
  desktop страница не прокручивается целиком: прокручиваются только список
  историй и лента сообщений.
- REQ-002: Слева — боковая панель шириной около `280px`: логотип
  «✦ Смешарики AI», кнопка «+ Новая история», заголовок «Мои истории», список
  историй и внизу логин текущего пользователя с кнопкой «Выйти».
- REQ-003: Справа — шапка с названием текущей истории (для новой —
  «Новая история») и индикатором состояния, лента сообщений по центру
  колонки шириной до `780px`, ниже поле ввода с кнопкой отправки и чипами
  тем. У нижнего края — приглушённые ночные холмы как фон, не перекрывающие
  текст и элементы управления.
- REQ-004: На ширине до `820px` боковая панель скрыта; в шапке появляется
  кнопка «Истории», которая открывает панель поверх чата, а выбор истории,
  «Новая история» или нажатие вне панели её закрывают. На viewport от `320px`
  до `1920px` нет горизонтальной прокрутки и элементов за краем экрана.

### Поведение

- REQ-005: При открытии страницы после проверки сессии (как раньше) frontend
  создаёт новый диалог, открывает `EventSource`, показывает приветствие
  ассистента и параллельно загружает `GET /api/v1/dialogs`. В панели
  показывается логин пользователя из результата проверки сессии.
- REQ-006: Каждая история списка показывает `title`; список отсортирован так,
  как вернул backend. Текущая история выделена и помечена
  `aria-current="true"`. Пустой список показывает текст «Здесь появятся ваши
  истории».
- REQ-007: Нажатие на историю закрывает текущий `EventSource`, загружает
  `GET /api/v1/dialogs/{dialog_id}/messages`, показывает сообщения в порядке
  ответа (пользовательские справа, ответы ассистента слева), ставит название в
  шапку и открывает `EventSource` этого диалога. Форма разблокируется только
  после `ready`. Новые сообщения отправляются в выбранный диалог.
- REQ-008: «+ Новая история» создаёт новый диалог, очищает ленту, показывает
  приветствие и снимает выделение в списке.
- REQ-009: Пока отправляется запрос или агент отвечает, переключение историй
  и «Новая история» недоступны (кнопки `disabled`).
- REQ-010: После `message_end` frontend перезагружает список, чтобы новая
  история появилась наверху со своим названием, а текущая осталась выделенной.
- REQ-011: Ошибка загрузки списка показывает в панели «Не удалось загрузить
  истории» и кнопку «Повторить»; чат при этом продолжает работать. Ошибка
  загрузки выбранной истории оставляет пользователя в текущем диалоге с
  сообщением об ошибке в строке состояния; `404` дополнительно
  перезагружает список.
- REQ-012: Для новых запросов действует прежнее правило сессии: при `401`
  один `refresh` и повтор, при повторном отказе — переход на `/login/`.
- REQ-013: Названия историй, сообщения и тексты ошибок вставляются только как
  текст, без `innerHTML`. `dialog_id` по-прежнему не сохраняется в cookie,
  `localStorage` или URL: перезагрузка страницы начинает новую историю, а
  прежние доступны в списке.
- REQ-014: Существующее поведение чата сохраняется: блокировка формы до
  `ready`, буферизация быстрых событий до ответа POST, одна реплика
  ассистента на ответ, повтор создания диалога через три секунды, отправка по
  Enter, чипы тем, выход через «Выйти».

### Клиент API

- REQ-015: `AgentApi.listDialogs()` выполняет `GET /api/v1/dialogs` и
  возвращает массив `{dialogId, title, updatedAt}`; `AgentApi.getMessages(id)`
  выполняет `GET /api/v1/dialogs/{id}/messages` и возвращает
  `{title, messages:[{role, content}]}`. Ошибки — `AgentApiError` с кодами
  `unauthorized` (`401`), `not_found` (`404`), `load_failed` (сеть и прочие
  статусы) и `invalid_response` (некорректный JSON или схема).

## Сценарии

### Продолжение истории

- Given у пользователя есть сохранённая история «Крош и Ёжик строят ракету»
- When он открывает чат и нажимает на неё в панели
- Then лента показывает прежние сообщения, шапка — название, а новое
  сообщение продолжает эту историю с учётом контекста

### Первая история

- Given у пользователя нет историй
- When он отправляет первый запрос и получает ответ
- Then история появляется наверху списка с названием из его запроса и
  выделена как текущая

### Mobile

- Given viewport `375x800`
- When пользователь нажимает «Истории» и выбирает историю
- Then панель закрывается, открыт выбранный диалог, горизонтальной прокрутки
  нет

### Ошибка списка

- Given backend отвечает `503` на `GET /api/v1/dialogs`
- When открывается чат
- Then панель показывает «Не удалось загрузить истории» и «Повторить», а
  новый диалог работает

### Переключение во время ответа

- Given агент отвечает на запрос
- When пользователь пытается выбрать другую историю
- Then кнопки истории недоступны, текущий ответ дописывается в текущий диалог

## Технологии и структура

Vanilla JavaScript без новых зависимостей. Меняются `frontend/src/index.html`,
`frontend/src/styles.css`, `frontend/src/script.js`,
`frontend/src/agent-api.js`, тесты `frontend/tests/ui.test.js` и
`frontend/tests/agent-api.test.js`, `frontend/README.md` и описание
frontend в `docs/README.md`. Изображения персонажей на странице чата больше не
используются, но файлы остаются (они нужны странице входа).

## Команды

- Запуск: `make run`
- Dev server: `make frontend`
- Тесты: `make test`

## Тестирование

- Node-тесты `AgentApi`: запросы, разбор ответов и коды ошибок новых
  методов.
- Node-тесты UI на fake DOM: загрузка и отображение списка, выделение
  текущей истории, открытие истории с загрузкой сообщений и новым
  `EventSource`, «Новая история», блокировка переключения во время ответа,
  перезагрузка списка после `message_end`, ошибка списка с повтором,
  `404` истории, вставка только текстом, прежние сценарии сессии и потока.
- Тесты подсказки Кроша удаляются вместе с подсказкой.
- Визуальная проверка скриншотами headless Chrome на `1440x900`, `1280x720`,
  `768x1024`, `375x800`, `320x640` и ручная проверка в `make run` с реальным
  backend.

## Границы

- Всегда: проверять сессию как раньше, вставлять пользовательский и модельный
  текст только как текст, блокировать параллельные запросы.
- Сначала спросить: удаление или переименование историй, сохранение
  выбранной истории между перезагрузками, светлую тему.
- Никогда: не менять backend в рамках этого изменения, не использовать
  `innerHTML` для динамического текста, не хранить `dialog_id` в браузерном
  хранилище.

## Критерии приёмки

- [ ] На `1440x900` чат во весь экран без внешней рамки: слева панель
  историй, справа чат, как на выбранном макете.
- [ ] Сохранённая история открывается из списка с прежними сообщениями и
  продолжается новым запросом.
- [ ] Новая история появляется в списке после первого ответа.
- [ ] На `375x800` панель открывается кнопкой «Истории», горизонтальной
  прокрутки нет.
- [ ] Ошибки списка и истории не ломают текущий чат.
- [ ] `make test` проходит успешно.

## Открытые вопросы

- Нет. Допущения: подсказка Кроша и персонажи убираются со страницы чата, как
  на макете; выбранная история не восстанавливается после перезагрузки.
