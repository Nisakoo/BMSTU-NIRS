# Кнопка выхода в чате и панели администратора

## Цель

Пользователь чата `/` и администратор на `/admin/` могут завершить сессию
кнопкой «Выйти» и попасть на страницу входа и регистрации `/login/`. Backend
уже реализует `POST /api/v1/auth/logout` (см. [`docs/auth.md`](../../../docs/auth.md));
изменение затрагивает только frontend и документацию.

## Требования

- REQ-001: На странице чата `/` есть кнопка «Выйти» (`<button type="button">`)
  в шапке окна чата справа, рядом со статусом, доступная с клавиатуры и
  видимая на desktop и mobile без перекрытия формы ввода.
- REQ-002: На странице `/admin/` есть кнопка «Выйти» в нижней части боковой
  панели под ссылкой на пользовательский чат; на узких экранах она остаётся
  доступной.
- REQ-003: Нажатие отправляет `AuthApi.logout()` (`POST /api/v1/auth/logout`
  без тела, `credentials: "same-origin"`). На время запроса кнопка
  заблокирована, повторные нажатия не отправляют новых запросов.
- REQ-004: После `204` страница выполняет `location.replace("/login/")`. В
  чате перед переходом закрывается `EventSource` и отменяется отложенный повтор
  создания диалога; незавершённый ответ агента не ожидается.
- REQ-005: Если запрос выхода не удался (сеть, `503`, другой статус), страница
  остаётся на месте, кнопка снова доступна, показывается сообщение «Не удалось
  выйти. Попробуйте ещё раз»: в чате — в строке статуса (на узких экранах строка статуса
  показывается для состояния ошибки), в админке — в
  существующем блоке ошибки или рядом с кнопкой. Переход на `/login/` не
  выполняется, потому что при ошибке backend cookie сессии не сбрасываются.
- REQ-006: Кнопка не читает и не удаляет cookie из JavaScript и не использует
  `localStorage`/`sessionStorage`: сессию завершает backend.
- REQ-007: Документация (`docs/auth.md`, `frontend/README.md`, `AGENTS.md`)
  описывает кнопки выхода; пункт «кнопка выхода» удаляется из «Что пока не
  реализовано».

## Сценарии

### Пользователь выходит из чата

- Given пользователь вошёл и открыт чат `/`
- When он нажимает «Выйти»
- Then отправляется `POST /api/v1/auth/logout`, backend отвечает `204`
- And открывается `/login/`, а повторное открытие `/` снова ведёт на `/login/`

### Администратор выходит из панели

- Given администратор открыл `/admin/`
- When он нажимает «Выйти» в боковой панели
- Then после `204` открывается `/login/`

### Backend недоступен при выходе

- Given открыт чат, Redis или PostgreSQL недоступны
- When пользователь нажимает «Выйти»
- Then backend отвечает `503`, страница остаётся на `/`
- And в статусе показано «Не удалось выйти. Попробуйте ещё раз», кнопка снова
  активна

## Технологии и структура

Vanilla JavaScript без новых зависимостей. Используется существующий
`AuthApi.logout()` и константа `LOGIN_PATH` из `auth-session.js`. Разметка
добавляется в `frontend/src/index.html` и `frontend/src/admin/index.html`,
стили — в `styles.css` и `admin/admin.css`. Backend не меняется.

## Команды

- Запуск: `make run`
- Тесты: `make test`

## Тестирование

- Node-тесты чата (`ui.test.js`) и админки (`admin-ui.test.js`) с fake
  `fetch`/`location`: успешный выход закрывает поток и переходит на `/login/`;
  блокировка кнопки во время запроса и отсутствие повторного запроса; ошибка
  оставляет страницу, показывает сообщение и разблокирует кнопку.
- Ручная проверка в `make run`: выход из чата и из админки, после выхода `/`
  и `/admin/` ведут на `/login/`; вид кнопки на desktop и mobile.

## Границы

- Всегда: только `textContent` для сообщений; переход через
  `location.replace`.
- Сначала спросить: подтверждение перед выходом, выход со страницы `/login/`,
  показ логина пользователя рядом с кнопкой.
- Никогда: удаление cookie или хранение токенов в JavaScript.

## Критерии приёмки

- [ ] Кнопка «Выйти» есть в чате и в админке и доступна с клавиатуры.
- [ ] Успешный выход ведёт на `/login/`; после этого `/` и `/admin/` снова
  ведут на `/login/`.
- [ ] Ошибка выхода оставляет пользователя на странице с понятным сообщением.
- [ ] Повторные нажатия во время запроса не отправляют новых запросов.
- [ ] Документация обновлена по REQ-007.
- [ ] `make test` и `make lint` проходят успешно.
