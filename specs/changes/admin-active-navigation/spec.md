# Активное состояние навигации панели администратора

## Цель

Исправить навигацию панели администратора так, чтобы визуально и программно
активным был выбранный пользователем раздел, а ссылка «Обзор» не оставалась
подсвеченной после перехода к другим разделам страницы.

## Требования

- REQ-001: При открытии `/admin/` без поддерживаемого hash активной является
  ссылка «Обзор».
- REQ-002: При выборе ссылки «Обзор», «Активность» или «Пользователи» активное
  состояние переносится только на выбранную ссылку; ранее выбранная ссылка
  перестаёт быть активной.
- REQ-003: Активная ссылка программно обозначается атрибутом
  `aria-current="location"`, чтобы состояние было доступно не только визуально.
- REQ-004: При открытии страницы с hash `#overview`, `#activity` или `#users`,
  а также при изменении hash средствами браузера, активная ссылка соответствует
  указанному разделу.
- REQ-005: Неизвестный или пустой hash безопасно выбирает «Обзор» и не нарушает
  существующую отрисовку демонстрационных данных и переключение периода.

## Сценарии

### Выбор другого раздела

- Given в панели администратора активна ссылка «Обзор»
- When пользователь выбирает ссылку «Активность»
- Then ссылка «Активность» получает активную подсветку и
  `aria-current="location"`
- And ссылка «Обзор» больше не имеет активной подсветки и `aria-current`

### Открытие ссылки на конкретный раздел

- Given URL панели содержит `#users`
- When панель инициализируется
- Then активной является только ссылка «Пользователи»

### Некорректный hash

- Given URL панели содержит неизвестный hash
- When панель инициализируется или hash изменяется
- Then активной является только ссылка «Обзор»
- And панель продолжает работать без ошибки

## Технологии и структура

Изменение остаётся в существующем vanilla JavaScript frontend. Логика
активного состояния добавляется в `frontend/src/admin/admin.js`, статический
активный атрибут в `frontend/src/admin/index.html` приводится к новому
доступному контракту, а поведение покрывается Node DOM-тестами в
`frontend/tests/admin-ui.test.js`. Новые зависимости и изменения backend не
требуются.

## Команды

- Запуск: `make run`
- Frontend-тесты: `npm --prefix frontend test`
- Production-сборка: `npm --prefix frontend run build`
- Полная проверка: `make test`

## Тестирование

| Требования | Способ проверки |
| --- | --- |
| REQ-001–REQ-003 | Node DOM-тест начального состояния и переноса `aria-current` после выбора каждой навигационной ссылки |
| REQ-004–REQ-005 | Node DOM-тест инициализации и события `hashchange` с поддерживаемым, пустым и неизвестным hash |
| Отсутствие регрессий | Существующие frontend-тесты, production build и полный `make test` |

Новые тесты на этапе `specify` не реализуются.

## Границы

- Всегда: сохранять существующие ссылки-якоря, стили активного состояния,
  клавиатурную доступность и работу остальных элементов панели.
- Сначала спросить: добавлять новые разделы, автоматическое переключение
  подсветки при ручной прокрутке без изменения hash или менять внешний вид
  навигации.
- Никогда: добавлять backend-запросы, новые runtime-зависимости или изменять
  пользовательский чат в рамках этого исправления.

## Критерии приёмки

- [ ] После выбора «Активность» или «Пользователи» «Обзор» больше не остаётся
  подсвеченным.
- [ ] В каждый момент активна ровно одна ссылка навигации, соответствующая
  текущему поддерживаемому hash или fallback-разделу «Обзор».
- [ ] Активность определяется визуально и через `aria-current="location"`.
- [ ] Прямые ссылки на поддерживаемые разделы и навигация назад/вперёд
  синхронизируют активное состояние.
- [ ] Существующая отрисовка панели и переключение периода работают без
  регрессий.
- [ ] `npm --prefix frontend test`, production build и `make test` проходят
  успешно.

## Открытые вопросы

- Нет. В рамках этого изменения активный раздел определяется выбранной
  якорной ссылкой и URL hash; автоматический scrollspy при ручной прокрутке не
  добавляется.
