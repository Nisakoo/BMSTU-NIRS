# План: адаптивный frontend и скрытие подсказки Кроша

## Исходное состояние и решения

- Корневая ширина ограничена `1180px`, чат — `860px`; на широком экране оба
  блока перестают расти слишком рано.
- В `styles.css` есть два набора media queries для одних и тех же breakpoint,
  поэтому итоговая геометрия персонажей и подсказки зависит от поздних
  переопределений.
- Подсказка уже имеет CSS-состояние `.is-hidden`, но JavaScript добавляет его
  только после успешного `202 Accepted`.
- Автоматический `prompt.focus()` при событии `ready` сохраняется. На время
  этого программного фокуса обработчик скрытия будет явно подавлен; остальные
  focus/pointer/keyboard/input/clipboard/drop-события пользователя скрывают
  подсказку идемпотентно.
- Новые runtime-зависимости не нужны. Геометрия будет проверена в реальном
  браузере на viewport из спецификации, а поведение подсказки — существующим
  Node DOM-harness.

## Задача 1. Зафиксировать и реализовать жизненный цикл подсказки

**Требования:** REQ-006–REQ-009.

**Критерии приёмки:** автоматический фокус не скрывает подсказку; первое
пользовательское взаимодействие или тематическая кнопка скрывает её;
повторные события безопасны; значение textarea, autosize и отправка не
меняются.

**Зависимости:** одобренная спецификация; существующий `.is-hidden` в CSS.

**Файлы:**

- `frontend/tests/ui.test.js`;
- `frontend/src/script.js`.

**Шаги:**

1. Расширить fake DOM так, чтобы тест мог наблюдать подсказку и различать
   программный и пользовательский фокус.
2. Сначала добавить падающие тесты для автоматического фокуса, событий
   `focus`, `pointerdown`, `keydown`, `input`, `paste`, `drop`, выбора chip и
   идемпотентного повторного скрытия.
3. Добавить единую функцию `dismissHint()` и привязать её к перечисленным
   пользовательским событиям.
4. Обернуть только автоматический фокус после `ready` в локальное подавление
   скрытия; выбор тематической кнопки должен скрывать подсказку до вызова
   `focus()`.
5. Оставить скрытие после успешной отправки как безопасную идемпотентную
   страховку либо заменить прямое изменение класса вызовом той же функции.

**Проверка:**

```sh
npm --prefix frontend test
```

## Задача 2. Сделать геометрию fluid и устранить конфликтующие breakpoint

**Требования:** REQ-001–REQ-005, REQ-009.

**Критерии приёмки:** интерфейс заметно крупнее на `1440x900` и `1920x1080`;
на `320x568`, `375x667`, `768x1024` и `1366x768` нет горизонтального overflow,
обрезанных контролов или перекрытия формы декором.

**Зависимости:** задача 1 не блокирует CSS, но выполняется первой, чтобы
поведение подсказки было покрыто тестом до визуальной перестройки.

**Файлы:**

- `frontend/src/styles.css`.

**Шаги:**

1. Заменить жёсткие верхние пределы корневого контейнера, hero, сцены и чата
   на согласованные fluid-значения с `min()`, `clamp()` и адаптивными
   внешними отступами; сохранить ограничение длины сообщения.
2. Масштабировать высоту сцены и области сообщений в разумных пределах, чтобы
   широкие экраны использовались лучше, а ноутбучный viewport не получал
   чрезмерную фиксированную высоту.
3. Объединить дублирующиеся правила `1050px`, `820px` и `570px`, сохранив
   ночную тему и один понятный источник геометрии персонажей, подсказки, луны и
   пейзажа.
4. Для `<=820px` зарезервировать нижнюю декоративную область сцены отдельно от
   чата; для `<=570px` уменьшить внешние отступы, гарантировать минимальные
   размеры textarea/send и оставить горизонтальную прокрутку только внутри
   ряда chip.
5. Добавить узкий fallback для viewport около `320px`, если измерения покажут
   наложение двух персонажей или подсказки; персонажи не скрывать без нового
   согласования.

**Проверка:**

```sh
npm --prefix frontend run build
```

Дополнительно в реальном браузере для каждого viewport из спецификации:

- сравнить `document.documentElement.scrollWidth` и `clientWidth`;
- проверить bounding box сцены, чата, composer, textarea и send button;
- проверить отсутствие пересечения composer с Крошем, Копатычем и подсказкой;
- визуально просмотреть снимки `320x568` и `1920x1080`.

## Риски и контроль

- **Программный focus ошибочно скрывает подсказку.** Контроль отдельным тестом
  сразу в задаче 1.
- **Поздний CSS override возвращает старую геометрию.** Контроль консолидацией
  повторных media queries и browser computed-style/bounding-box проверкой.
- **Декор не перекрывает composer визуально, но ловит ввод.** У декоративного
  пейзажа сохраняется `pointer-events:none`; пересечение bounding box
  дополнительно проверяется для видимых персонажей и подсказки.
- **Широкий чат ухудшает читаемость.** Ширина оболочки увеличивается, но
  отдельная реплика сохраняет ограниченную максимальную ширину.
