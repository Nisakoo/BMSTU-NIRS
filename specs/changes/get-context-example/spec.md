# Пример инструмента `get_context`

## Цель

Добавить демонстрационный инструмент агента, который возвращает заранее заданный текст. Произвольный маркер в тексте позволяет проверить, что ответ получен через вызов инструмента, а не выведен моделью из общих знаний.

## Требования

- REQ-001: Production-сборка backend регистрирует у агента инструмент с именем `get_context`, описанием назначения и схемой без аргументов. Инструмент не предоставляет отдельный HTTP endpoint.
- REQ-002: При вызове `get_context` с пустым объектом аргументов результатом является в точности строка: `Секретный маркер учебного стенда: СФЕРА-8К2М-ЛИМОН. Контрольная фраза: «пингвин считает жёлтые скрепки».`
- REQ-003: Повторные вызовы возвращают ту же строку. Инструмент не читает environment, файлы, сеть и состояние диалога.
- REQ-004: Вызов с неожиданными аргументами отклоняется существующим `ToolRegistry` как `invalid_arguments` без исполнения инструмента.
- REQ-005: Агент может получить строку через штатный tool-calling loop и использовать её при формировании ответа; выбор момента вызова остаётся за LLM.
- REQ-006: Тематическая документация агента и глобальный каталог отражают добавленный инструмент и его границу ответственности.

## Сценарии

### Основной сценарий

- Given запущен backend и модель решила вызвать `get_context` с `{}`
- When `ToolRegistry` выполняет вызов
- Then модель получает точную строку из REQ-002 как результат инструмента и продолжает формировать ответ.

### Ошибка или граничный случай

- Given модель вызвала `get_context` с неизвестным полем
- When `ToolRegistry` проверяет аргументы
- Then он возвращает безопасную ошибку `invalid_arguments`; текст контекста не возвращается.

## Технологии и структура

Отдельная реализация `Tool` в пакете `smeshariki_ai.agent`; регистрация в существующем backend bootstrap через `ToolRegistry`. Pydantic-модель без полей с запретом лишних аргументов. Текущие контракты агента, LiteLLM и HTTP остаются прежними.

## Команды

- Запуск: `make run`
- Тесты: `make test`

## Тестирование

- Модульный тест проверяет имя, схему без аргументов, точную строку, повторяемость и отклонение лишних аргументов через `ToolRegistry`.
- Тест сборки backend проверяет, что агенту доступен `get_context`; тест agent loop с детерминированным провайдером проверяет передачу результата инструмента модели.
- Документация проверяется ревью, без тестов наличия файлов или строк в README.

## Границы

- Всегда: хранить текст как фиксированное значение в реализации backend; подключить инструмент к production bootstrap; обновить документацию.
- Сначала спросить: одобрение этой спецификации и следующего плана по правилам SDD.
- Никогда: добавлять публичный endpoint, внешние зависимости или раскрывать текст инструмента через системный промпт.

## Критерии приёмки

- [ ] `get_context` доступен агенту в production-сборке и принимает только `{}`.
- [ ] Успешный вызов возвращает точную строку из REQ-002 при каждом вызове.
- [ ] Неожиданные аргументы дают `invalid_arguments`.
- [ ] Agent loop передаёт результат модели и может завершить ответом на его основе.
- [ ] Документация агента и глобальный каталог актуальны.
- [ ] `make test` проходит успешно.
