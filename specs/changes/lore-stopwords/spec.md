# Стоп-слова в BM25-поиске по лору

## Цель

Снизить вклад служебных слов в ранжирование лора. Замер на golden set показал,
что самые частые термы корпуса — `не` (df 185/188 чанков), `а` (184), `я` (183),
`что` (179), `и` (178), `это` (174): они есть почти в каждом чанке и входят в
каждый вопрос, поэтому балл определяется не темой, а количеством «шумовых»
совпадений. Явный список стоп-слов удаляет их из индекса и из запроса при том
же анализе, что и раньше.

Пользователь результата — агент и его бенчмарк: ожидается рост `Recall@5` и
`MRR@5` без изменения архитектуры, схемы хранения и контракта инструмента.

## Требования

- REQ-001: добавляется модуль `rag/lore/stopwords.py` с `STOP_WORDS`
  (frozenset нормальных форм, после лемматизации) и функцией
  `drop_stop_words(terms)`. Список — стандартный расширенный русский
  stop-list: служебные части речи и местоимения плюс лёгкие глаголы
  (`быть`, `мочь`, `знать`, `делать`, `говорить`, `хотеть`, `сделать`,
  `сказать`, `давать`, `видеть`, `думать` и подобные). Имена персонажей и
  содержательные термины (`играть`, `игра`, `футбол`, `мороз`, `зуб`) в список
  не входят.
- REQ-002: `SimpleAnalyzer` и `MorphAnalyzer` удаляют стоп-слова после
  токенизации и (у `MorphAnalyzer`) лемматизации, поэтому индекс документов и
  запрос проходят одну и ту же фильтрацию.
- REQ-003: `LoreContextBuilder` перестаёт держать собственную копию списка:
  `NON_CONTENT_TERMS` в `context.py` становится ссылкой на `STOP_WORDS`, имя
  сохраняется для совместимости. Правило «запрос из одних имён даёт пустой
  контекст» продолжает работать.
- REQ-004: список фиксируется по лингвистическим критериям до контрольного
  прогона; вопросы golden set не меняются и не используются для подбора
  отдельных слов. Замеры вариантов списка носят характер проверки дизайна и
  раскрываются в `verification.md` полностью.
- REQ-005: изменение сохраняется, только если ни одна из метрик не ухудшилась
  и хотя бы `Recall@5` или `MRR@5` выросли. Контрольный прогон golden set
  `k=5` до/после фиксируется в документации и `verification.md`.
- REQ-006: существующие тесты анализатора, ожидающие служебные слова в
  результатах, обновляются; добавляются тесты: стоп-слово удаляется из
  документа и из запроса, содержательный терм и имя персонажа сохраняются,
  пустой текст по-прежнему даёт пустой кортеж, список един для документа и
  запроса.
- REQ-007: документация обновляется: `docs/lore.md` (раздел «Предобработка»,
  где сейчас сказано, что стоп-слова не удаляются, и «Ограничения»),
  `docs/rag.md`, `AGENTS.md`.
- REQ-008: изменение анализа меняет термы индекса, поэтому в документации
  фиксируется операционное требование: после выкладки production-индекс
  перезагружается командой `make lore-load DIR=<path>`.

## Сценарии

### Основной сценарий

- Given корпус и вопрос содержат `и`, `что`, `герой`;
- When выполняется поиск;
- Then служебные термы не участвуют в балле, а `Recall@5` и `MRR@5` не хуже
  прежних.

### Ошибка или граничный случай

- Given запрос «Крош и Ёжик»; When контекст строится; Then служебное слово
  удалено, имена сохранены, правило «имена без содержания» по-прежнему даёт
  `empty`.
- Given текст только из стоп-слов («и что это»); When анализ; Then результат —
  пустой кортеж, а поиск возвращает `empty`-контекст.
- Given production-индекс, собранный до изменения; When поиск после выкладки
  без `lore-load`; Then термы индекса и запроса не совпадают — в документации
  указано требование перезагрузки.

## Технологии и структура

Python: новый `rag/lore/stopwords.py`, правки `rag/lore/analyzer.py` и
`rag/lore/context.py`. Тесты: `backend/tests/unit/rag/lore/test_analyzer.py`,
новый `test_stopwords.py`, при необходимости `test_context.py`,
`test_services.py`, `test_tool.py`. Документация: `docs/lore.md`,
`docs/rag.md`, `AGENTS.md`.

## Команды

- Замеры: `python -m smeshariki_ai.rag lore-benchmark data/lore-golden/lore
  --questions data/lore-golden/questions.yaml --answers
  data/lore-golden/answers.json --context`
- Тесты: `make test`; линт: `make lint`.

## Тестирование

- `test_stopwords.py`: состав списка (нормальные формы), удаление стоп-слов,
  сохранение имён и содержательных терминов, пустой результат для текста из
  стоп-слов.
- `test_analyzer.py`: обновлённые ожидания для `и`, плюс проверка, что документ
  и запрос получают одинаковые термы.
- Поведенческие тесты `test_services.py`/`test_tool.py` подтверждают, что поиск
  и инструмент работают после фильтрации.

## Границы

- Всегда: список как данные в одном модуле; вопросы golden set не менять.
- Сначала спросить: изменение параметров BM25 (`k1`, `b`), `min_score`,
  добавление embeddings.
- Никогда: не подбирать отдельные слова по конкретным вопросам golden set, не
  удалять имена персонажей из индекса.

## Критерии приёмки

- [ ] `make test` проходит успешно; `make lint` без замечаний.
- [ ] Контрольный прогон: `Recall@5` и `MRR@5` не ниже `0.450`/`0.637`,
      фактические значения зафиксированы.
- [ ] Правило «имена без содержания» продолжает работать (тест).
- [ ] Документация отражает новое поведение и требование `make lore-load`.
