# Зашифрованные данные RAG в репозитории

## Цель

Хранить закрытые данные RAG (сценарии, пакеты знаний) в публичном репозитории
так, чтобы прочитать их могли только участники команды, знающие кодовую
фразу. Рабочая копия данных лежит в игнорируемой Git папке `data/`, в
репозиторий попадает только зашифрованный архив `encrypted/data.enc`.
Шифрование и расшифровка выполняются командами `make` и описаны локальным
skill, чтобы ИИ-агент знал порядок работы и не касался кодовой фразы.

## Допущения

- Репозиторий публичный. Видны размер архива, время и частота его изменений и
  вся история прошлых версий; содержимое и имена файлов скрыты.
- Секрет — одна общая кодовая фраза команды. Она передаётся вне репозитория и
  никогда не попадает в файлы, аргументы командной строки, environment и чат
  с агентом.
- Смена кодовой фразы не отзывает доступ к старым версиям архива в истории
  Git: тот, кто знал прежнюю фразу, может их расшифровать.
- Объём данных — единицы мегабайт текста, поэтому весь каталог шифруется одним
  архивом, а не пофайлово: так скрыты имена и структура файлов.
- Это инструмент разработки, а не код продукта: backend и его зависимости не
  меняются.

## Требования

- REQ-001: `/data/` игнорируется Git; `encrypted/data.enc` отслеживается.
- REQ-002: `make data-encrypt` запрашивает кодовую фразу дважды без эха,
  упаковывает содержимое `data/` в архив и записывает
  `encrypted/data.enc`, зашифрованный аутентифицированным шифром с ключом из
  кодовой фразы через KDF с затратой памяти и случайной солью.
- REQ-003: Кодовая фраза короче 12 символов или несовпадение повторного ввода
  при шифровании — ошибка; файл не меняется.
- REQ-004: Если содержимое `data/` совпадает с содержимым существующего
  `encrypted/data.enc`, расшифрованного той же фразой, файл не
  перезаписывается: Git не видит изменений. Архив детерминирован (порядок
  файлов, время, владелец и права не зависят от машины).
- REQ-005: При шифровании пропускаются `.DS_Store` и `.git`; символьные ссылки,
  отсутствующая или пустая `data/` — ошибка без записи файла.
- REQ-006: `make data-decrypt` запрашивает кодовую фразу один раз и
  восстанавливает содержимое `data/` из `encrypted/data.enc`.
- REQ-007: Неверная фраза или повреждённый файл дают одно понятное сообщение
  и ненулевой код; `data/` не меняется.
- REQ-008: Если `data/` не пуста и отличается от архива, расшифровка
  отказывается и перечисляет отличающиеся пути. `make data-decrypt FORCE=1`
  заменяет содержимое `data/` целиком. Совпадающая `data/` — успех без
  изменений.
- REQ-009: Распаковка не создаёт файлов вне `data/`, символьных ссылок и
  специальных файлов.
- REQ-010: Без терминала кодовая фраза читается из первой строки stdin только
  с явным флагом `--passphrase-stdin`; иначе — ошибка. Make-цели флаг не
  передают.
- REQ-011: Сообщения скрипта и его ошибки не содержат кодовую фразу и
  содержимое файлов.
- REQ-012: Skill `.agents/skills/data-crypt/SKILL.md` описывает, когда
  шифровать и расшифровывать данные, и запрещает агенту запрашивать, читать,
  вводить и сохранять кодовую фразу: агент даёт пользователю команду для
  запуска в его терминале.
- REQ-013: `AGENTS.md` и `docs/rag.md` описывают хранение данных: рабочая
  копия в `data/`, в репозитории только `encrypted/data.enc`; ссылка на skill.

## Сценарии

### Сокомандник получает данные

- Given свежий клон репозитория с `encrypted/data.enc` и пустой `data/`
- When он выполняет `make data-decrypt` и вводит кодовую фразу
- Then `data/` содержит те же файлы, что были зашифрованы

### Автор обновляет данные

- Given изменённые файлы в `data/`
- When он выполняет `make data-encrypt` и дважды вводит фразу
- Then `encrypted/data.enc` изменился, и его можно закоммитить

### Данные не менялись

- Given `data/`, совпадающая с архивом
- When выполняется `make data-encrypt` с той же фразой
- Then `git status` не показывает изменений

### Неверная фраза

- Given `encrypted/data.enc`
- When `make data-decrypt` с неверной фразой
- Then сообщение «неверная кодовая фраза или файл повреждён», код ненулевой,
  `data/` не изменилась

### Локальные правки не затираются

- Given `data/` с несохранёнными в архив изменениями
- When `make data-decrypt`
- Then отказ со списком отличающихся путей; с `FORCE=1` — замена `data/`

### Агента просят расшифровать данные

- Given пользователь пишет агенту «расшифруй данные»
- When агент следует skill
- Then агент не просит фразу в чате, а даёт команду `make data-decrypt` для
  запуска пользователем в его терминале

## Технологии и структура

- Скрипт `.agents/skills/data-crypt/scripts/data_crypt.py` с подкомандами
  `encrypt` и `decrypt`; запускается `uv run --script` с inline-метаданными
  (PEP 723), Python 3.12, зафиксированной зависимостью `cryptography` и
  lock-файлом скрипта. Зависимости backend не меняются.
- Криптография: ключ 256 бит из `hashlib.scrypt` (n = 2^17, r = 8, p = 1,
  соль 16 байт), шифр AES-256-GCM (nonce 12 байт). Формат файла:
  магическая строка, версия формата, параметры scrypt, соль, nonce,
  шифртекст с тегом; заголовок аутентифицируется как associated data.
  Полезная нагрузка — детерминированный `tar` + gzip без времени изменения.
- Распаковка — `tarfile` с фильтром `data` во временный каталог рядом с
  `data/`, затем замена.
- `Makefile`: цели `data-encrypt` и `data-decrypt [FORCE=1]`, строки в `help`.
- `.gitignore`: `/data/` (добавлено ранее в этой ветке).
- Файлы: `.agents/skills/data-crypt/SKILL.md`, скрипт и его lock-файл,
  `encrypted/data.enc` (создаёт пользователь своей фразой).
- Документация: раздел «Данные» в `docs/rag.md`; пункт 2 раздела
  «Реализованный каталог знаний» и процесс разработки в `AGENTS.md`.

## Команды

- Шифрование: `make data-encrypt`
- Расшифровка: `make data-decrypt [FORCE=1]`
- Проверка: `make lint`, `make test`

## Тестирование

Скрипт — инструмент разработки, а не код продукта, поэтому по правилам
проекта автоматические тесты в `make test` не добавляются. Требования
проверяются ручными прогонами на синтетическом каталоге во временной папке
вне репозитория (фраза передаётся через `--passphrase-stdin`):

| Требования | Проверка |
| --- | --- |
| REQ-001 | `git check-ignore` для `data/`, отсутствие игнора для `encrypted/data.enc` |
| REQ-002, REQ-006 | Round-trip: побайтовое сравнение исходного и восстановленного каталога |
| REQ-003 | Короткая фраза и несовпадение ввода: ошибка, файл не создан |
| REQ-004 | Повторное шифрование без изменений: хеш файла прежний; изменение одного файла меняет хеш |
| REQ-005 | `.DS_Store`/`.git` не попадают в архив; символьная ссылка и пустая `data/` — ошибка |
| REQ-007 | Неверная фраза и испорченный байт файла: сообщение, код, `data/` не тронута |
| REQ-008 | Отличающаяся `data/`: отказ со списком; `FORCE=1`: замена; совпадающая: успех |
| REQ-009 | Ревью: фильтр `data` у `tarfile` |
| REQ-010 | Запуск без TTY и без флага — ошибка |
| REQ-011 | Ревью сообщений; поиск фразы в выводе прогонов |
| REQ-012, REQ-013 | Ревью skill, `AGENTS.md`, `docs/rag.md` |

Интерактивный ввод через make-цели проверяет пользователь: агент фразу не
вводит.

## Границы

- Всегда: шифровать весь каталог одним файлом; не трогать `data/` при любой
  ошибке; проверять скрипт на синтетических данных вне репозитория.
- Сначала спросить: изменение параметров KDF или формата после первого
  коммита `encrypted/data.enc`; добавление skill в `.claude/skills/`.
- Никогда: запрашивать, вводить, логировать или сохранять кодовую фразу;
  коммитить `data/`; создавать `encrypted/data.enc` за пользователя.

## Критерии приёмки

- [ ] Round-trip восстанавливает каталог побайтово.
- [ ] Повторное шифрование неизменённых данных не меняет файл.
- [ ] Неверная фраза и повреждённый файл не меняют `data/` и дают понятную
      ошибку.
- [ ] Расшифровка не затирает отличающуюся `data/` без `FORCE=1`.
- [ ] Короткая фраза, несовпадение ввода, пустая `data/` и символьные ссылки
      отклоняются.
- [ ] Skill запрещает агенту работать с кодовой фразой и даёт команды для
      пользователя.
- [ ] `AGENTS.md` и `docs/rag.md` описывают хранение данных.
- [ ] `make lint` и `make test` проходят: код продукта не менялся, команды
      подтверждают, что изменение его не затронуло.
