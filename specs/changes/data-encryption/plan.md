# План: зашифрованные данные RAG в репозитории

## Основание

План реализует согласованную спецификацию
`specs/changes/data-encryption/spec.md`. Работа ведётся в отдельной ветке
`feat/data-encryption` от `main`; незакоммиченные `.gitignore` и
SDD-артефакты переносятся в неё. Коммиты — только по просьбе пользователя.

## Решения и зависимости

- Скрипт `.agents/skills/data-crypt/scripts/data_crypt.py` — самостоятельный
  PEP 723 script: `requires-python = ">=3.12"`, зависимость `cryptography`
  с точной версией. Lock-файл `data_crypt.py.lock` создаёт
  `uv lock --script`; make-цели вызывают `uv run --locked --script`.
- Корень репозитория скрипт получает аргументом `--root` (по умолчанию —
  текущий каталог), поэтому проверки идут на временном каталоге вне
  репозитория, не трогая настоящие `data/` и `encrypted/`.
- Формат `encrypted/data.enc`:
  `b"SMSHAI-DATA"` · версия `1` (1 байт) · `log2(n)`, `r`, `p` (по 1 байту) ·
  соль 16 байт · nonce 12 байт · шифртекст AES-256-GCM с тегом. Заголовок до
  шифртекста передаётся как associated data. Неверная магия или версия —
  отдельная понятная ошибка.
- Полезная нагрузка — `tar.gz`: файлы в лексикографическом порядке путей,
  `mtime = 0`, `uid/gid = 0`, пустые имена владельцев, права `0644`/`0755`,
  gzip с `mtime = 0`. Каталоги включаются, чтобы сохранять пустые папки.
- Сравнение `data/` с архивом идёт по набору путей и SHA-256 содержимого
  файлов; оно используется и для REQ-004 (не перезаписывать), и для REQ-008
  (отказ со списком).
- Расшифровка: распаковка `tarfile.extractall(filter="data")` во временный
  каталог рядом с корнем, затем атомарная замена `data/` через
  переименование; при ошибке временный каталог удаляется.
- Ввод: `getpass.getpass` при TTY; иначе только `--passphrase-stdin`.
- Коды возврата: `0` — успех или «без изменений», `1` — ошибка данных или
  фразы, `2` — неверные аргументы.

## Порядок реализации

1. Окружение скрипта: ветка, PEP 723, lock, запуск через `uv` (риск — первым).
2. Шифрование и расшифровка с проверками.
3. Make-цели.
4. Skill и документация.
5. Verify.

## Задача 1. Ветка и окружение скрипта

**Связанные требования:** REQ-001.

**Критерии приёмки:** ветка `feat/data-encryption` содержит изменения
`.gitignore` и SDD-артефакты; заготовка скрипта запускается
`uv run --locked --script` и импортирует `cryptography`.

**Зависимости:** нет.

**Файлы:** `.agents/skills/data-crypt/scripts/data_crypt.py`,
`.agents/skills/data-crypt/scripts/data_crypt.py.lock`.

**Проверка:** `git check-ignore data/x`; `git check-ignore encrypted/data.enc`
возвращает «не игнорируется»; `uv run --locked --script ... --help`.

## Задача 2. encrypt и decrypt

**Связанные требования:** REQ-002–REQ-011.

**Критерии приёмки:** критерии спецификации о round-trip, неизменном файле,
неверной фразе, повреждённом файле, отказе без `--force`, короткой фразе,
несовпадении ввода, пустой `data/`, символьных ссылках и запуске без TTY.

**Зависимости:** задача 1.

**Файлы:** `.agents/skills/data-crypt/scripts/data_crypt.py`.

**Шаги:** реализовать по одной проверке из таблицы «Тестирование»
спецификации: сначала прогон на временном каталоге показывает отсутствие
поведения, затем код, затем повтор прогона.

**Проверка:** ручные прогоны с `--root <tmp>` и `--passphrase-stdin` на
синтетических файлах; `uvx ruff check` и `uvx ruff format --check` по
скрипту.

## Задача 3. Make-цели

**Связанные требования:** REQ-002, REQ-006, REQ-008, REQ-010.

**Критерии приёмки:** `make data-encrypt` и `make data-decrypt [FORCE=1]`
вызывают скрипт без `--passphrase-stdin`; цели есть в `make help`.

**Зависимости:** задача 2.

**Файлы:** `Makefile`.

**Проверка:** `make help`; `make -n data-encrypt`, `make -n data-decrypt
FORCE=1`; запуск цели без TTY (`</dev/null`) завершается ошибкой ввода.
Интерактивный ввод проверяет пользователь.

## Задача 4. Skill и документация

**Связанные требования:** REQ-012, REQ-013.

**Критерии приёмки:** skill описывает назначение, команды, когда их
запускать, и запрет работы агента с фразой; `AGENTS.md` и `docs/rag.md`
описывают `data/` и `encrypted/data.enc`.

**Зависимости:** задача 3.

**Файлы:** `.agents/skills/data-crypt/SKILL.md`, `AGENTS.md`,
`docs/rag.md`.

**Проверка:** ревью.

## Задача 5. Verify

**Связанные требования:** все.

**Критерии приёмки:** все критерии спецификации подтверждены;
`verification.md` записан; временные каталоги проверки удалены.

**Зависимости:** задачи 1–4.

**Файлы:** `specs/changes/data-encryption/verification.md`.

**Проверка:** повтор прогонов задачи 2; `make lint`; `make test`.
