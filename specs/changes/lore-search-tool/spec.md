# Инструмент агента `search_lore` с контекстным бюджетом

## Цель

Подключить готовый BM25-поиск по лору к агенту как инструмент `search_lore`.
Агент должен получать несколько компактных нарративных фрагментов, а не весь
корпус и не сырые карточки: БД даёт ориентир по миру и тону, но не диктует
сюжет. Инструмент возвращает только текст, название и источник; score,
внутренние id и полные postings наружу не выходят.

## Требования

### Контекстный бюджет

- REQ-001: `LoreContextBuilder` превращает `LoreSearchResult` в
  `LoreContext`: не более 3 фрагментов, не более одного фрагмента на документ,
  не более 1600 символов суммарно. Слишком длинный последний фрагмент
  обрезается с маркером `…`, после чего добавление прекращается.
- REQ-002: Слабые совпадения отбрасываются: фрагмент включается, только если
  его score не меньше `0.5` от лучшего score. Если после фильтрации не
  осталось текста, контекст имеет статус `empty`, а не ошибку.
- REQ-003: `LorePassage` содержит `title`, необязательный `source` и `text`.
  `LoreContext` содержит статус `found`/`empty`, фрагменты и безопасное
  сообщение. Score, `document_id`, `chunk_id` и `position` в контекст не
  попадают.
- REQ-004: Пустой результат и результат без сильных совпадений возвращают
  `status="empty"` и сообщение «в лоре нет подходящих фрагментов; продолжай по
  идее пользователя». `LoreContextBuilder` не вызывает LLM и не пишет в БД.

### Инструмент

- REQ-005: `SearchLoreTool` наследуется от `Tool`, имеет имя `search_lore`,
  описание на английском и Pydantic-модель аргументов `{query: str}`:
  непустая строка до 300 символов, лишние поля запрещены. `top_k` не входит в
  аргументы: бюджет задаёт код, а не модель.
- REQ-006: Инструмент вызывает `SearchLore` с `top_k=10`, затем
  `LoreContextBuilder`; возвращает JSON `{status, passages, message}`.
  `passages` — список объектов `{title, source, text}`; score и внутренние
  идентификаторы отсутствуют.
- REQ-007: Ошибка `LoreStoreError` перехватывается и превращается в
  `status="unavailable"` с безопасным сообщением; агент может продолжить без
  лора. Ошибки аргументов и исполнения по-прежнему обрабатывает
  `ToolRegistry`.
- REQ-008: Описание инструмента требует использовать его не более одного раза
  на сказку, воспринимать фрагменты как ориентир, а не готовый сюжет, не
  пересказывать их, не перечислять факты и не упоминать источники; при
  `empty`/`unavailable` нельзя выдавать выдуманные факты за канон.

### Composition root

- REQ-009: Production bootstrap регистрирует `search_lore` рядом с
  `get_context` и `lookup_knowledge`, передаёт `PostgresBm25Index` на общем
  engine и `MorphAnalyzer`. Без production-индекса (явный `auth_service` или
  unit-тест) используется пустой `InMemoryBm25Index` и `SimpleAnalyzer`, чтобы
  тесты не требовали БД и морфологического словаря.
- REQ-010: `build_agent_service` принимает необязательные `lore_index` и
  `lore_analyzer`; `create_application` передаёт production-адаптеры. Engine
  закрывается существующим `on_shutdown`; отдельный lifecycle не создаётся.
- REQ-011: Инструмент не меняет системный промпт, `Agent`, `AgentService`,
  `LLMProvider`, HTTP-слой и frontend. Изменения в общем `bootstrap.py` —
  только регистрация инструмента и передача зависимостей.

### Наблюдаемость, документация, проверка

- REQ-012: Поиск и инструмент не пишут в журнал текст запроса, фрагменты,
  названия документов и источники. Используются существующие безопасные
  события `lore.search.completed` и поля `match_count`, `index_version`,
  причина и тип ошибки.
- REQ-013: `docs/lore.md`, `docs/rag.md`, `docs/agent.md`, `docs/README.md` и
  раздел о runtime в `AGENTS.md` получают описание `search_lore` и
  контекстного бюджета. `docs/lore.md` фиксирует, что это ориентир, а не
  сюжет.
- REQ-014: Тесты покрывают builder (лимиты, дедупликацию, порог, обрезку,
  пустой результат), инструмент (JSON, отсутствие score/id, недоступность,
  валидацию аргументов), bootstrap (наличие инструмента и выбор адаптеров).
  `make lint`, `make test` и `make test-integration` проходят.

## Сценарии

### Обычный поиск

- Given в PostgreSQL загружен лор с тремя документами про Кроша
- When модель вызывает `search_lore` с запросом «Крош и Ёжик поссорились»
- Then инструмент возвращает не более 3 фрагментов, по одному на документ,
  без score и внутренних id.

### Слабые совпадения

- Given поиск нашёл один сильный и несколько слабых фрагментов
- When строится контекст
- Then слабые фрагменты ниже половины лучшего score не попадают в ответ.

### Пустой лор

- Given корпус пуст или совпадений нет
- When вызывается `search_lore`
- Then `status="empty"`, `passages=[]`, сообщение предлагает продолжить по идее
  пользователя.

### Недоступная БД

- Given PostgreSQL недоступен
- When вызывается `search_lore`
- Then `status="unavailable"`, `passages=[]`, безопасное сообщение; агент
  продолжает без лора.

### Ограничение аргументов

- Given аргументы `{"query": "", "top_k": 100}`
- When `ToolRegistry` валидирует вызов
- Then возвращается `invalid_arguments`, инструмент не выполняется.

## Технологии и структура

- `rag/lore/context.py` — `LorePassage`, `LoreContext`,
  `LoreContextBuilder`.
- `rag/lore/tools.py` — `SearchLoreArguments`, `SearchLoreTool`.
- `bootstrap.py` — регистрация `search_lore`, `PostgresBm25Index`,
  `MorphAnalyzer`; без production-инфраструктуры — пустой in-memory индекс.
- `docs/lore.md`, `docs/rag.md`, `docs/agent.md`, `docs/README.md`,
  `AGENTS.md` — описание инструмента и бюджета.
- Новых зависимостей нет.

## Границы

- Всегда: контекстный бюджет в RAG; инструмент возвращает только текст,
  название и источник; production-индекс на общем engine.
- Сначала спросить: изменение системного промпта, `Agent`, `AgentService`,
  `LLMProvider`, HTTP-слоя, frontend и другие чужие модули.
- Никогда: отдавать модели score, `chunk_id`, `document_id`, полный корпус
  или сырые карточки; логировать текст запроса и фрагменты; делать
  pre-retrieval в обход инструмента.

## Критерии приёмки

- [ ] `LoreContextBuilder` соблюдает лимиты 3/1600/один документ и порог.
- [ ] `search_lore` возвращает компактный JSON без score и внутренних id.
- [ ] Пустой и недоступный лор дают безопасные статусы, а не исключения.
- [ ] Production bootstrap регистрирует инструмент с PostgreSQL и
      `MorphAnalyzer`; тесты не требуют БД.
- [ ] Логи не содержат текст запроса и фрагменты.
- [ ] Документация и `AGENTS.md` обновлены.
- [ ] `make lint`, `make test` и `make test-integration` проходят.

## Открытые вопросы

- Нет. Контекстный бюджет фиксирован: 3 фрагмента, 1600 символов, порог 0.5;
  изменение значений — отдельное решение по результатам benchmark.
